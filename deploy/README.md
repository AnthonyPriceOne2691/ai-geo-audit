# Памятка подготовки сервера

Подготовка к первому выкату (6а): каталоги, файл окружения, значения и секреты владельца,
предполётная проверка. Подъём, сверка и откат — памятка выката (6в).

## Правила общей машины

- Сервер общий с соседом. Наше — только корни ниже, порт web на петле и имена с приставкой
  `ai-geo-audit`. Чужое не трогаем: ни `docker … prune`, ни остановок по списку всех, ни правок
  чужих файлов compose, nginx и кронов.
- Запуск — `python3 -I deploy/deploy.py <команда>` из `/srv/ai-geo-audit` от root: `-I` не берёт
  каталог скрипта в путь импорта и не читает переменные `PYTHON*`. Соседа скрипт только читает.
- Значения и секреты — только файлами, в аргументах команд их нет: аргументы видны в списке
  процессов. Вывод скрипта — имена, права, коды и счёт, без значений.
- Команды неинтерактивные. Долгие — под `tmux new -d`, ход — короткими вызовами `last`: обрыв
  связи шаг не роняет. Вход на сервер — только по ключу; после работы ключ закрыть.

## Каталоги и права

| Путь | Владелец | Права | Что |
|---|---|---|---|
| `/srv/ai-geo-audit/` | root | как у клона | клон репозитория, скрипт выката |
| `/srv/ai-geo-audit/.env` | root | 600 | файл окружения сервера |
| `/srv/ai-geo-audit/.deploy/` | root | 700 | журналы хода и замок одного запуска |
| `/srv/ai-geo-audit-backups/` | root | — | корень копий, заводит выкат (6в) |
| `/etc/ai-geo-audit/` | root | 700 | каталог мастер-ключа |
| `/etc/ai-geo-audit/master.key` | uid 10001 | 400 | мастер-ключ ключей сервисов, только у api и воркера |
| `/etc/ai-geo-audit/incoming/` | root | 700 | входящие файлы владельца |

## Подготовка по шагам

```sh
cd /srv/ai-geo-audit
python3 -I deploy/deploy.py env-init
python3 -I deploy/deploy.py put-secret /etc/ai-geo-audit/incoming/owner.env
python3 -I deploy/deploy.py check
python3 -I deploy/deploy.py last
```

1. **Клон** репозитория — в `/srv/ai-geo-audit`, ревизия — та, что назовёт ведущая.
2. **`env-init`** создаёт файл окружения: пароли базы, ролей и очереди и секрет подписи —
   случайными, hex, адреса с этими паролями; мастер-ключ и каталог входящих. Второй запуск —
   отказ: база помнит пароли первого, новый секрет подписи гасит все пропуска.
3. **Значения и секреты владельца — файлом** строк `ИМЯ=значение` ровно с именами «задаёт
   владелец» блока «сервер» `.env.example`: `SITE_DOMAIN`, `WEB_PORT`, `FRONT_SUBNET`,
   `WEB_ADDRESS`, `NEIGHBOR_HEALTH_URLS`, `ALERT_TELEGRAM_BOT_TOKEN`, `ALERT_TELEGRAM_CHAT_ID`.
   Файл с правами 600 кладёт сам владелец из своего терминала —
   `scp -p <файл> <сервер>:/etc/ai-geo-audit/incoming/`; сессии его каталог секретов не читают.
   Затем, по его слову, ведущая запускает `put-secret` с путём к файлу: строки имён в файле
   сервера заменяются, входящий удаляется. Чужое имя, права шире 600 или файл не из каталога
   входящих — отказ, ничего не тронуто.
   - `WEB_PORT` — свободный порт на петле; `FRONT_SUBNET` — /28 вне пулов докера и сетей соседа;
     `WEB_ADDRESS` — последний адрес узла в ней: докер раздаёт адреса с начала подсети.
   - `NEIGHBOR_HEALTH_URLS` — адреса проверки соседа на петле через запятую,
     `http://127.0.0.1:<порт>/<путь>`, без учётных данных.
4. **Копии у владельца.** Без файла окружения и мастер-ключа данные не вернуть: в файле — пароли
   ролей базы, мастер-ключом зашифрованы ключи сервисов. `.env` и `master.key` владелец переносит
   к себе сам — `scp` из своего терминала — и хранит у себя; сессии их не читают и не переносят,
   в чатах, письмах и репозитории их нет.
5. **`deploy.py check`** — строка на тему: файл окружения, образы, пары «пароль — адрес», имена,
   порт, подсеть, ресурсы, снимок соседа — «ок», отказ с причинами или названное исключение
   («образов ещё нет — первый выкат»). Код не 0 — отказ хоть в одной строке: поправить и снова.
   «Сверить» — порт или подсеть соседа не прочитаны: переменная без умолчания, тег, якорь или
   список в несколько строк; сверить руками. Памяти после наших пределов нужно не меньше 10 ГБ,
   места в каталоге докера и в корне копий — не меньше 20 ГБ.
6. **`last`** — последний журнал хода и идёт ли выкат.
