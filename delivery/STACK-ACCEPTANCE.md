## Разбор: где эта процедура подвела

Формат: симптом → корневая причина → что сделано → как проверено. Проект — первый
на этой ревизии канонов, поэтому пишется каждая находка, включая мелкие.

### 2026-11-18 — шаг «мерж bootstrap через merge_guard.sh» на волне только оси ①

- **Симптом:** Delivery §7.2 п.6 требует закончить bootstrap мержем в main через
  `merge_guard.sh <ветка> main`, пока bootstrap — активная поставка. При
  развёртывании «только Delivery по §7» (AGENT_STACK §2.A) этого скрипта нет: он из
  CQG §8.5.2.
- **Причина:** §7.2 п.6 написан под полный контур; развёртывание оси ① отдельно им
  не предусмотрено, хотя карта его разрешает.
- **Сделано:** bootstrap на ветке `bootstrap/contour-b0` от коммита шага 0; гейт
  поставки — на вершине ветки в чистом клоне; перемотка main только после вердикта
  проверяющего. Значение `parallel_sessions` — `manual-deploy`, а не `merge-guard`:
  объявлять очередь без скрипта гейт запрещает сам.
- **Проверено:** прогон в чистом клоне (`archive/2026-11-18-contour-b0/verify-report.md`).

### 2026-11-18 — вариант D между волнами В0 и В1 держится только локальным игнором

- **Симптом:** исполнитель правила, который «едет с клоном», — хук
  `canon-texts-stay-out` (AGENT_STACK §7.1a), а это рецепт для
  `.pre-commit-config.yaml`. На волне В0 pre-commit нет.
- **Причина:** §7.1a ставит хук в шаг развёртывания CQG, а волны канон не
  описывает.
- **Сделано:** игнор, запрет `git add -f` и вопрос на `git push` в правах агента,
  проверка `git ls-files` и `--check-local` перед каждым push.
- **Проверено воспроизведением:** свежий клон без строк игнора с текстами внутри —
  `--check-local` даёт «без игнора 7» и код 1, `git add -A --dry-run` берёт 7 файлов.
