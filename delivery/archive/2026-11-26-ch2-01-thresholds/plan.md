## Approach

**Шаг 0. Пробы — до кода, итог в decisions (L8).**
1. `RAISE EXCEPTION … USING ERRCODE = 'restrict_violation', CONSTRAINT = 'reference_frozen'` в
   триггере доходит до `orig.__cause__.constraint_name` под asyncpg и SQLAlchemy так же, как имя
   ограничения (L133; A302).
2. `numeric` читается в `Decimal` без потерь; `json.loads` с `parse_float=Decimal` и
   `parse_int=Decimal` даёт `Decimal("3.25")`; `NaN` и `Infinity` ловит `parse_constant`;
   `true` приходит `bool` — отказ своей веткой до схемы; поле `Decimal` pydantic 2.14 в строгом
   режиме не берёт `bool` и `float` (L131).

## Stack / boundaries
- **Новых пакетов нет:** pydantic, SQLAlchemy и asyncpg уже в окружении и в коде сервиса;
  стандартная библиотека — `json`, `hashlib`, `decimal`, `argparse`.
- **Слои:** `reference` зависит от `storage`, `config`, `logs`, `refusal`; от `reference` зависят
  Ч2.1б, Ч2.2 и Ч3.1; `schema.py` — от модулей таблиц.
- **Контракт слоёв не держит новых пакетов сам:** в `backend/.importlinter` `exhaustive = False`,
  поэтому `reference` вписывается независимым соседом `settings` над `storage` (проба 4 шага 0);
  без этой строки слои держит только ревью.
- Файл заказчика читает только команда — по пути или со стандартного ввода; сервис — нет.
- Записи командой в поставке нет: замок `REFERENCE` и знак при записи — Ч2.1б.
- Процесс `reference` в `startup_checks.Process` берут и правила стека (`stack_rules._PROCESSES`):
  сервиса `reference` в compose нет — правила его не судят; проба — правила стека на compose
  main, нарушений столько же, сколько до правки.

## Rejected alternatives
- **Версия у каждой строки вместо одной редакции на справочник — отклонена:** аудит помнит одно
  число, а не 58, и Ч5.1 читает одну редакцию. Цена одной редакции — правка одного порога
  копирует 58 строк с порогами, около 0,1 МБ на редакцию.
- **Пороги JSONB в строке вместо отдельной таблицы — отклонены:** предел и значение держит
  ограничение базы, а число — `numeric` без перевода через float. Цена таблицы — около 30 строк и
  копирование порогов.
- **Выгрузка листа заказчика вместо своего формата файла — отклонена:** колонки листа меняет
  заказчик, а проверка сверяет один договор. Цена — сборка файла инженером, шаг 4.
- **Манифест только в базе вместо манифеста в git — отклонён:** ревью видит лишь git. Цена — новый
  файл ждёт коммита манифеста и образа с ним; загрузки редки, пороги правят без файла (Ч2.1б).
- **Том с файлом вместо стандартного ввода одноразового контейнера — отклонён:** на сервере файл
  не остаётся. Цена — флаг `-T` обязателен, без него ввод не дойдёт (README).
- **Удаление пропавшей строки — отклонено:** коды держат наборы и аудиты. Цена — снятую
  заказчиком проверку убирают из наборов, в справочнике она остаётся.
- **Пределы в файле вместо таблицы единиц в коде — отклонены** ответом проверяющего
  2026-11-20T11:27Z, потому что ревью видит таблицу в git. Цена — у порогов одной единицы пределы
  одни.
- **Одна дисциплина кода вместо триггера на строках и порогах — отклонена:** неизменность
  редакции — договор, а не привычка (кейсы L133). Цена — функция и два триггера, около 20 строк, и
  A302; заголовок триггер не держит — подтверждено ответом 11:27Z.
- **Снятие `UPDATE` и `DELETE` у роли сервиса вместо триггера — отклонено:** по
  `deploy/db/roles.sql` роль сервиса получает их правами по умолчанию на все таблицы, а `UPDATE`
  заголовка редакции ей нужен для записи Ч2.1б; точечное снятие у двух таблиц — правка
  `roles.sql` и оракула ролей чужих поставок, а тестовая база с одной ролью его не видит.
- **Манифест JSON-файлом — отклонён:** в JSON нет пометки для сканера секретов, и снимок
  `.secrets.baseline` менялся бы с каждым новым файлом.
- **Правка текстов строки с экрана — отклонена:** тексты меняет инженер файлом, граница ТЗ (ответ
  проверяющего 2026-11-20T11:27Z).
- **Черновик целиком — запись вместе с проверкой — отклонён:** по L125 около 2720 при пределе
  2500 (decisions).
- **Разрез «загрузка поверх правки и `status` — в Ч2.1б, остальная запись здесь» — отклонён:**
  около 2515 — всё ещё выше 2300, а запись без своих гонок и замка в одной поставке не живёт.
- **`status` здесь — отклонён:** без записи командой он показал бы только «справочник не
  загружен»; его место — рядом с `load` (Ч2.1б).
- **Свой разбор отказов вместо `errors(include_input=False)` pydantic — отклонён:** у pydantic
  место ошибки и тип известны без значения, а свой разбор повторял бы схему второй копией.

## Risks
- **Номер ревизии** — у того, кто первым в main: Ч1.7в «рук» тоже заведёт ревизию; второй
  перенумеровывает свою и пробные ревизии тестов, как Ч1.12а: два `0003` дадут красный A17.
- **«Учётки-2» (№34) правят `config/startup_checks.py` и `test_startup_checks.py`** — другие
  места файлов (`_address`, `_queue`, проверки адреса очереди). После их слияния — влить main
  под `TZ=UTC`, две сверки диффа, весь набор и обе стадии хуков (L74, L143).
- **Кандидат и файл ведущей разойдутся** — расхождение ведущей; срезы идут на построителе, хеш
  манифеста встаёт по файлу ведущей, до него — пустой.
- **Пометка сканера секретов** — проба на первом коммите с манифестом: хук В1а зелёный,
  `.secrets.baseline` не изменился (L61).
- **Порчи нового пакета** — около 450 одной долей (L67, L98): шаг долей подходит к бюджету —
  число из прогона CI; точечный прогон — с методами классов (L129).
- **Мера по L125 недооценивала:** у Ч1.14а1 при оценке около 1180 вышло 1912. Точки после
  срезов 1 и 2 — стоп до коммита, не после (L103).

## Rollout / migration
- Ревизия ложится на базу с ревизиями main: таблицы пустые и на стенде, и на бою, если выкат
  придёт раньше. Откат удаляет три таблицы, функцию и триггеры — до первой загрузки (Ч2.1б)
  ничего не теряет, после неё стирает справочник: строка в README.
- На бою поставка ничего не пишет: `check` только читает. Первая загрузка — действие ведущей
  после Ч2.1б, по слову владельца.

## Test / eval strategy
- **pytest на настоящем Postgres 16:** все примеры; ревизии — подпроцессами `alembic`; команда —
  в процессе теста через её `main`, вход в бою — и подпроцессом `python -m` (L123); вывод —
  целиком, оба потока и записи журнала.
- **Пробы проверяющей:** раздел «Безопасность», п. 4 спеки.
- **Ручные порчи** — с `PYTHONPATH` на `src` копии, без кэша байткода (L6, L12, L104), с
  сохранением синтаксиса (L120):
  - снят частичный индекс — A301, вторая `active`; снято любое ограничение — его строка A301;
  - снят триггер — A302;
  - проверка собирает только первую причину — A305, три порчи в одном файле; общий текст вместо
    своего у порчи — её строка A305; таблица единиц не сверяется — A305, порог 61; `\d` вместо
    цифр ASCII или `match` вместо `fullmatch` — A305, коды; булево принято за число — A305;
  - снят предел размера или строк — A306; причина несёт текст поля — A307; сбой печатает текст
    исключения — A307;
  - `check` не сверяет манифест, `--manifest` в бою принят, пустой хеш пропущен — A308;
  - команда в бою стартует без адреса, с чужой ролью или печатает значение настройки — A310;
    класс отказа в `__main__` — A310 подпроцессом;
  - `diff` сравнивает числа записью — A304, четвёртая строка; не называет отменяемые правки —
    A304, третья; пропавший код молча пропущен — A312.
- **Сканер** слов и поясов по правилу A23 — по новым и изменённым файлам.
- **Живой шаг** (`eval-smoke.md`): `check` в контейнере api стенда — вход в образе и роль; ревизия
  `0003` под ролью миграций — шаг `stack` CI (A65).
