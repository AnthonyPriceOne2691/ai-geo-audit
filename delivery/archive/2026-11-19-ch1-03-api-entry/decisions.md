- 2026-11-19 · выбрал ожидания строк A34, A39–A44 по пробам 1–8 плана на пакетах ветки (fastapi 0.141.1, starlette 1.7.0, uvicorn 0.54.0, httpx 0.28.1, pydantic-settings 2.16.3, Python 3.12.13; 2026-11-19T12:49Z) вместо чтения документации, потому что поведение библиотек меняется от версии к версии; цена — пробы гоняются заново при смене пары. Итоги — все совпали со строками примеров.
  Проба 1 — закрытый порт: `ConnectionRefusedError` без обёртки (A39); молчащий сервер под пределом 0,5 с — `TimeoutError` за 0,50 с, соединение после отмены клиент закрыл (A40).
  Проба 2 — `uvicorn.Config(...).load()` с фабрикой: `loaded_app` — `ProxyHeadersMiddleware` над приложением; `forwarded_allow_ips` принимает список; от доверенного адреса и из доверенной подсети клиент берётся из `X-Forwarded-For`, от чужого — адрес соединения (A34, A47).
  Проба 3 — слой, поставленный `add_middleware`, стоит внутри `ServerErrorMiddleware` и над всем остальным; поймав исключение сам, он отдаёт 500, исключение к клиенту теста не выходит, трассировка в журнале одна (A42, A45).
  Проба 4 — 405 у маршрута включённого роутера — `starlette.exceptions.HTTPException` с `Allow: GET` (A43).
  Проба 5 — вошедший в `scope["state"]` виден зависимости как `request.state`; ответ ворот без `receive` уходит, генератор тела не тронут — 0 кусков (A42).
  Проба 6 — строка со своим разбором принимает `10.9.9.9, 172.20.0.0/16`; отказ валидатора: `loc` — `('API_TRUSTED_PROXIES',)`, текст `ValidationError` называет переменную, а не поле; строка вида JSON остаётся строкой (A33).
  Проба 7 — один байт `\xff` с `application/json` — голый `HTTPException` 400 «There was an error parsing the body»; `\xff\xfe` — 422 `json_invalid` (A44). Первый прогон дал 422 `missing`: схема тела была объявлена внутри функции при `from __future__ import annotations`, и FastAPI не нашёл её по имени. Схемы маршрутов-проб — только на уровне модуля.
  Проба 8 — `HEAD /api/health` у маршрута `GET` — 405 с `Allow: GET` (строка «Открытого» для Ч1.5).
