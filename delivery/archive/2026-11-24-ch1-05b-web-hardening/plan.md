## Уроки до кода
Прочитано до кода — те же источники, что у Ч1.5а, плюс:

- сверка описи защит 2026-11-19 и её поправки: тесты CSP, журнал nginx контейнера;
- спеки Ч1.3, Ч1.4а и Ч1.4б: что они оставили сюда;
- чтение спек независимым читателем 2026-11-19 и решения ведущей по нему.

Ниже — суть своими словами и куда урок лёг.

**nginx и заголовки**
- **Заголовки защиты ставит nginx контейнера — смотреть по ответам** (реестр CI, Ч1.5).
  Оракул читает заголовки у пяти видов ответов, а не только у страницы (A79).
- **Ловушка наследования `add_header`** (опись, З12): location со своим `add_header` молча
  теряет все заголовки уровня server. Сниппет — в каждом таком location, статический тест —
  без Docker (A79, вторая строка).
- **Заголовок — ровно один** (чтение спек): сервис ставит свой `nosniff` (Ч1.3, A49), web —
  свой; без `proxy_hide_header` их два. Значение `Permissions-Policy` — строкой, как у соседа,
  иначе порча «оплата снята» проходит по смыслу (A79).
- **Тесты CSP у соседа закрывают только `script-src`** (сверка описи, З11). У нас тест сверяет
  каждую директиву (A80). Стили — вариант «а», решение ведущей с причинами в спеке.
- **Стили Mantine 8.3.18 — по исходникам** (сверила ведущая): `MantineCssVariables`,
  `InlineStyles` и `MantineClasses` вставляют элементы `<style>` — без `'unsafe-inline'` или
  метки их блокирует политика. Атрибуты `style`, которые React ставит через CSSOM, политика не
  задевает. Метку библиотека умеет (`getStyleNonce`), но её надо выдавать на каждый ответ —
  это строгий путь после первого выката (метка из `$request_id` nginx).
- **Адрес api — через DNS докера с переменной** (сосед, комментарий в nginx контейнера и тест
  на это): пересоздание одного api давало 502 на каждый запрос, пока web не перезапустят.
  Срок ответа DNS задан явно, `valid=10s`, — из него и окно A81.
- **Страница — `no-cache`** (опись, З13): иначе после выката браузер держит старую страницу со
  ссылками на файлы, которых уже нет, — белый экран. У соседа у файлов сборки два заголовка
  кэша; у нас один (A78).
- **Адрес клиента — только от прокси, перезаписью, а не дописыванием** (реестр CI, Ч1.6;
  опись, З5 и З6). web передаёт заголовок как есть, api верит только адресу web; поле
  `client` строки доступа даёт Ч1.3, её A47 (A83).
- **Долгое у нас идёт очередью** (опись, З42): у соседа предел ответа 600 с ради прогонов
  запросом. У нас 30 с (A84).
- **Отказ прокси — страница nginx** (опись, Б15, с поправкой сверки): в теле отказа остаётся
  HTML-страница nginx, экран соседа подставляет слова по коду. Отказы web на `/api/` — JSON
  общей формы литералом (A84).
- **Третий журнал — nginx контейнера** (опись, З71 по поправке сверки; Б16): у соседа путь без
  параметров пишет только прокси хоста, а в nginx контейнера формата нет, и умолчание образа
  пишет строку запроса целиком. Путь берётся из присланного адреса без параметров, а не из
  `$uri`: после `try_files` там стоял бы `/index.html` (A83).
- **Журнал ошибок nginx несёт строку запроса** (чтение спек): строки уровня `error` при 502 и
  504 пишут `request:` с параметрами. Журнал ошибок — с уровня `crit`, проверка — запросами с
  меткой при остановленном и замершем api (A83).
- **ASVS 5.0, 3.4.3** — минимум CSP: `object-src 'none'` и `base-uri 'none'`. По памяти; до
  кода — сверить с текстом стандарта. Отсюда `base-uri 'none'`.

**Контейнеры и сеть**
- **Контейнеры от root** (второй сосед, Z52; опись, З79 и Б19): у соседа nginx с умолчаниями
  образа. У нас пользователь `nginx` образа и порт выше 1024 (A82), у всех — `cap_drop` и
  `no-new-privileges` (A87).
- **Одна сеть на всё** (опись, Б23): у соседа база и очередь в сети с выходом наружу. У нас
  три сети (A86).
- **Одна роль базы** (опись, З75 и Б18) и **очередь без пароля** — в поставке «Учётки
  хранилищ» сразу после этой: две роли с правами по умолчанию и пароль Redis — требование
  ASVS L2 о проверке подлинности между частями сервиса (A85). Ч1.6 зависит от неё.
- **Здоровье у каждого процесса своё** (реестр CI, Ч1.3): проверка web — страница, без
  `/api/health`. Иначе перезапуск api виден как два сбоя, и статус web врёт о web (A82).
- **Два прогона разом не должны делить порт и подсеть** (чтение спек): «свободный от системы»
  гоняется между проверкой и подъёмом. Порт и подсеть — от имени стека, занятый — следующий
  (A82).

## Approach

Срез 0, семь срезов кода и контрольная точка после срезов 1–4. Каждый срез кода — отдельные
коммиты; тест или шаг оракула сначала красный, потом зелёный. Ч1.3б уже в main — срез 3
никого не ждёт. Срез 7 с таблицей шагов и строка web в списке скана — после слияния main с
«Оракулом» в ветку 5б, по команде проверяющего.

**0. Версии и дайджесты — в день кода, до первой сборки.** Как в Ч1.5а: последний патч линии
старше 14 суток, дата выхода по первоисточнику; образ — с Docker Hub по дайджесту, сверка
дайджеста по второму источнику — проба, чтение, а не источник сборки; строка на образ в
decisions. Строк кода нет.

**1. Образ фронта и сервис web (A77, A82).**
- `deploy/web/Dockerfile`: стадия сборки на `node` 24-alpine — `npm ci`, `npm run build`,
  `npm run check:dist`; итоговая на `nginx` 1.30-alpine — `dist/` в пустой корень сайта,
  наш файл в пустой `conf.d`, `USER` числом 101.
- `deploy/web/Dockerfile.dockerignore`: `*`, открыты `frontend/` и `deploy/web/`, снова
  закрыты `node_modules`, `dist`, `coverage`, `.env*`.
- Разбор `Dockerfile` (`backend/tests/test_dockerfiles.py`) — под правила по файлу: сейчас он
  рассчитан на один файл — общий список линий `python` и `uv`, установка только `uv sync`. У
  `deploy/backend/Dockerfile` правила прежние, у `deploy/web/Dockerfile` — линии `node` и
  `nginx` и установка `npm ci`.
- После слияния main с «Оракулом»: `deploy/web/Dockerfile` — в список скана `IMAGES`
  (`scripts/image_scan.py`); страж A126 краснеет, пока его там нет. Тест скана
  (`backend/tests/test_image_scan.py`) рассчитан на один образ на debian — его случаи
  правятся под второй образ на alpine, без Python. Новой строки примеров не нужно.
- compose: сервис web — порт на петле, ждёт api healthy, проверка здоровья — страница.
- Оракул: порт web и подсеть `front` — от имени стека, ряд кандидатов, не больше пяти попыток;
  функция выбора — с тестом без Docker.
- Шаги 5б — в новом модуле `scripts/stack_oracle_web.py`: `stack_oracle.py` — 480 строк при
  пределе гейта длины 500 (у «Оракула» — 492); таблица шагов берёт их списком из модуля.
- Шаги оракула: канарейки контекста фронта, состав корня сайта и `conf.d`, uid, порт, корень,
  здоровье web при остановленном api.

**2. nginx и заголовки (A78–A80).**
- `deploy/web/nginx.conf`: `server_tokens off`; `/` — `try_files` на `index.html`,
  `no-cache`, CSP, `Cross-Origin-Opener-Policy`; `/assets/` — один заголовок кэша; pid и
  временные файлы — в `/tmp`; журнал доступа — свой формат, журнал ошибок — с `crit`.
- `deploy/web/security-headers.conf`: пять заголовков, все с `always`.
- `backend/tests/test_web_conf.py`: свой маленький разбор блоков nginx; `include` в каждом
  location с `add_header`, `always`, `server_tokens`, `proxy_hide_header`, директивы CSP по
  одной, переменные формата журнала, уровень журнала ошибок.
- Оракул: заголовки у пяти видов ответов — каждый ровно один; кэш; CSP.

**3. `/api/` через web (A81, A83, A84).** Предел тела из кода Ч1.3б уже в main
(`BODY_LIMIT_BYTES`), сторону сервиса держит A58 Ч1.3б; вторая строка A84 добавляет сторону
nginx и сверяет текст `too-large` с образцом сервиса.
- location `/api/`: `resolver` докера с `valid=10s` и переменная в `proxy_pass`;
  `X-Forwarded-For` — как есть; `proxy_hide_header X-Content-Type-Options`; предел тела 1 МБ;
  предел ответа 30 с; `error_page` 413, 502, 504 — JSON с `no-store`. Пределы заголовков и
  тела — в Ч1.6, решение ведущей.
- `contracts/api-refusals.json`: раздел «прокси» — три образца по форме раздела сервиса:
  `id`, `when`, `status`, `headers`, `body`. По `id` ищет `sample()` (`api_probes.py`), у
  каждого образца он свой: у 502 и 504 вид один — `unavailable`. Тексты `detail` — простыми
  словами для человека, без имён заголовков, кодов и внутренних имён: экран показывает их как
  есть. Тест без Docker сверяет тела в `nginx.conf` с файлом; оракул сверяет с ним живые
  ответы. Таблицы отказов у экрана в main нет: файл читают тесты и оракул.
- `too-large` — один вид и один текст у сервиса и у прокси: «Запрос слишком большой — можно не
  больше 1 МБ». Тест без Docker в `backend/tests/test_web_conf.py` сверяет
  `client_max_body_size` из `nginx.conf` с пределом тела сервиса из кода Ч1.3б и тексты
  `too-large` обоих разделов файла. Разойдутся — тест красный: текст без числа не делаем.
- Оракул: пересоздание api; два пути адреса клиента — через web и из разового контейнера в
  сети `front`, поле `client` строки доступа Ч1.3; журнал web с меткой при живом,
  остановленном и замершем api, отбор строк по маске; отказы с границей 1 048 576 байт.

**4. Защита стека (A86, A87).**
- compose: сети `data`, `front`, `edge`; постоянный адрес web — `WEB_ADDRESS`
  (`API_TRUSTED_PROXIES: ${WEB_ADDRESS:?…}` стоит с Ч1.5а, его держит правило `trusted-proxy`);
  `cap_drop`, `no-new-privileges`, `read_only` и `tmpfs`; db и redis — под
  пользователем своего образа, чтобы входной скрипт не просил прав на смену пользователя.
- Правила основного набора, продолжение перечня Ч1.5а: 17. `cap-drop`;
  18. `no-new-privileges`; 19. `read-only`; 20. `web-address`; 21. `trusted-is-web`;
  22. `segments`; 23. `internal`; по пробе на каждое условие и на соседний случай без
  нарушения (L53). `trusted-is-web` строже `trusted-proxy`: адрес обязан быть адресом web.
- Оракул: выход наружу, сети, `HostConfig` контейнеров; шаг A73 — «сервисов 5, правил 23»
  на основном файле.
- Роли базы и пароль очереди (A85, правила `db-roles` и `redis-auth`) — не здесь: поставка
  «Учётки хранилищ» сразу после этой.

## Rejected alternatives
- **Метка на ответ для стилей, вариант «б»,** — отложена решением ведущей: Mantine умеет
  метку, но её надо выдавать на каждый ответ — подстановка в nginx, около 60 строк, а цель —
  L2. Вернуться после первого выката, метка из `$request_id` nginx. Причины — в спеке.
- **Образ nginx стороннего издателя, уже без root,** — отвергнут, потому что это новый
  издатель. Официальный образ с его пользователем `nginx` достаточен.
- **Зеркало реестра для `node` и `nginx`** — отвергнуто решением ведущей, как в Ч1.5а. Выбрал
  Docker Hub по дайджесту вместо зеркала, потому что дайджест закрепляет содержимое и второй
  поставщик не нужен. Цена — сборка web в CI зависит от лимитов Docker Hub для анонимных
  загрузок; отказ по лимиту — повтор человеком после конца прогона.
- **Проверка здоровья web вместе с `/api/health`, как у соседа,** — отвергнута, потому что
  перезапуск api тогда виден как два сбоя, а статус web врёт о web (A82).
- **`json-file` с ротацией, как у соседа,** — отвергнут для боя, потому что журнал пропадает
  при пересоздании контейнера. Предварительно — journald (решение ведущей).
- **Одна сеть на всё, как у соседа,** — отвергнута, потому что база и очередь получают выход
  наружу, а web видит базу.
- **Доверие всей подсети `front`** — отвергнуто, потому что любой контейнер в ней подделал бы
  адрес клиента. Доверие — одному постоянному адресу web (решение ведущей).
- **`proxy_pass` на имя api без переменной** — отвергнут, потому что после пересоздания api
  web ходит по старому адресу и отвечает 502.
- **Журнал ошибок nginx с уровня `error`** — отвергнут, потому что его строки при 502 и 504
  несут строку запроса с параметрами. Ход отказа виден в журнале доступа: путь и код.
- **«Свободный от системы» порт и подсеть в момент проверки** — отвергнуты, потому что второй
  прогон успевает занять их между проверкой и подъёмом. Выбор от имени стека с повтором.
- **Предел ответа 600 с и предел тела 8 МБ, как у соседа,** — отвергнуты, потому что долгое у
  нас идёт очередью, а загрузок файлов до Части 3 нет. 30 с и 1 МБ; загрузки придут своим
  location со своим пределом.
- **Роли базы и пароль очереди в этой поставке** — отвергнуты: «Учётки» остаются отдельной
  поставкой «рук» — решение проверяющего 2026-11-20T08:59Z. «Учётки хранилищ» идут сразу после
  этой; механика — в их плане.
- **Пароль Redis с первым потребителем, в Ч1.8,** — отвергнут решением ведущей, потому что
  связь частей сервиса без проверки подлинности — требование ASVS L2, а к первому выкату
  сервис защищён (слово владельца).
- **Ждать код 0 при остановке api** — отвергнуто, потому что uvicorn 0.54 после мягкой
  остановки снова поднимает SIGTERM: нормальная остановка — 143 с записью uvicorn (A88).
- **Правило `api-listen`** («у api адрес прослушивания — не петля») — отвергнуто решением
  проверяющего 2026-11-23T10:12Z: адрес на петле ловит живой шаг A69 оракула — здоровье из
  разового контейнера в сети стека (L50); статическое правило дублировало бы его и тронуло бы
  подписанные A87 и A89.

## Risks
- **Стоп по мере — до коммита кода.** Гейт считает только закоммиченное
  (`merge_base..HEAD`, `scripts/delivery_diff.py`): в срезе 4 один коммит кода перескочил стоп
  1830 сразу до 2072. Мера до коммита — `git add -N` новых файлов и `git diff --numstat HEAD`
  по путям, которые считает гейт, плюс текущий `net_loc`; выше стопа — не коммитить, а
  отчитаться (решение проверяющего 2026-11-23T14:04Z).
- **Mantine и CSP.** Все ли стили проходят под `'self'` и `'unsafe-inline'` — видно только в
  браузере. Поэтому проба ведущей в Chrome без окна — в обеих темах. Скрипта схемы Ч1.4б в
  main нет — срез ушёл в «Схему и цвета компонентов»; когда придёт, он файлом, его пропускает
  `script-src 'self'`.
- **Пауза api и 504.** Ядро принимает соединение и у остановленных паузой процессов — на это
  опирается A84. Проверить первым шагом на машине и на раннере.
- **Права и запись.** `cap_drop` у db и redis требует запуска под пользователем образа; корень
  только для чтения — `tmpfs` для pid и временных файлов. У db — `tmpfs` на
  `/var/run/postgresql` и `/tmp` (слово владельца 2026-11-23T14:12:15Z).
- **Подсеть.** Ряд кандидатов берётся из частного диапазона с учётом сетей соседей на машине;
  пересечение докер называет при подъёме, оракул берёт следующий кандидат.
- **Соседние поставки.** При открытии ветки и после каждого слияния main — сверка: вид
  `too-large`, поле `client` (A47), `server_settings()` и поведение uvicorn при остановке. Если
  uvicorn вернётся к коду 0, разбор остановки его уже принимает.
- **(Ч1.5в) journald на машине может не быть** — боевое наложение проверяют только правила.
- **(Ч1.5в) Числа в выводе compose.** `mem_limit` приходит в байтах, `cpus` — числом; правило
  `limits` сравнивает числа, а не строки файла.
- **Имя db из web.** Через домен поиска машины короткое имя может распознаться снаружи.
  Поэтому A86 смотрит не только на имя, но и на соединение: из web до базы его нет.
