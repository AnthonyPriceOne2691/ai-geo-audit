# Spec: пакет, конфиг с проверкой на старте, логи (Ч1.1)

## Problem
Кода сервиса нет. Каждому следующему модулю нужны три вещи: настройки, прочитанные из
окружения с проверкой типов; отказ стартовать, если в боевом режиме чего-то не хватает;
журнал, где у записи есть id запроса или аудита, время в UTC и нет секретов.

## Users / stakeholders
- Исполнитель следующих поставок: читает настройки только через `config`.
- Тот, кто выкатывает сервис: узнаёт о негодных настройках при старте, все сразу.
- Тот, кто разбирает сбой: ищет записи аудита по id и сопоставляет время двух машин.

## In scope
- Пакет `ai_geo_audit` в `backend/src/`, `pyproject.toml` на uv, Python 3.12.
- Домены настроек: режим, хранилище, вход, мастер-ключ, логи; `.env.example`.
- Проверка старта по процессам `api`, `worker`, `migrate`.
- Логи JSON и текстом: поля `extra`, id запроса и аудита, UTC, вычистка секретов.

## Out of scope
- Точки входа api и воркера, эндпоинт здоровья — Ч1.3.
- База, сессии, миграции — Ч1.2.
- Ключи внешних сервисов и их шифрование — Ч1.12; здесь только путь к мастер-ключу.
- Тревоги в Telegram — Ч1.14.

## Acceptance (observable)
- [ ] Без `.env` разработка работает из коробки.
- [ ] Каждую настройку задаёт переменная окружения с её именем.
- [ ] В бою процесс без нужной настройки не стартует и называет все такие переменные разом.
- [ ] В журнале нет секретов, время в UTC, поля и id доживают до вывода.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| A1 | Нет `.env`, ни одна переменная конфига не задана | режим `dev`; база `postgresql+asyncpg://…@localhost:5432/audit`; Redis `redis://localhost:6379/0`; срок входа 12 ч; формат логов `text` |

| A3 | `APP_ENV=prod` и больше ничего; процесс `api` | отказ старта; в тексте все четыре имени разом: `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`, `KEYS_MASTER_KEY_FILE` |
| A3 | `APP_ENV=prod`; `JWT_SECRET=CHANGE_ME_` + 40 знаков; адрес базы с паролем `CHANGE_ME`; `KEYS_MASTER_KEY_FILE=CHANGE_ME` | отказ по трём переменным, у каждой причина «стоит заглушка из .env.example» |

| A3 | `APP_ENV=prod`; `KEYS_MASTER_KEY_FILE=/nonexistent/master.key` | отказ: «файла нет: /nonexistent/master.key» |
| A3 | `APP_ENV=prod`; задан только `DATABASE_URL` | `migrate` стартует; `worker` — отказ по `REDIS_URL`, `KEYS_MASTER_KEY_FILE`; `api` — по ним и `JWT_SECRET` |
| A4 | `APP_ENV=prod`; заданы четыре обязательные; ключей OpenAI, DataForSEO, Ahrefs нет | `api` стартует; среди 11 переменных конфига нет ни одной про эти сервисы |

| A6 | секрет `s3cr3t-token-value-1234567890` в сообщении, в `extra`, во вложенном поле, в тексте исключения и в записи журнала `httpx`; оба формата | секрета в выводе нет, маска `***` — не меньше 4 раз |
| A6 | `JWT_SECRET` и `DATABASE_URL` с паролем `db-password-123456` в окружении, без ручной отметки | ни секрета, ни пароля в выводе; уровень журналов `httpx` и `httpcore` — WARNING |
| A7 | сканер слов и поясов, связанных с РФ и РБ, по новым файлам поставки | 0 совпадений |
| A8 | `.env.example` | ровно 11 переменных, те же, что читает конфиг; у `JWT_SECRET`, `DATABASE_URL` и `KEYS_MASTER_KEY_FILE` — метка `CHANGE_ME` |

## Non-functional
- Тесты не читают `.env` и переменные окружения разработчика, не ходят в сеть.
- Строки до 100 знаков, форма — как у форматтера ruff (он придёт с волной В1).
