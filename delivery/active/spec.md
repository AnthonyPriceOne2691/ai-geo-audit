## Problem

С bootstrap `delivery/evals/smoke/README.md` обещает три сценария, а таблица пуста и `run.sh` нет.
`merge_guard.sh` печатает «smoke evals — ПРОПУЩЕН: нет delivery/evals/smoke/run.sh», шаг CI «Smoke
evals (product oracles)» в джобе `delivery` — «no smoke suite», `delivery_check` на каждом прогоне —
предупреждение §6.1. Пропуск итог не красит: на запросе никто не проверяет, что сервер поднимается
на свежей базе и отвечает, а миграции идут с нуля той же командой, что в бою.

## In scope

- README: таблица S1–S3 — id, команда, ожидание, предел времени — вместо обещания; строка о том,
  чего S1 не доказывает: доступность из сети стека судит оракул стека (L50).
- `run.sh`: сценарии таблицы подряд, у каждого — свой предел времени; первый сбой — код 1, строка
  с id и причиной; итог — «сценариев N из M», ноль — красное (L73). Глушилок кода нет: `|| true`,
  `set +e`, `| tail` (L91). Postgres недоступен — строка «окружение: …» с командой подъёма до первого
  сценария, код 1, ни один сценарий не засчитан. База и процесс сценариев снимаются при любом
  исходе.
- S3 — пустая база своего корня → `alembic upgrade head` подпроцессом из `backend/`, той же
  командой, что сервис `migrate` стека (L19). Судится итог, а не код выхода (L28): ревизия базы —
  head цепочки, таблицы схемы на месте.
- S1 — на базе S3 сервер настоящей точкой входа `python -m ai_geo_audit.api` (L55): окружение
  задаётся целиком, без `.env` (L30), порт — свободный на петле. Ожидание здоровья — один общий срок
  по `monotonic`, исход словами (L83); затем проба `python -m ai_geo_audit.api.probe`: код 0 —
  `GET /api/health` 200. Вывод сервера — в файл, при отказе — хвост (L89). Остановка — `SIGTERM`
  своей группе процессов, по сроку — `killpg` (L85). Сервер на `asyncio`, как тесты
  (`server_settings`).
- S2 — набор backend, как в CI: код 0 и «пропущено 0» (A106).
- CI: S1 и S3 — шагом джобы `tests` после тестов: там база и зависимости. S2 в CI — сам шаг «Тесты
  с покрытием» этой джобы: `run.sh` пропускает его вслух, второй прогон набора не нужен. Шаг «Smoke
  evals» джобы `delivery` (шаблон канона) без базы и зависимостей не судит — адаптация: печатает,
  где идёт smoke.
- Тесты: `run.sh` на подставных сценариях — первый сбой даёт код 1 и остановку, предел времени —
  красный, ноль сценариев — красный (L88); таблица README и `run.sh` одни и те же; корень копии — у
  `envguard.repo_root()` (L94). Контракт CI держит шаг smoke в `tests` после тестов; копии без него
  — красные.
- `merge_guard.sh` (тело канона, без правок) — шаг «smoke evals» идёт и судит все три сценария.

## Безопасность

Сетевого входа нет: сервер слушает `127.0.0.1` на свободном порту и живёт только в сценарии.
Секретов нет: адрес базы — публичный пароль стенда, и в README и `run.sh` он не пишется (L80) — его
дают настройки тестов; окружение сервера задаётся целиком, `ENV_FILE=/dev/null` — `.env` не
читается. Снос базы — только `audit_test_` своего корня.
