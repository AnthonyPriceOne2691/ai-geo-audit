## Problem
- Фронт вне CI: `npm run check` гоняет исполнитель рукой, чистый клон — ведущая. Регресс между
  ручными прогонами не виден, а поставок фронта к вехе — около пятнадцати.
- Семь ролей гейтов на фронте объявлены n/a «до В1б»: сложность, слои, мёртвый код, порчи, ратчет
  предупреждений, дубли, JS-аудит. Мета-гейт печатает их на каждом прогоне.
- jscpd — пакет npm: без него дублирование не судит никто, и в Python тоже
  (`STACK-ACCEPTANCE.md:57`).
- В dev-цепочке `typescript-eslint` → `minimatch` — 7 умеренных находок `npm audit` (2026-11-26).

## Users / stakeholders
- **Владелец.** Слово на шесть пакетов и на обязательную проверку фронта в защите ветки.
- **Ведущая.** Выкладка, защита ветки по слову владельца; до В1б — чистый клон каждой поставки
  фронта.
- **Проверяющая.** Принимает по CI, копиям с нарушениями и доктору контура.
- **Исполнитель следующих поставок фронта.** Пишет под гейтами: красное видно в CI, а не в его
  памяти.

## In scope
- **CI фронта.** Node — из `frontend/.nvmrc` (24), а не «22» шаблона (адаптация: `engine-strict`
  уронил бы `npm ci`); `npm ci --prefix frontend` — скрипты установки не исполняются (`.npmrc`);
  действия — по полному хешу, права токена — только чтение, как у джоб В1а. `npm run check` — шагом
  CI. Обязательная проверка в защите ветки — словом владельца.
- **TS-половины гейтов канона** — по шаблонам и скриптам `scripts/lint/` как есть, записи
  `not-applicable.json` «поставка В1б» снимаются:
  - сложность — eslint с порогами гейта (`check_complexity_gate.sh`), общий снимок;
  - слои — dependency-cruiser, `.dependency-cruiser.cjs` с правилами проекта: без циклов; тема и
    слова не знают страниц; тесты — вне слоёв продукта;
  - мёртвый код — knip (`check_dead_code.py`), конфиг JSON;
  - порчи — Stryker с раннером Vitest на запросе с правкой `frontend/src`: доля убитых — от 60 %,
    бюджет — 300 с; отдельным прогоном, потому что при `LINT_PY_SRC` гейт судит только Python
    (`mutation_py.sh:13–22`);
  - ратчет предупреждений eslint — свой снимок (сегодня 0 предупреждений, 0 ошибок в 12 файлах);
  - дубли — jscpd по TS и Python, одно число в снимке;
  - JS-аудит зависимостей — шаг смотрит `frontend/`: critical и high — красное всегда, рост
    умеренных и низких над снимком — красное.
- **Хуки TS** — eslint по изменённым файлам, ратчет предупреждений, `prettier --check`;
  `frontend/src` — в `files:` хуков дублей, слоёв и сложности; `LINT_*` — в каждом `entry:`. Бюджет
  стадии коммита — до 5 с (CQG:4054).
- **Правило «нет вставки HTML строкой» (З14)** — eslint в `frontend/src`: `dangerouslySetInnerHTML`,
  присваивание `innerHTML` и `outerHTML`, `insertAdjacentHTML`, `document.write` — ошибка с именем
  правила.
- **Свойство на fast-check** — над переводом роли в имя переменной и обратно (`cssVar`,
  `schemeColors`): круг даёт ту же роль для любой роли вида `[a-z][a-zA-Z]*`.
- **Dev-цепочка `typescript-eslint` → `minimatch`** — до выпуска с исправлением, не моложе 14 суток;
  `npm audit` по lock — 0.
- **Шесть новых пакетов** — точные версии не моложе 14 суток, без скриптов установки, строки в
  `approved-packages.json` и `new_dependency` в STATUS одной правкой (F17, A104). Кандидаты на

- **Записи контура** — `not-applicable.json`, `adapted.json`, приёмка стека (ось ② — TS-половины),

## Прогоны: семь вопросов
Шагов аудита нет; вопросы приложены к прогону гейтов.

| Вопрос | Ответ |
|---|---|
| 1. Повтор шага | Гейты — только чтение; повтор даёт тот же итог |
| 2. Сбой и число попыток | Своих повторов нет; сбой инструмента — «не судит» словами, не зелёное (A383–A389) |
| 3. Потолок | Платных вызовов нет; порчи — бюджет 300 с, хуки коммита — до 5 с |
| 4. Обрыв посреди шага | Гейты файлов не пишут, кроме `--generate` снимков — только вниз |
| 5. Кто ещё меняет те же данные | Снимки гейтов — общие с половиной Python; рост — только словом человека |
| 6. Двойное нажатие или запрос | `concurrency` CI В1а отменяет устаревший прогон запроса |
| 7. Тревога | Красный main — тревога В1а (`main-guard`) |

## Безопасность
1. **Что появляется.** Шесть пакетов npm в цепочке поставки dev-зависимостей; установка фронта в CI.
2. **От кого защищаемся.** Подмена пакета свежим выпуском или скриптом установки; известные
   уязвимости зависимостей; вставка HTML строкой — путь к внедрению скрипта.
3. **Защиты поставки.** Каждая краснеет без своей защиты: A394 и F17 — возраст, скрипты установки,
   список одобренных, lock из реестра npm с integrity; A389 — аудит; A391 — правило З14; A382 —
   права токена и закрепление действий.
4. **Пробы проверяющего.** Копии с нарушением каждой роли; доктор контура; CI на ветке.
5. **Открытое.** Нет.
6. **Опора на опись защит соседа** — строка З14: «нет вставки HTML строкой» — берём правилом eslint.

## Чего защита не ловит
- Внешний вид — снимки и проба первого кадра остаются ручными у поставок фронта.
- Порчи судят только правку запроса: старый код без порч до первой правки не меряется.
- Новые находки `npm audit` в пакетах, которые не менялись, всплывут на любом запросе — красным, не
  по вине запроса.
