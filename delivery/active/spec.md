# Spec: стенд базы, движок, сессия (Ч1.2а)

Первая из двух поставок «Базы и миграций». Вторая — Ч1.2б «Модели и миграции»: соглашение об
именах, перечисления, alembic и ревизии, пароли в адресах.

## Problem
Кода работы с базой нет. Следующим поставкам нужны три вещи:
- Postgres разработки и тестов, который не пересекается с соседними проектами;
- движок и сессия с явной фиксацией, шаг стадии на точке сохранения, движок для задач воркера;
- тестовая база на настоящем Postgres: своя у рабочей копии, с двумя независимыми соединениями
  для гонок и с честной остановкой, когда базы нет.

## Users / stakeholders
- Исполнитель следующих поставок: берёт сессию и шаг из `storage`, пишет тесты гонок на
  двух соединениях.
- Тот, кто разбирает сбой: видит процесс по имени в `pg_stat_activity`; время соединения — UTC.
- Владелец машины: тесты не трогают ни базы разработки, ни баз соседних проектов.

## In scope
- `docker-compose.dev.yml`: один сервис `db`, `postgres:16-alpine`, `127.0.0.1:5462`.
- Зависимости по слову владельца: sqlalchemy (asyncio), asyncpg; pytest-asyncio — для тестов.
- `storage`: движок процесса (ленивый, один, проверка соединения перед выдачей, имя приложения,
  пояс UTC); движок задачи воркера со своим малым пулом и закрытием в конце; `session_scope()` —
  фиксация на выходе, откат при ошибке; `step()` — шаг стадии на точке сохранения. Значения
  параметров запросов в ошибки и журнал не попадают.
- Настройки пула: процесса и задачи воркера; адрес базы разработки по умолчанию — порт 5462.
- Тестовая обвязка: своя база `audit_test_…`, снос схемы только в базе с этим префиксом;
  остановка без Postgres; фикстура `session` во внешней транзакции теста; фикстура настоящих
  фиксаций на двух соединениях; предупреждения в тестах — ошибки.
- Строка в `README.md`: как снести тестовую базу снятой рабочей копии.

## Out of scope
- Соглашение об именах ограничений, база моделей, перечисления — Ч1.2б.
- alembic, ревизии, сверка моделей с базой, замок миграций — Ч1.2б; тестовая база перейдёт на
  `alembic upgrade head` с нуля там же.
- Пароли в адресах Redis и базы, длина пароля базы в бою — Ч1.2б.
- Таблицы продукта; «вставить или пропустить», захват строки, бронь расхода — Часть 3.

## Acceptance (observable)
- [ ] Записанное видно другому соединению только после фиксации; сбой шага откатывает шаг, а не
      стадию; обрыв процесса точка сохранения не переживает.
- [ ] Задача воркера в своём цикле событий работает с базой и не оставляет соединений.
- [ ] Тесты не трогают никакой базы, кроме своей тестовой; без Postgres прогон честно
      останавливается.
- [ ] Гонку двух соединений тест воспроизводит и краснеет, если защиту убрать.

## Прогоны: семь вопросов

Шагов прогона в поставке нет: она даёт инструменты, на которых их соберут в Части 3.

| Вопрос | Ответ |
|---|---|
| 1. Повтор шага | не относится: шагов прогона нет; повтор шага решает его владелец, Часть 3 |
| 2. Сбой и число попыток | не относится: повторов запросов нет. Убитое соединение пула заменяется проверкой перед выдачей (A9) — это не повтор запроса |
| 3. Потолок | не относится: платных вызовов и расхода нет |
| 4. Обрыв посреди шага | точка сохранения обрыв процесса не переживает: сделанное цело только после фиксации (A10); фиксация на шаг — Часть 3 |
| 5. Кто ещё меняет те же данные | два соединения с одним ключом дают одну строку (A12); две рабочие копии гоняют тесты в разных базах (A12) |
| 6. Двойное нажатие или запрос | не относится: действий человека нет |
| 7. Тревога | не относится до Ч1.14: тревог в поставке нет |

## Non-functional
- Тесты не читают `.env`, `DATABASE_URL` и переменные разработчика, не ходят в сеть дальше
  тестового Postgres.
- Полный прогон тестов — один на рабочую копию за раз.
- Строки до 100 знаков, форма — как у форматтера ruff (он придёт с волной В1).
