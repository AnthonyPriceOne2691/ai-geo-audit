## Problem
- **Файла окружения сервера нет.** Не решено, кто и какой командой создаёт секреты и как
  секреты владельца попадают на сервер, не проходя через чат.
- **Порт и подсеть нечем сверить с соседом.** Живой снимок не видит остановленный сервис соседа:
  его порт и подсеть записаны только в файлах compose. Займём их — сосед упадёт на своём
  следующем подъёме.
- **Боевое наложение не знает сервера:** образы в нём не по дайджесту из файла сервера, боевой
  режим и формат журнала не названы.
- **Токену бота нет места:** правила Ч1.5а не дают передать секрет процессу вне его списка
  проверки старта.
- **Ядра скрипта выката нет:** исполнителя команд, журнала хода, замка и правил «что скрипт
  пишет на диск».

## Users / stakeholders
- **Ведущая.** Запускает команды на сервере по слову владельца; читает вывод, годный для
  `observed.md` без правки.
- **Владелец.** Видит и подтверждает каждый заход; кладёт свои секреты файлом у себя.
- **6в, 6б и 6в3.** Берут ядро: исполнитель, отчёт, замок, функцию файлов, чтение файла
  сервера, снимок соседа; `up` берёт ещё `check`.
- **Сосед.** Его порты, подсети, контейнеры и файлы не меняются и не отнимаются.

## In scope
- **Боевое наложение** `docker-compose.prod.yml`:
  - у migrate и api — `image: ${BACKEND_IMAGE:?…}`, у web — `image: ${WEB_IMAGE:?…}`, у всех трёх
    `pull_policy: never`: на сервере ничего не собирается;
  - у migrate и api — `APP_ENV: prod` и `LOG_FORMAT: json` литералами.
- **Правила боя** — два новых: `image-from-server` и `prod-mode`. `image-digest` Ч1.5а значение
  `${VAR:?…}` в наложении не судит: его судит `image-from-server`.
- **Конфиг.** `ALERT_TELEGRAM_BOT_TOKEN` — секрет, `ALERT_TELEGRAM_CHAT_ID` — целое; в бою оба
  обязательны у api. Разбор конфига без запуска сервиса — `python -m ai_geo_audit.ops.config_check
  <процесс>`; ошибку импорта конфига команда ловит и называет без значения.
- **`.env.example`, блок «сервер»** — имена, у каждого пометка: «создаёт скрипт», «задаёт
  владелец», «пишет выкат».
- **Скрипт выката** `deploy/deploy.py` — только стандартная библиотека; ядро:
  - один исполнитель внешних команд: предел времени у каждой, пустой stdin, значения — только
    через окружение процесса, дочерние процессы — в своей сессии;
  - отчёт по шагам, время — UTC с Z; ход сначала пишется в `.deploy/`, вывод в терминал — по
    возможности: обрыв связи шаг не роняет;
  - замок одного запуска; метка «идёт выкат» с номером процесса и временем;
  - одна функция файлов: запись через временный файл с правами 600 с момента создания,
    переименование и удаление — только под своими корнями;
  - чтение файла сервера без исполнения: права, владелец, заглушки, пустые значения;
  - снимок соседа до и после — его зовут `check`, `up` и `proxy install`.
- **Команды:** `env-init`, `put-secret <файл>`, `check`, `last`.
- **`.gitignore`:** `.deploy/`.
- **Памятка** `deploy/README.md`, часть подготовки: каталоги, `env-init`, ввод секретов
  владельца, копии у владельца, `check`, правила общей машины, запуск долгих команд под `tmux`.

## Out of scope

  по реестру.
- **6б:** блок nginx хоста, сертификат, пароль сайта, пробы через прокси, стенд.
- Остальное вне Ч1.6 — общая спека, «Сверка с ТЗ», п. 3, и спеки 6в и 6б.

## Acceptance (observable)
- [ ] Файл окружения и мастер-ключ создаются на сервере командой скрипта; секреты владельца
      приходят файлом и в вывод не попадают.
- [ ] `check` отказывает на занятом имени, порту и подсети — живых и объявленных в файлах compose
      соседа — и на нехватке памяти и диска; перед первым выкатом проходит.
- [ ] В выводе и журнале скрипта нет секретов, адресов, портов, домена и имён соседа; скрипт
      трогает только свои файлы и свой стек.
- [ ] Боевое наложение задаёт образы и бой; правила это держат; разбор конфига — без значений.

## Прогоны: семь вопросов

Шаг здесь — `env-init`, `put-secret`, `check`. Шагов аудита нет.

| Вопрос | Ответ |
|---|---|
| 1. Повтор шага | `env-init` второй раз — отказ, ничего не пересоздаёт (A182); `put-secret` с тем же файлом — те же строки, входящий удалён; `check` — только чтение, повтор ничего не меняет |
| 2. Сбой и число попыток | своих повторов нет; отказ — со словами, что делать. Повтор — человеком |
| 3. Потолок | платных вызовов нет; у каждой внешней команды — предел времени |
| 4. Обрыв посреди шага | запись файлов — через временный и переименование: прерванная запись прежний файл не портит; ход — сначала в `.deploy/`; обрыв связи шаг не роняет |
| 5. Кто ещё меняет те же данные | сосед: свои контейнеры, порты, подсети, файлы; `check` их читает и не меняет (A185, A186). Два запуска разом — замок, второй отказывает сразу |
| 6. Двойное нажатие или запрос | двойной `env-init` — отказ; двойной `put-secret` — второй не находит входящего файла и отказывает словами |
| 7. Тревога | не относится до Ч1.14; отказ громкий — код выхода и причина в выводе и в `.deploy/` |

## Безопасность
1. **Что появляется.** На сервере — файл окружения со всеми секретами стека, мастер-ключ, каталог
   входящих секретов и скрипт, который запускают от root. Входов из сети нет.
2. **От кого защищаемся.**
   - Ошибка оператора: секрет в выводе или в аргументах, широкие права файла, заглушка в бою,
     пароль роли и пароль в адресе разошлись, порт или подсеть соседа.
   - Утечка в git и чат: файл окружения в дереве, секрет владельца через чат.
   - Вред соседу: его порт, подсеть, имена, файлы; «уборка» не своего.
   - Не защищаемся: от root машины и соседа с root.
3. **Защиты этой поставки.** Каждая краснеет без своей защиты:
   - A182 — создание на сервере, права, повтор, ввод секретов владельца файлом;
   - A183, A184 — вывод и аргументы без секретов и чужого, домен только из файла сервера;
   - A185, A186 — права и заглушки файла сервера, имена, порт, подсеть, ресурсы, снимок соседа,
     только свои файлы;
   - A181, A189, A192 — бой в наложении, разбор конфига без значений, пары «пароль — адрес», токен
     бота секретом.
4. **Что проверит ведущая своими пробами.** Матрица прав и заголовки не применимы: входа из сети
   нет. Применимо: вывод `env-init`, `put-secret` и `check` на стенде с метками — меток нет; права
   и владельцы файлов; своя порча — печать значения в одном месте, тест A183 красный.
5. **Открытое.** Копии секретов у владельца — переносом файлов (общая спека, «Секреты»); снимок
   соседа не видит его медленной работы — Часть 13.
6. **Опора на опись защит соседа.** З83 — вход на сервер только по ключу, настройки машины не
   трогаем. Чего в описи нет, делаем сами: создание секретов на сервере, ввод секретов владельца
   файлом, сверка с портами и подсетями из файлов соседа, снимок соседа, функция файлов под своими
   корнями, вывод без секретов и чужих имён.

## Non-functional
- Скрипт — один файл, стандартная библиотека Python; на сервере — `python3 -I deploy/deploy.py`:
  каталог скрипта не попадает в путь импорта. Тесты скрипта идут и на минимальной версии Python
  из разведки — джоба `tests` на 3.12: минор из `requires-python` (A99) равен версии сервера,
  отдельного шага нет; синтаксис новее неё краснеет до сервера.
- Команды неинтерактивные: запросов с клавиатуры нет; долгие команды ведущая запускает под
  `tmux new -d` и смотрит их короткими вызовами `last`.
- Свои корни: `/srv/ai-geo-audit/`, корень копий по решению среза 0, `/etc/ai-geo-audit/`; 6б
  добавляет свои файлы nginx и каталог выдачи сертификата. В тестах корень — временный каталог.
- Строки до 100 знаков, кроме строк таблиц и блоков команд.
- **Чего защита не ловит.**
  - root машины и сосед с root видят файл окружения и мастер-ключ.
  - Окно пальца: после касания ключ сервера открыт всем процессам владельца, пока ведущая не
    закроет его `ssh-finger lock`; `ssh` в конституции — `ask`: одно «да» в этом окне — и сессия
    на сервере.
  - Порт соседа, заданный переменной без умолчания, `check` не знает: он только говорит о нём.
  - Подсеть, которую сосед заведёт позже, `check` увидит только на следующем выкате.
