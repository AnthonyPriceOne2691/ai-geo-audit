# Spec: сборка фронта (Ч1.4а)

Поставка идёт параллельной полосой фронта: код пишет исполнитель полосы в своей рабочей копии.
В main сливается строго по очереди через проверяющего.

Разрез проверяющего 2026-11-19: фронт первой стадии — три поставки по шву «сборка / тема /
клиент». Это Ч1.4а «Сборка», Ч1.4б «Тема» (спека — рабочий черновик вне репозитория), Ч1.4в
«Клиент API». Порядок в полосе: 4а → 4б → 4в, без перерыва между 4а и 4б.

Источники:
- черновик Д2 (рабочий черновик вне репозитория), его строки Д2-1…Д2-11;
- решения проверяющего 2026-11-18 по вопросам В1–В12 черновика и 2026-11-19 — по этой спеке;
- слова владельца 2026-11-18 о виде сервиса.

Номера примеров у фронта свои — F1…, правило сканера — общее A23. Номера F сквозные для 4а и 4б,
поэтому здесь нет F6, F10–F15, F18–F20: они в Ч1.4б. Владелец подписывает примеры 4а пачкой с
Ч1.4б и Ч1.2в; подпись вносит проверяющий своим коммитом.

## Problem
Фронта ещё нет. Его первая поставка закладывает:
- сборку, линтер и тесты на Node 24, с цепочкой проверок и оракулом сборки;
- цепочку поставки пакетов: только реестр npm, точные версии, скрипты установки выключены;
- имя сервиса в одном месте и страницу-заглушку, которая называет сервис и говорит, что на ней
  есть.

Своя тема — сразу следом, в Ч1.4б.

## Users / stakeholders
- **Исполнитель следующих поставок фронта.** Цепочка `npm run check` скажет о любой поломке.
- **Проверяющий.** Принимает сборку оракулом и снимками двух ширин.
- **Тот, кто собирает образ (Ч1.5).** Сборка проверена оракулом: страница не ссылается на
  несуществующие файлы, служебного и чужих узлов в ней нет, встроенных скриптов нет — CSP для
  скриптов обойдётся без хешей.
- **Волна В1, проверки фронта (В1б).** Ей нужна только сборка из этой поставки.

## Acceptance (observable)
- [ ] `npm run check` проходит на Node 24 и отказывает на другом; дерево после цепочки чистое.
- [ ] Сборка проверена оракулом:
  - каждый файл, на который ссылается страница, есть;
  - нет `.map`, встроенных скриптов, адресов разработки и чужих узлов;
  - адреса узлов в JS сборки — только из поимённого списка с причиной.
- [ ] Пакеты — только из реестра npm, у каждой записи пакета в lock есть `integrity`, версии
      точные; каждая прямая зависимость — из одобренного списка; скрипты установки выключены.
- [ ] Имя сервиса — в одном месте. Заглушка называет сервис и говорит, что на ней есть; на
      1440 × 900 и 390 × 844 страница не шире окна — по снимкам для приёмки.

## Прогоны: семь вопросов

Шагов прогона в поставке нет: вопросы приложены к сборке и тестам.

| Вопрос | Ответ |
|---|---|
| 1. Повтор шага | Повтор сборки — `npm ci` по lock и та же цепочка; дерево после неё чистое (F3, F4) |
| 2. Сбой и число попыток | Своих повторов нет; любой красный шаг цепочки — код ≠ 0 (F3) |
| 3. Потолок | Платных вызовов нет. Ресурсный предел — не больше двух воркеров тестов на общей машине (F2) |
| 4. Обрыв посреди шага | Сборка, оборванная посередине, оставляет `dist/` со ссылками на несуществующие файлы — оракул красный (F5) |
| 5. Кто ещё меняет те же данные | Вторая сессия и соседи гоняют тесты в ту же минуту — предел воркеров (F2) |
| 6. Двойное нажатие или запрос | Не относится: запросов к серверу в Ч1.4а нет |
| 7. Тревога | Не относится: фронт тревог не шлёт |

## Безопасность

1. **Что появляется.** Статические файлы фронта: HTML, JS, CSS. Данных заказчика, секретов и
   запросов к API нет. Новая поверхность — пакеты npm.
2. **От кого защищаемся.**
   - Внедрение скрипта: страница готова к строгой CSP без хешей для скриптов.
   - Подмена или лишняя зависимость, скрипт установки пакета.
   - Утечка служебного в сборке: карты исходников, адреса разработки, запросы к чужим узлам при
     загрузке страницы.
3. **Защиты этой поставки.** Каждая краснеет без своей защиты:
   - F7 — встроенных скриптов нет;
   - F5 — нет `.map`, адресов разработки и чужих узлов; узлы в JS — только из поимённого списка
     с причиной;
   - F17 — пакеты только из реестра npm, с `integrity` у каждой записи пакета в lock, точными
     версиями; каждая прямая зависимость — из одобренного списка; скрипты установки выключены;
   - F1 — одна версия Node.
4. **Что проверит ведущая сессия своими пробами.** Заголовков ещё нет: сервер фронта — Ч1.5.
   Проверяет собранные файлы — чужие узлы, встроенные скрипты, карты исходников — и снимки двух
   ширин. Чужой узел подкладывает в формах: адрес без схемы, `@import`, `preconnect` и
   `dns-prefetch`, `srcset`, `url()` в CSS.
5. **Открытое.**
   - Заголовки защиты и CSP — на nginx образа, Ч1.5. CSP для скриптов будет без хешей (F7).
     Для стилей — не так: Mantine вставляет переменные темы встроенным тегом `style`. Разрешать
     встроенные стили или давать метку — решается в Ч1.5 вместе с заголовками.
   - Аудит зависимостей на уязвимости в CI — волна В1.
   - Вывод текста страниц клиентов и ответов моделей только как текст — с первым экраном, где он
     появится; правило — в `frontend/UI_RULES.md` (Ч1.4б).
6. **Опора на опись защит соседа.** Ссылки на строки З и Б — после приёмки описи.
