# Spec: фронт под nginx и защита стека (Ч1.5б)

Источники:
- рабочий черновик Ч1.5 «Образы и compose» вне репозитория, его строки Д4-21…Д4-29;
- решения ведущей 2026-11-18 и 2026-11-19: доверенный адрес — постоянный адрес web, подсеть
  из переменной; Д4-26 остаётся здесь; журнал — драйвер journald в боевом файле,
  окончательно — в Ч1.6; цель защиты — ASVS 5.0, уровень L2; стили в CSP — вариант «а»;
  адрес клиента в строке доступа api даёт Ч1.3 (её A47); правило версий образов;
- опись защит соседа — строки З и Б с поставкой Ч1.5, сверены с кодом и тестами соседа;
- спеки Ч1.3, Ч1.4а и Ч1.4б: строка доступа и форма отказа api, CSP для скриптов без хешей.

Номера примеров сквозные: здесь A77–A87, A88 и A89 — в Ч1.5в, в Ч1.5а — A60–A73, в «Оракуле
стека в CI» — A74–A76 и A124–A129. Правило сканера слов — общее A23.
Ветка — от main `4b46e66` (решение проверяющего 2026-11-23T09:48Z): Ч1.5а и Ч1.3б уже в main —
те же файлы compose, те же правила и тот же оракул; предел тела из кода Ч1.3б — там же.
«Оракул стека в CI» ляжет в main раньше этой поставки; main с ним вливается в ветку по команде
проверяющего, и только после этого — строка web в списке скана и срез с таблицей шагов.

## Problem
- **Фронта в стеке нет.** Сборку Ч1.4 никто не отдаёт. Заголовков защиты и CSP нет: Ч1.4а и
  Ч1.4б оставили их сюда вместе с решением о встроенных стилях Mantine.
- **`/api/` должен идти через web:** одно происхождение для браузера, CORS не нужен. Адрес
  клиента api берёт только от web — иначе подставной заголовок обойдёт будущий счётчик
  попыток входа (Ч1.8).
- **Стек после Ч1.5а слишком доверчив:**
  - у контейнеров полные права Linux по умолчанию;
  - все сервисы в одной сети с выходом наружу;
  - migrate и api ходят в базу одной ролью — суперпользователем образа базы: взлом api даёт
    право менять и удалять схему и всё в базе; Redis отвечает любому соседу по сети без
    пароля. Это закрывает поставка «Учётки хранилищ» сразу после этой.
- **Боевых отличий нет:** лимитов, журнала, переживающего пересоздание контейнера, потолка
  Redis, счёта соединений базы. Перезапуск упавшего процесса и мягкая остановка не проверены.

## Users / stakeholders
- **Тот, кто выкатывает (Ч1.6).** Боевой файл накладывается на основной; прокси хоста
  перезаписывает адрес клиента, web передаёт его как есть.
- **Ведущая.** Принимает заголовки на всех видах ответов, права контейнеров и сети.
- **Ч1.8.** Адрес клиента для счётчика попыток входа берётся только от web.
- **Поставка «Учётки хранилищ».** Идёт сразу после этой, в те же compose и оракул.
- **Экран.** Таблицы отказов у экрана в main нет: Ч1.4в в main не вошла. Образцы web из файла
  договора читают тесты и оракул; экран возьмёт тот же файл, когда его таблица появится.
- **Часть 3 и дальше.** Воркер встаёт в сеть данных.

## In scope
- **Образ фронта** — `deploy/web/Dockerfile`, контекст — корень репозитория, белый список —
  `deploy/web/Dockerfile.dockerignore`: открыты `frontend/` и `deploy/web/`; снова закрыты
  `node_modules`, `dist`, `coverage` и файлы окружения `.env*`.
  - Стадия сборки на `node` линии 24-alpine: `npm ci`, `npm run build`, `npm run check:dist`.
    Битая сборка роняет сборку образа, а не выкат.
  - Итоговая стадия на `nginx` линии 1.30-alpine: в корне сайта — ровно собранное, файлы
    образа nginx оттуда убраны; в `conf.d` — только наш файл; пользователь `nginx` образа,
    uid 101; порт выше 1024; pid и временные файлы — в `/tmp`.
  - Версии — правило Ч1.5а: с Docker Hub по дайджесту, тег линии и дайджест, последний патч
    линии, который на день кода старше 14 суток. Исключение — выпуск, который закрывает
    находки скана образа (A126): его берём сразу, по слову владельца.
- **`deploy/web/nginx.conf` и `deploy/web/security-headers.conf`:**
  - `server_tokens off`;
  - заголовки сниппетом, все с `always`, на уровне server и в каждом location со своим
    `add_header`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
    `Referrer-Policy: no-referrer`,
    `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`,
    `Cross-Origin-Resource-Policy: same-origin`; у страницы — ещё CSP и
    `Cross-Origin-Opener-Policy: same-origin`. На `/api/` свой `nosniff` сервиса (Ч1.3, A49)
    скрыт `proxy_hide_header`: заголовок один;
  - кэш: страница — `no-cache`, файлы сборки — год и `immutable`, одним заголовком;
  - любой путь экрана отдаёт `index.html`;
  - `/api/` ведёт к api через DNS докера: `resolver` с `valid=10s` и переменная в
    `proxy_pass`; `X-Forwarded-For` — как есть;
  - предел тела — 1 МБ, то есть 1 048 576 байт, равный пределу тела сервиса (Ч1.3б): равенство
    держит тест без Docker (A84). Предел ожидания ответа — 30 с. Пределы ожидания заголовков
    и тела — в Ч1.6, решение ведущей: те же пределы стоят на прокси хоста;
  - отказы 413, 502 и 504 на `/api/` — JSON общей формы отказа с `no-store`, а не страница
    nginx. Тела — из общего файла договора `contracts/api-refusals.json`: эта поставка
    добавляет в него раздел «прокси» — 413 `too-large`, 502 и 504 `unavailable`. Оракул и тест
    сверяют ответ и `nginx.conf` с файлом, а не со своей копией текста. Тексты `detail`
    читает человек: экран показывает их как есть. Поэтому они — простыми словами, без имён
    заголовков, кодов и внутренних имён. У `too-large` один текст у сервиса и у прокси — с
    числом предела, поэтому пределы обязаны быть равны;
  - свой журнал доступа: время, метод, путь без строки запроса, код, время ответа, адрес из
    `X-Forwarded-For`. У соседа в nginx контейнера формата нет вовсе, и умолчание образа
    пишет строку запроса целиком — третий журнал рядом с uvicorn и прокси хоста;
  - журнал ошибок — только с уровня `crit`: строки уровня `error` несут строку запроса с
    параметрами.
- **Стили в CSP — решение ведущей, вариант «а»:** `style-src 'self' 'unsafe-inline'`, как у
  соседа. Почему — по исходникам Mantine 8.3.18, сверила ведущая:
  - `MantineCssVariables`, `InlineStyles` и `MantineClasses` вставляют элементы `<style>` —
    переменные темы и отзывчивые свойства. Политика без `'unsafe-inline'` их блокирует;
  - атрибуты `style`, которые React ставит через CSSOM, политика не задевает;
  - метку библиотека умеет (`getStyleNonce`), но выдавать её нужно на каждый ответ: это
    подстановка в nginx, около 60 строк; цель — ASVS L2, метка на ответ — требование L3;
  - вставку тега держат запрет встроенных скриптов и вывод чужого текста только текстом;
    остальные источники — `'self'`: вынести данные стилем некуда.
- **compose:**
  - сервис web: порт опубликован только на петле, `WEB_PORT`; ждёт api healthy; проверка
    здоровья — страница `/`: `interval` 10 с, `timeout` 3 с, `retries` 3, `start_period` 10 с;
  - сети: `data` — внутренняя, для db, redis, migrate и api; `front` — внутренняя, для api и
    web, подсеть — `FRONT_SUBNET`, у web постоянный адрес `WEB_ADDRESS`; `edge` — обычная,
    только для web: опубликованному порту нужна обычная сеть;
  - `API_TRUSTED_PROXIES` у api — ровно `WEB_ADDRESS`. В compose это стоит с Ч1.5а
    (`${WEB_ADDRESS:?…}`, правило `trusted-proxy`); эта поставка даёт web постоянный адрес и
    правило `trusted-is-web`: доверенный адрес обязан быть адресом web;
  - урезанные права у всех: `cap_drop: [ALL]`, `no-new-privileges`, корень только для чтения
    с `tmpfs` там, где процессу нужна запись;
- **Правила compose** — семь новых в основном наборе; коды — в A87.
- **Оракул** — шаги web и защиты стека. Порт web и подсеть `front` он
  выбирает от имени стека: занятый кандидат — следующий из ряда.

## Out of scope
- **Ч1.6:** файл прокси хоста — пароль на весь сайт, TLS и его версии, HSTS, запрет
  индексации, сервер по умолчанию для чужого имени, зона частоты на `/api/`, перезапись адреса
  клиента, его отказы в общей форме; обычный порт открыт только для перенаправления и выдачи
  сертификата; публикация образов; journald на сервере окончательно; первый живой подъём
  боевого наложения; права файла мастер-ключа на сервере. Решение ведущей: туда же пределы
  ожидания заголовков и тела — бывший медленный клиент из A84.
- **Ч1.5в «Остановка и боевое наложение»** — сразу после этой, до «Учёток хранилищ»:
  `stop_grace_period`, разбор остановки, правило `stop-grace`, `docker-compose.prod.yml` и три
  боевых правила; примеры A88 и A89 (слово владельца 2026-11-23T14:06:40Z).
- **Поставка «Учётки хранилищ» — сразу после Ч1.5в, около 150 строк; зависимость:** она
  попадает в main до первого выката, Ч1.6 от неё зависит. Её пример — A85. В ней:
  - две роли базы — владелец схемы для migrate и роль сервиса для api, без права менять
    схему, с правами по умолчанию на будущие таблицы и последовательности; правило
    `db-roles`;
  - Redis с `--requirepass` из переменной сервера, проверка здоровья — с паролем; у api адрес
    очереди с паролем, как уже стоит в образце окружения;
  - проверка старта в бою: адрес Redis без пароля или с паролем короче 12 знаков — отказ,
    зеркало A21; правило compose `redis-auth`.

  Причина пароля очереди — требование ASVS L2 о проверке подлинности при связи между частями
  сервиса, а не «с первым потребителем»; и слово владельца: к первому выкату сервис защищён.
- **Ч1.8:** только Redis в проверке здоровья.
- **Часть 4:** сеть с выходом наружу для обходчика и вызовов провайдеров — с первым, кому она
  нужна.
- **Часть 3:** правило `db-connections` — сумма пулов против `max_connections`, решение
  ведущей: сумма впервые растёт с пулом воркера.
- **Этап 1.1, конец Части 5:** замер лимитов под нагрузкой — три технических аудита разом на
  общем сервере, по нему пересчёт лимитов контейнеров; повтор — Часть 13.
- **Хвост Части 1:** выгрузка журнала с машины (Б27, вторая половина).

## Acceptance (observable)
- [ ] Образ фронта отдаёт только собранное, не от root, на петле. Любой путь экрана — страница
      приложения, кэш страницы и файлов сборки — свой.
- [ ] У всех видов ответов — заголовки защиты, каждый ровно один; у страницы — CSP, каждая
      директива проверена; версии сервера нет.
- [ ] `/api/` через web переживает пересоздание api; отказы web — в общей форме; api верит
      адресу клиента только от web; в журналах web нет строки запроса.
- [ ] Контейнеры без лишних прав; база, очередь и api без выхода наружу.
- [ ] Упавший процесс перезапускается, остановка мягкая и не читается как падение.
- [ ] Боевое наложение держит лимиты, журнал и потолок Redis.

## Безопасность

1. **Что появляется.**
   - Первый вход из сети в стеке — порт web на петле машины. Снаружи к нему ходит только
     прокси хоста (Ч1.6).
   - Страница и `/api/` — с одного происхождения; заголовки защиты и CSP.
   - Файлы конфигурации nginx в образе.
   - Данных заказчика ещё нет, но ответы API будут их нести: `no-store` ставит сервис (Ч1.3),
     web его не снимает.
2. **От кого защищаемся.**
   - Посторонний из сети: внедрение скрипта ради пропуска из хранилища браузера, вставка
     сервиса во фрейм, угадывание типа файла, версия сервера в ответах.
   - Подставной адрес клиента — обход будущего счётчика попыток входа.
   - Утечка в журналы web: параметры запроса, пропуск, пароль прокси.
   - Огромные запросы и зависший api, которые держат web. Медленные клиенты — на прокси хоста,
     Ч1.6.
   - Захват контейнера: лишние права Linux, root у nginx, выход наружу из сети данных.
   - Ошибка оператора: нет лимита, порт не на петле, журнал пропал при пересоздании.
   - Не защищаемся — решение ведущей: шифрования внутри машины нет.
3. **Защиты этой поставки.** Каждая краснеет без своей защиты:
   - A79, A80 — заголовки и CSP, каждая директива; A78 — кэш страницы и сборки;
   - A77 — в образе только собранное, базы по дайджесту; A82 — nginx не от root, порт на петле;
   - A83 — адрес клиента api берёт только от web; в журналах web нет строки запроса;
   - A84 — предел тела и ответа, отказы общей формы без страницы nginx;
   - A86 — база, очередь, api и migrate без выхода наружу; web не видит базу и очередь;
   - A87 — урезанные права; лимиты, журнал, перезапуск и мягкая остановка — A88 и A89 в Ч1.5в.
4. **Что проверит ведущая сессия своими пробами.**
   - Заголовки на всех видах ответов, `curl -i` своей рукой.
   - Страница в Chrome без окна на машине: ноль нарушений CSP в консоли, в обеих темах.
   - Подробности в отказах: 413, 502, 504 — без версии и без страницы nginx.
   - Лимиты: тело больше предела, замерший api.
   - `docker inspect`: права, сети, пользователь.
   - Два живых прогона из двух копий (A82).
5. **Открытое.**
   - Прокси хоста — пароль на весь сайт, TLS, HSTS, запрет индексации, сервер по умолчанию,
     зона частоты, перезапись адреса клиента, его отказы в общей форме — Ч1.6. Там же
     обычный порт открыт только для перенаправления и выдачи сертификата. Ч1.6 зависит от
     поставки «Учётки хранилищ»: та попадает в main до первого выката.
   - Взлом api пока даёт право менять схему: migrate и api ходят одной ролью; Redis — без
     пароля. Две роли базы и пароль очереди — поставка «Учётки хранилищ» сразу после этой
     (A85).
   - Журнал journald окончательно — Ч1.6; выгрузка журнала с машины (Б27) — хвост Части 1.
   - Сторож здоровья судит остановку тем же разбором (A88, Ч1.5в): код 143 после остановки — не
     падение — Ч1.14.
   - Redis в проверке здоровья — Ч1.8. До «Учёток хранилищ» Redis виден только из сети
     `data`.
   - Сеть с выходом наружу для обходчика и провайдеров — Часть 4, с первым, кому она нужна.
   - Более строгий путь для стилей — метка из `$request_id` nginx на каждый ответ; вернуться к
     нему после первого выката.
   - Пределы ожидания заголовков и тела — Ч1.6, на прокси хоста; сумма пулов против

   - Замер лимитов под нагрузкой — этап 1.1, конец Части 5; повтор — Часть 13.

   - З12 — сниппет заголовков с `always`, `include` в каждом location (A79).

## Non-functional
- У каждого шага оракула свой предел времени; порт и подсеть — от имени стека.
- Шифрования внутри машины нет — решение ведущей: web, api, база и очередь говорят открытым
  трафиком внутри внутренних сетей докера.
- Строки до 100 знаков, кроме строк таблиц.
- **Чего защита не ловит.**
  - У web есть выход наружу: опубликованному порту нужна обычная сеть. Зато web не видит базу
    и очередь.
  - Подставной `X-Forwarded-For` с самой машины на порт web api примет: это граница машины,
    её держат прокси хоста и фаервол (Ч1.6).
  - `'unsafe-inline'` в `style-src` пропускает внедрённые стили; скрипты — нет.
  - Свой скрипт с того же адреса — например, подменённый пакет npm — CSP не держит: она
    держит чужие источники. Это цепочка поставки (В1, аудит зависимостей).
  - Отказы nginx вне `/api/` и с другими кодами — 400, 408, 414, 431 — идут страницей nginx.
  - Строки журнала ошибок nginx уровня `crit` и выше могут нести строку запроса; в обычной
    работе их нет.
  - Трафик внутри машины не шифруется (решение ведущей).
  - Медленный клиент держит соединение web до умолчаний nginx, пока не встанут пределы прокси
    хоста (Ч1.6).
