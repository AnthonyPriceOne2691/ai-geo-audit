## Problem
У сервиса нет входа из сети: нет приложения, точки запуска, проверки здоровья и формы отказов.
Это первая сетевая поверхность. За ней с Части 3 лягут данные заказчика, а слово владельца
2026-11-18 — защита закладывается сразу.

Умолчания библиотек здесь опасны:
- **uvicorn.** Свой формат журналов идёт мимо нашей вычистки секретов. Журнал доступа пишет путь
  вместе со строкой запроса. Заголовок `Server` называет сервер. Доверие заголовкам прокси у
  соседа — всем адресам. Набор `standard` приносит uvloop: он распознаёт имена мимо
  `socket.getaddrinfo`. Два поля uvicorn сам читает из окружения.
- **FastAPI.** Готовые схемы входа с `auto_error=True` отвечают 401 с `WWW-Authenticate`, а на
  401 браузер стирает пароль сайта. Ответ 422 возвращает присланное значение (`input`). 404 и
  405 — голым `{"detail": …}`.
- **Проверка входа зависимостью роутера опаздывает.** FastAPI читает и разбирает тело раньше
  зависимостей: битый JSON на закрытый адрес без пропуска получает 422. Неизвестный адрес без
  пропуска отвечает 404 — карту адресов видно без входа.
- **Секреты в запросе.** Пароль сайта (`Authorization: Basic`) прокси передаёт сервису в каждом
  запросе, пропуск (`X-Access-Token`) — тоже. Вычистка их из журнала — Ч1.3б (A48).

## Users / stakeholders
- **Экран (Ч1.4в, Ч1.10).** Одна форма отказа на весь API, её образцы — в общем файле
  `contracts/api-refusals.json`. `detail` экран показывает человеку как есть. Признак
  `signed-out` в заголовке. Номер запроса в каждом ответе.
- **Тот, кто собирает образ (Ч1.5).** Точка запуска `python -m ai_geo_audit.api`; здоровье 200
  или 503; настройки `API_*`; мягкая остановка 20 с. Пример A83 той поставки проверяет строку
  доступа этой (A47): без параметров запроса, с адресом клиента только от доверенного прокси.
- **Выкат (Ч1.6).** Доверенный адрес прокси в бою обязателен. Без пропуска открыт один путь —
  здоровье; без пароля сайта — ни одного (это держит прокси).
- **Тот, кто разбирает сбой.** Номер запроса в ответе и в журнале. Строка доступа на каждый
  запрос, и на отказанный воротами тоже. Трассировка 500 — в журнале с тем же номером.
- **Поставки входа и прав (Ч1.7–Ч1.9).** Проверка пропуска — одна функция: Ч1.8 меняет только её
  тело. Таблица видов отказа и файл образцов растут строками.

## In scope
- **`config`** — домен `ApiSettings` и объект `config.api`:
  - `API_HOST` и `API_PORT` — по умолчанию `127.0.0.1` и `8107`, порт разработки API из решения
    проверяющего 2026-11-18;
  - `API_TRUSTED_PROXIES` — строка: адреса и сети прокси через запятую, по умолчанию
    `127.0.0.1`. Поле — строка со своим разбором, не список: список из окружения
    pydantic-settings разбирает как JSON (проба 6). Каждый элемент — адрес или сеть не шире
    `/16` у IPv4 и не шире `/64` у IPv6; `*`, более широкая сеть (`0.0.0.0/0`) и негодный
    элемент отвергаются при сборке конфига в любом режиме. В бою настройка задаётся явно —
    строка проверки старта процесса `api`.
- **`api/app.py`:**
  - `create_app()`: проверка старта `api` и настройка журналов — до сборки приложения;
    обработчики отказов, промежуточный слой, роутер здоровья. Схема и консоль API выключены во
    всех режимах (`openapi_url`, `docs_url`, `redoc_url`, `swagger_ui_oauth2_redirect_url` —
    `None`); консоль в разработке — Ч1.3б (A51);
  - `server_settings()` — настройки uvicorn одной функцией.
- **`api/__main__.py`** — `python -m ai_geo_audit.api`: журналы, затем uvicorn с
  `server_settings()`, приложение — фабрикой.
- **`api/contract.py`** — договор API:
  - своё исключение отказа с видом из таблицы видов;
  - обработчики `HTTPException` и `RequestValidationError`. В 422 наружу уходят только `loc` и
    `type` каждой ошибки. Голый `HTTPException` библиотеки с кодом вне таблицы — в форме
    отказа: 4xx — вид `invalid`, 5xx — `internal`, текст вида, текста исключения нет;
  - база схем запросов с запретом неизвестных полей.
- **`contracts/api-refusals.json`** в корне репозитория — образцы ответов сервиса: шесть видов
  Ч1.3 и здоровье. Тесты бэкенда сверяют, что сервис отвечает именно так.
- **`api/access.py`:**
  - имена заголовков `X-Access-Token` и `X-Access-Refusal`;
  - проверка пропуска — `async def visitor_for(token: str) -> Visitor | None`: до Ч1.8 не
    признаёт ни одного пропуска; `create_app()` получает её при сборке, тесты передают свою;
  - поимённый список открытых путей с причинами — точные строки. В Ч1.3 в нём один путь,
    `/api/health`, во всех режимах (`test` — как `dev`);
  - зависимость закрытого роутера берёт вошедшего из состояния запроса — для прав Ч1.9 и для
    схемы консоли; нет вошедшего — 403 `signed-out`.
- **`api/middleware.py`** — чистый ASGI-слой; область `lifespan` идёт насквозь:
  - перехват падения — снаружи всего остального: исключение даёт 500 в форме отказа с номером
    запроса, наружу оно не выходит;
  - номер запроса;
  - ворота входа — до маршрутизации и до чтения тела: путь вне списка открытых без годного
    пропуска получает 403 `signed-out` сразу; с пропуском — вошедший в состоянии запроса;
  - строка доступа: метод, путь без параметров и в записи с процентами, код, длительность,
    номер запроса и адрес клиента — из заголовка прокси, только если соединение пришло от
    доверенного адреса.
- **`api/health.py`** — `GET /api/health`: своё короткое соединение под пределом
  `HEALTH_DB_LIMIT_SECONDS` = 3 с.
- **`logs/setup.py`** — поле `color_message` из записей uvicorn в вывод не идёт.
- **Пакеты** — `fastapi`, `uvicorn` (без `standard`), `httpx` в группе тестов; `uv.lock`.
- **`.env.example` и README** — новые переменные и строка о запуске сервера.

## Acceptance (observable)
- [ ] `python -m ai_geo_audit.api` поднимает сервер фабрикой. Настройки uvicorn — ровно таблица
      A34; в бою без нужных настроек приложение не собирается и называет их все.
- [ ] Доверенные прокси — названные адреса и сети не шире `/16` и `/64`; `*` и `/0` не
      принимаются нигде.
- [ ] Вход закрыт по умолчанию: без годного пропуска любой путь вне списка открытых — 403
      `signed-out` до маршрутизации и до чтения тела, есть такой адрес или нет.
- [ ] Каждый отказ — один из образцов общего файла: `detail`, `kind`, `retry`. 401 и
      `WWW-Authenticate` нет. В 422 — только `loc` и `type`, в 500 — подробностей нет.
- [ ] `GET /api/health` без пропуска: 200 `{"status": "ok"}` при живой базе, 503 в форме отказа
      при закрытой или молчащей; запросы, которым база не нужна, её не трогают.
- [ ] Журнал приложения и строка доступа идут через наш обработчик: время UTC, строки запроса
      нет, перевод строки из пути не рвёт запись.

## Виды отказа — договор на весь API

Форма у всех: `{"detail": "<что случилось и что делать>", "kind": "<вид>", "retry": <поможет
ли повтор>}`; у `invalid` — ещё `errors`, у каждой записи только `loc` и `type`. Признак
доступа — в заголовке `X-Access-Refusal`, а не в тексте: экран не разбирает слова.

`detail` читает человек: экран показывает его как есть. Поэтому текст — простыми словами, без
имён заголовков и полей, без кодов и внутренних имён. Имя заголовка пропуска стоит в договоре
API, а не в тексте отказа. Номер запроса у `internal` остаётся в тексте: его человек называет,
когда сообщает о сбое (решение проверяющего 2026-11-19T10:30Z, тексты `detail` приняты им же).

Образцы видов Ч1.3 лежат в `contracts/api-refusals.json`; новые виды добавляют свои поставки —
строкой здесь и образцом там. Голый `HTTPException` библиотеки с кодом вне таблицы: 4xx — вид
`invalid` с `errors: []`, 5xx — `internal`; текста исключения нет. Тексты видов, которые
придут позже, здесь — предложение; закрепляет их поставка вида.

## Безопасность

Цель — OWASP ASVS 5.0, уровень L2; требования L3 — там, где они дёшевы. Номера требований — по
описи защит соседа.

1. **Что появляется.**
   - Вход из сети: `GET /api/health` без пропуска. Схемы и консоли API нет ни в одном режиме.
   - Новое решение о доступе — вход закрыт по умолчанию: ворота отказывают любому пути вне
     списка открытых, пока проверка пропуска не признает пропуск. До Ч1.8 она не признаёт
     ни одного.
   - Данных заказчика ещё нет.
   - Секреты в каждом запросе: пропуск (`X-Access-Token`) и пароль сайта, который прокси
     передаёт сервису в `Authorization: Basic`.
   - Настройки: адрес и порт API, доверенные прокси. Пакеты: `fastapi`, `uvicorn`, `httpx`.
   - Общий файл образцов отказов — договор с экраном.
2. **От кого защищаемся.**
   - Посторонний из сети — за паролем сайта и без него, если прокси ошибся. Перебирает адреса,
     ищет схему API, версии и подробности ошибок. Карты адресов он не видит: без пропуска любой
     путь вне списка открытых — один и тот же 403.
   - Человек с паролем сайта, но без пропуска: его тело запроса сервис не читает.
   - Подставленный клиентом `X-Forwarded-For`: с Ч1.8 по адресу клиента считает счётчик попыток
     входа.
   - Ошибка оператора: доверие всем прокси или всему миру сетью `/0`, путь закрытого маршрута в
     списке открытых, uvloop, свой журнал uvicorn.
   - Подделка строки журнала переводом строки в номере запроса или в пути; строка запроса в
     журнале.
   - Вредная страница, файл или ответ модели — не относится: их в поставке нет.
3. **Защиты этой поставки** — каждая краснеет без своей защиты:
   - A32, A33, A47 — бой не стартует без настроек; доверенные прокси — только названные, сети не
     шире `/16` и `/64`, `*` нет; адрес клиента из заголовка — только от них (ASVS 4.1.3,
     15.3.4);
   - A34 — uvicorn: без `Server`, без своего журнала доступа, без окружения, мягкая остановка
     20 с, keep-alive 5 с (ASVS 13.4.6, L3);
   - A35 — один цикл `asyncio`: запрет сети в тестах действует и на боевом цикле;
   - A36 — журнал приложения идёт через вычистку секретов;
   - A39–A41 — здоровье не рассказывает о начинке; запрос, которому база не нужна, её не трогает;
   - A42 — вход закрыт по умолчанию: ворота до маршрутизации и до чтения тела, список открытых —
     точными строками, пропуск — только из `X-Access-Token`, сбой проверки вход не открывает,
     ошибка в списке открытых не открывает закрытый маршрут; 403 с признаком вместо 401, без
     `WWW-Authenticate` (ASVS 8.3.1);
   - A43–A45 — одна форма отказа по общему файлу образцов; 422 без присланных значений; 500 без
     подробностей, с номером (ASVS 16.5.1; API3:2023);
   - A46, A47 — присланный номер запроса и путь не подделают строку журнала; строки запроса в
     журнале нет (ASVS 16.2.5).
4. **Что проверит проверяющий своими пробами** — на живом сервере, не через тестовый клиент:
   - матрица прав: ролей ещё нет; без пропуска любой путь вне списка открытых — 403
     `signed-out`, существует он или нет; 401 нет нигде;
   - ворота не читают тело: сырой сокет шлёт заголовки с `Content-Length: 5000000` и делает
     паузу — 403 приходит раньше тела;

## Non-functional
- Тесты API — через ASGI-клиент `httpx` в том же цикле событий. Движок процесса в тестах
  смотрит в тестовую базу копии, база разработки не трогается.
- Маршруты-пробы и подставная проверка пропуска живут только в тестах. Литералов, похожих на
  секрет, в тестах нет: пропуск — из слов-заглушек, `Basic` собирается из слов.
- Тесты не ходят дальше петли (A30 Ч1.2в): сервер «базы» в A40 и A41 — на `127.0.0.1`. Имена
  `API_*` стоят в `.env.example` — их вычищает из окружения тестов A31.
- Коды ответов — числом: устаревшие имена кодов на пути отказа при `filterwarnings = error`
  превращают отказ в 500.
- Строки до 100 знаков, форма — как у форматтера ruff (он придёт с волной В1).
- **Чего защита не ловит:**
  - до Ч1.3б пропуск и пароль сайта, попавшие в текст записи, не маскируются: код Ч1.3 их не
    пишет, а вычистка запроса — A48 Ч1.3б. Там же: своим значением `Basic` клиент может
    вычистить кусок строки о собственном запросе — путь при этом остаётся в журнале прокси
    (Ч1.5б);
  - отказ транспорта uvicorn (400 на негодный HTTP-запрос, заголовки больше 16 КиБ) идёт его
    текстом — до приложения;
  - номер запроса из `X-Request-ID` присылает клиент: он может повторить чужой номер. Подделать
    строку журнала он не может (A46). В бою номер ставит прокси хоста и перезаписывает
    присланный (Ч1.6);
  - путь из списка открытых открыт любому методу: лишний метод получает 405 без пропуска;
  - доверенный прокси сам может подставить чужой адрес: перезапись адреса клиента держит прокси
    хоста (Ч1.6). Значение `127.0.0.1` из образца окружения, скопированное в бой, пройдёт
    «задано явно» — доверие от этого уже, а не шире;
  - ворота видят только область `http`: включённые вебсокеты прошли бы мимо них — их держит
    `ws="none"` (A34);
  - здоровье без входа говорит любому, отвечает ли база: это его работа;
  - здоровье делит пул соединений с будущими закрытыми маршрутами: поток запросов к нему при
    медленной базе держит пул до 3 с на запрос — до предела запросов в работе (Ч1.3б) и зоны
    частоты (Ч1.6).
