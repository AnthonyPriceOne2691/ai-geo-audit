## Problem
- **Справочник в базу пишет только помощник тестов.** Ч2.1 проверяет файл и показывает «было —
  станет», а записи командой нет: настоящий справочник в базу боя не попадает (ТЗ:189, :384).
- **Руководитель меняет пороги и важность без программиста** (ТЗ:113, :116, :192) — функции
  правки нет.
- **Запись не трогает прошлого:** новая редакция, прежняя неизменна, активна одна — и у
  загрузки, и у правки; по прежней посчитаны прошлые аудиты (PHASES:302, :306).
- **Две записи разом** или запись поверх невиданной редакции не должны дать двух активных,
  записи поверх того, чего человек не видел, или молча отменённой правки.

## Users / stakeholders
- **Ведущая** — первая загрузка настоящего файла на бой по слову владельца; дальше — инженер

  аудита.

## In scope
- **Замок `REFERENCE`** — ключ в реестре `storage/locks.py`; различие ключей держит тест A19.
  Каждая запись редакции — загрузка и правка — одна транзакция: первым запросом — предел ожидания
  `lock_timeout` и `pg_advisory_xact_lock(REFERENCE)`, как у миграций (`env.py`); активная
  редакция читается после замка. Ждали дольше 10 с — отказ «справочник сейчас пишет другая
  запись: ждали 10 с — повторите позже», база не тронута.
- **Запись редакции** — `reference/store.py`, одна функция для загрузки и правки: прежняя
  активная — `archived` с `archived_at`; новая — номер на 1 больше наибольшего, `active`; строки
  и пороги — вставкой. Порядок «погасить прежнюю, записать, зажечь новую» — под частичным
  индексом одной активной (кейсы L133, L134). Пределы порога ложатся в редакцию из таблицы
  единиц (Ч2.1).
- **Команда** `load <файл|-> --expect <знак> --reason <текст> [--replace-edits] [--manifest
  <путь>]`:
  - до базы — как у `check`: проверка старта, файл, его пределы и схема, манифест (A305–A308
    Ч2.1), файл со стандартного ввода (`-`) — с тем же пределом; знак — вида
    `<sha256>@<номер>`; причина — не пусто, до 500 знаков, одной строкой без управляющих знаков
    (категория Unicode Cc: перевод строки, `ESC`, NUL);
  - под замком, по порядку: содержимое равно активной редакции — «уже загружено: редакция N»,
    код 0, при любом знаке; знак — тот же sha256 файла и тот же номер активной; активная —
    правка (после последней загрузки файла справочник правили) — без `--replace-edits` отказ;
    пропавшая строка — отказ теми же словами, что у `check` (A312 Ч2.1); запись;
  - «содержимое равно» — пустое «было — станет» `diff` Ч2.1: `3.25` и `3.250`, доля `10` и
    `10.0` — одно число; дата снимка и sha256 в сравнение не входят — как у `check` (A304 Ч2.1,
    четвёртая строка); порядок строк входит — переставленные строки дают новую редакцию
    («порядок: строк на других местах N», решение ведущей 2026-11-26 в Ч2.1);
  - итог — «редакция N активна: строк K, порогов P»; сбой до фиксации — «сбой записи: <тип> —
    справочник не тронут»; сбой на фиксации — «сбой на фиксации: <тип> — запись могла пройти,
    проверьте status»; без текста исключения и трассировки (L57, L118).
- **Команда** `status` — активная редакция: номер, источник (файл или правка на основе N),
  строк, порогов, sha256 и дата снимка у файла, причина, время записи — UTC с `Z`. Пустой
  справочник — «справочник не загружен — загрузка: python -m ai_geo_audit.reference», код 1.
- **`check` — строка с готовой командой `load`** перед знаком: «запись: python -m
  ai_geo_audit.reference load <файл> --expect <знак> --reason "<чьё слово и когда>"»; последняя
  строка — по-прежнему знак (A304 Ч2.1). `--replace-edits` в готовой команде нет: отмену правки
  человек пишет сам по подсказке отказа.
- **Правка порогов и важности** — `reference/edit.py`, `change_thresholds(session, *, expected,
  changes, apply)`:
  - правка — `(код, поле, значение)`; поле — `importance`, `share_percent` или `param:<имя>`;
    тексты строки и прочие поля — отказ;
  - значение доли и порога — только конечный `Decimal`: булево, `float`, `int`, строка, NaN и
    sNaN — отказ «нужно точное число» до сравнения с пределом (L131), бесконечность — вне
    пределов; важность — `critical`, `important` или `low`; предел порога — из редакции
    (`min_value`, `max_value`); доля — больше 0 и не больше 100, у проверки по сайту доли нет;
    значение, равное прежнему, — отказ; одна правка поля дважды — отказ; пустой список правок —
    отказ «правок нет — ничего не меняется»; все причины — за один вызов, в порядке правок;
  - активна не `expected` — «справочник уже изменён: вы смотрели N, активна M — перечитайте»;
    пустой справочник — отказ «справочник не загружен…»;
  - `apply=False` — только отчёт; `apply=True` — под замком редакция N+1 из N с правками:
    источник «правка», основа N, причина пустая (кто правил — журнал Ч2.3); отчёт тот же:
    строки `diff` Ч2.1 и «редакция N → N+1».
- **README** — раздел «Справочник»: `load` и `status` — порядок `check` → `load` с тем же
  файлом и знаком, чьё слово в `--reason`, флаг `-T` для стандартного ввода, `--replace-edits`;
  правка — строкой: функция для Ч2.3; откат ревизии `0003` после первой загрузки стирает
  справочник.

## Как справочник попадает в базу — запись
1. **Файл, манифест и проверка — Ч2.1** («Как справочник попадает в базу», п. 1–3): файл ведущей
   в `source/`, манифест в git, `check` с «было — станет» и знаком.
2. **Запись — эта поставка.** `load` с тем же файлом, знаком из вывода `check` и причиной — чьё
   слово с меткой времени. Подменить файл или справочник между проверкой и записью нельзя (знак),
   чужая правка молча не отменяется (`--replace-edits`), повтор того же содержимого новой
   редакции не даёт («уже загружено»).
3. **Где.** На бою — одноразовый контейнер сервиса api из того же образа, файл — на стандартный
   ввод: `docker compose run --rm -T api python -m ai_geo_audit.reference load - --expect …
   --reason …`; на диске сервера файл не остаётся. На сервер ходит только ведущая, под пальцем
   владельца.
4. **Чьё слово.** Загрузка в базу боя — изменение живой базы: только по слову владельца в чате
   действующей сессии (конституция). Слово с меткой времени — в `--reason`, `status` его
   показывает. Первая загрузка — действие ведущей после выката этой поставки, в коде её нет;
   перед ней — сверка с живым листом (Ч2.1, п. 7).
5. **Условие первой загрузки — решение ведущей 2026-11-26.** Кандидат справочника Ч2.1 (58 строк,
   sha256 `dcf3c82e…`) не грузится, пока тексты норм и ошибок № 9–11 и выводы исполнителя в нём
   не подтвердит Head of SEO через владельца (Ч2.1, «Spec coverage gaps»). Поэтому манифест в коде
   остаётся пустым и в этой поставке: его заполняет отдельный коммит по подтверждённому файлу.
   До того `load` в бою отказывает до базы — «манифест не заполнен — файла ведущей в нём ещё нет»
   (A309); `--reason` первой загрузки называет и слово владельца, и подтверждение.

## Out of scope
- HTTP, права Руководителя и Админа, журнал действий, предел частоты — Ч2.3; экран с «было —
  станет» и запретом вне пределов — Ч2.4.
- Наборы — Ч2.2. Аудит запоминает редакцию — Ч3.1. «Старый аудит показывает прежние пороги»
  (PHASES:306) — Ч5.1.
- Правка текстов строки — не делаем: тексты меняет инженер файлом (ТЗ:189; граница ТЗ — спека
  Ч2.1, «Сверка с ТЗ», п. 4).
- Возврат к прежней редакции командой — не делаем: прежний файл грузится заново (`check` и
  `load`), прежний порог — новой правкой. Прежняя редакция при этом не оживает: новая — с новым
  номером.
- Первая загрузка настоящего файла — действие ведущей по слову владельца, а не код; условие —
  п. 5 «Как справочник попадает в базу». Заполнение манифеста в коде — отдельный коммит после
  подтверждения Head of SEO.

## Acceptance (observable)
- [ ] `load` годного файла — путём или со стандартного ввода — со знаком из `check` и причиной
      даёт новую активную редакцию; прежняя неизменна; `status` называет записанную.
- [ ] Повтор того же содержимого новой редакции не даёт; запись поверх невиданной редакции,
      поверх правки без флага, без причины или с управляющими знаками в ней, со знаком другого
      файла или без строки активной — отказ словами, база не тронута.
- [ ] Две записи разом — одна новая редакция; сбой посреди записи — ни строк, ни новой
      активной; сбой на фиксации не выдаётся за «не тронут».
- [ ] Правка порога, доли или важности даёт новую редакцию; предпросмотр и запись — один отчёт,
      предпросмотр не пишет; негодное значение, пустая правка и правка поверх невиданной — отказ
      словами.
- [ ] Прежние редакции неизменны после следующих публикаций — загрузкой и правкой.

## Безопасность

1. **Что появляется.**
   - Команда, которая пишет в базу боя: вход — файл и причина от человека. Входов из сети нет,
     новых секретов нет.
   - Функция записи правкой — без входа из сети: маршрут и права — Ч2.3.
2. **От кого защищаемся.**
   - Ошибка оператора: не тот файл, файл поменялся после проверки, загрузка поверх чужой правки,
     загрузка без причины, двойной запуск, не та база или не та роль, загрузка кандидата до
     подтверждения текстов № 9–11.
   - Гонка двух записей: две активных, запись поверх невиданной редакции.
   - Тихая правка прошлого: редакция, по которой посчитан аудит, поменялась задним числом.
   - Утечка текстов заказчика в вывод и журнал при записи; ложное «справочник не тронут» после
     сбоя на фиксации; подделанная строка вывода `status` — переводом строки или `ESC` в причине.
3. **Защиты этой поставки** — каждая краснеет без своей защиты:
   - A309 — знак, причина (одной строкой, без управляющих знаков), манифест и пропавшая строка —
     до записи; в бою — только манифест из образа, пустой — отказ до базы (условие первой
     загрузки, п. 5);
   - A311 — «уже загружено», отмена правки только флагом, прежняя редакция цела;
   - A313 — одна транзакция; итог сбоя на фиксации назван честно; текста исключения нет;
   - A314, A319 — замок, проверка «уже загружено» и знака под замком, предел ожидания;
   - A317 — прежние редакции неизменны после следующих публикаций;
   - A318 — значения в пределах редакции, булево, `float`, NaN и sNaN — не число, отказ до
     сравнения с пределом; пустая правка — отказ; тексты не правятся.
4. **Что проверит проверяющий своими пробами:** `load` с файлом, изменённым на один байт после
   `check`; два `load` разом из двух терминалов; замок `REFERENCE`, взятый своим соединением, и
   `load` рядом; `status` после загрузки и после правки; `UPDATE` строки архивной редакции своим
   соединением — отказ (Ч2.1). Матрица прав и заголовки — не относится: входа из сети нет.
5. **Открытое.**
   - Права Руководителя и Админа, журнал действий, предел частоты — Ч2.3.
   - Заголовок редакции триггер не держит (Ч2.1): снимок прежней после записи сверяет A317.
   - Стоп-лист ТЗ:44 (LOGIC-10) на собранном отчёте вместе с текстами справочника — Ч5.6.
6. **Опора на опись защит соседа.** У соседа версии порогов без замка и уникальности — два
   сохранения дают одну версию. У нас уникальный номер и одна активная (Ч2.1), сверх них замок,
   знак и `expected` (разбор приёмов соседа, строка «версии»).

## Non-functional
- Тесты — настоящий Postgres 16 тестовой базы копии; гонки — фикстурой `committed` на двух
  соединениях: замок держит соединение теста, ожидание видно в `pg_locks` (`dbtools.lock_waiters`
  — оснастка A19), а не «сном на глаз».
- Вход команды — Ч2.1 (образец `ops.alerts`): `load` и `status` идут тем же входом и той же
  проверкой старта процесса `reference` (роль `audit_app`, имя `DATABASE_URL`), отказ словами
  без значений. Новых имён конфига и процессов нет: разбор `ops.config_check reference` (A189,
  6а-2) не меняется. Время в выводе — UTC с `Z`.
- Отказы правки — словами, с кодом и полем; число предела — из редакции.
- В тестах — только выдуманные строки; в коде — без имён соседей и людей.
- Строки до 100 знаков, кроме строк таблиц.

## Чего защита не ловит
- Знак защищает от смены файла и справочника между `check` и `load`, но не от второго человека,
  который сам сделает `check` и `load`: порядок держит замок, а решение — слово владельца.
- `expected` защищает, только если HTTP передаёт номер редакции, которую видел человек, — Ч2.3.
- Файл с тем же содержимым другими байтами — «уже загружено»: в заголовке остаются sha256 и дата
  прежнего файла, а манифест в git — новый. `status` называет sha256 записанного файла.
- Сбой на фиксации называет только «могла пройти»: точный итог видит `status`.
- Причина `--reason` — текст оператора: что это слово владельца, сверяет ведущая, а не код.
- Правка, разумная по числу, но неверная по смыслу, проходит: смысл держит Руководитель и «было —
  станет» на экране Ч2.4.
- Предел ожидания замка — константа в коде: правка — через ревью.
- Пустой манифест образа держит условие первой загрузки, пока манифест не заполнят. Подтвердил ли
  Head of SEO файл, вписанный в манифест, сверяет ведущая на ревью того коммита: код сверяет
  только файл с манифестом.
- Причина без управляющих знаков (Cc) может нести знаки форматирования (Cf — например, смену
  направления текста): `status` печатает их как есть; новой строки вывода они не дают.
