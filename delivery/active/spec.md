## Problem
- **Справочника в базе нет.** Наборы (Ч2.2), аудит (Ч3.1) и проверки (Часть 5) ссылаются на
  строку справочника: код, способ, норма, ошибка, рекомендация, важность, порог доли, числа.
- **Справочник — материал заказчика:** 58 строк — 34 проверки чек-листа, 17 подпроверок
  методики со своим критерием и 7 новых (ТЗ:384). Тексты в публичный репозиторий не идут:
  нужен путь в базу мимо git — проверяемый и с ясным «чьим словом».
- **Редакция, по которой посчитан аудит, не меняется:** новая запись — новая редакция, прежняя
  неизменна, активна одна. Неизменность держит база, а не привычка кода.
- **Файл проверяется до записи:** формат, пределы, совпадение с манифестом и «было — станет»
  против активной редакции — без записи и без текстов заказчика в выводе. Запись — Ч2.1б.

   Причина: формат — наш договор; колонки таблицы заказчика меняет заказчик, загрузчик их не
   знает.
2. **Манифест в git** — по файлу ведущей: число строк, sha256 и дата снимка (PHASES:300). Новый
   файл — новый манифест одним коммитом через ревью; до файла ведущей хеш пустой.
   Причина: файл видит только инженер; хеш в git — то, что ревью может сверить, и то, по чему
   через год видно, какой файл в бою.
3. **Проверка без записи — эта поставка.** `check` показывает «было — станет», называет правки,
   которые запись отменит, и пропавшие строки и печатает знак записи.
4. **Запись — Ч2.1б:** файл и манифест из образа, под замком; содержимое равно активной редакции
   — «уже загружено»; знак `--expect` — тот же файл и та же активная редакция; правки после
   последней загрузки файла — только с явным флагом; причина — чьё слово. Подменить файл или
   справочник между проверкой и записью нельзя, чужая правка молча не отменяется.
5. **Где.** На бою — одноразовый контейнер сервиса api из того же образа, файл — на стандартный
   ввод (`docker compose run --rm -T api python -m ai_geo_audit.reference check - …`); на диске
   сервера файл не остаётся. На сервер ходит только ведущая, под пальцем владельца.
6. **Чьё слово.** Загрузка в базу боя (Ч2.1б) — изменение живой базы: только по слову владельца
   в чате действующей сессии (конституция). `check` базу не меняет; заход на сервер — по его
   слову, как любой.
7. **Сверка с живым листом.** Перед первой настоящей загрузкой ведущая перечитывает лист
   заказчика через G connect (work) и сравнивает со снимком; расхождение — новый файл и новый
   манифест до загрузки (ответ проверяющего 2026-11-20T10:18Z).

## Безопасность

1. **Что появляется.**
   - Таблицы под данные заказчика — тексты справочника; пороги и важность — настройки агентства.
     Записи в них в этой поставке нет: только миграция и чтение.
   - Команда, которая читает файл от человека и базу. Входов из сети нет, новых секретов нет;
     права на правку — Ч2.3.
2. **От кого защищаемся.**
   - Ошибка оператора: не тот файл, файл с подставным или пустым манифестом, не та база или не
     та роль.
   - Вредный или битый файл: огромный, не UTF-8, `NaN`, булево вместо числа, лишние поля, строки
     без текста, коды из чужих цифр.
   - Утечка материалов заказчика в публичный репозиторий, фикстуры, журналы и тексты отказов.
   - Тихая правка прошлого: редакция, по которой посчитан аудит, поменялась задним числом.
3. **Защиты этой поставки** — каждая краснеет без своей защиты:
   - A305, A306 — строгая схема без лишних полей, все причины за прогон, пределы до разбора
     (З46, З47);
   - A307 — текстов файла нет в выводе, отказах и журнале; трассировки нет; непредвиденный сбой
     — без текста исключения;
   - A308 — сверка с манифестом из образа; чужой или пустой манифест в бою — отказ;
   - A310 — команда в бою не стартует без адреса, с негодной настройкой и с чужой ролью;
     причина без значений;
   - A302 — строки и пороги редакции не меняются ни кодом, ни сырой командой;
   - A303 — фикстура не равна настоящему файлу; коды фикстуры вне кодов справочника;
   - A301 — одна активная редакция и пределы значений — ограничениями базы.
4. **Что проверит проверяющий своими пробами:** `check` с файлом, изменённым на один байт против
   манифеста; `UPDATE` строки архивной редакции через `psql` — отказ; поиск меток текста в выводе

## Non-functional
- Тесты — настоящий Postgres 16 тестовой базы копии; ревизии — подпроцессами `alembic` (L19);
  вход команды — и подпроцессом `python -m` (L123).
- Команда — отказ словами без значений: проверка старта и негодные настройки — тем же путём,
  что у `env.py` и `ops.alerts` (L30). Время в выводе — UTC с `Z`.
- Файл и манифест проверяются до соединения с базой: битый файл базы не касается.
- В тестах и фикстурах — только выдуманные строки; в коде — без имён соседей и людей.
- Строки до 100 знаков, кроме строк таблиц.

## Чего защита не ловит
- Манифест доказывает, что проверен тот самый файл, а не что файл собран верно: ошибку переноса
  из таблицы заказчика держат «было — станет» и сверка ведущей с листом; приёмка заказчика —
  Часть 13.
- Пределы порога — таблица единиц в коде: у всех порогов одной единицы пределы одни; порогу,
  которому нужен свой предел, — правка таблицы через ревью. Сверку порогов с правилами делает
  Ч5.1.
- Заголовок редакции триггер не держит: сырой `UPDATE` причины, sha256, номера, основы или
  даты снимка пройдёт. Кода с такой записью нет; снимок прежней редакции после записи сверяет
  Ч2.1б.
- Триггер держит `UPDATE` и `DELETE`; вставку новой строки в старую редакцию сырой командой он
  не держит — кода с такой записью нет. `TRUNCATE` строчные триггеры не ловят: им чистит
  таблицы сервиса фикстура `committed` (`tests/dbtools.py`, `truncate`); у роли сервиса права
  `TRUNCATE` нет (`deploy/db/roles.sql`, «Учётки-1»), а `UPDATE` и `DELETE` есть — правами по
  умолчанию на все таблицы, поэтому строки держит триггер.
- Роль миграций может снять триггер — её держит ревью ревизий; роль сервиса не владеет
  таблицами и снять его не может.
- Тексты справочника на стоп-лист при проверке не сверяются: стоп-лист — на собранном отчёте
  (Ч5.6). Формулы и разметка в текстах лежат как есть — защита при выгрузке и показе.
- sha256 в публичном репозитории о содержимом не говорит, но подтвердит догадку тому, у кого
  файл уже есть.
- Непредвиденный сбой `check` называет только тип: подробностей в выводе нет — их даёт повтор
  под отладкой на стенде.
