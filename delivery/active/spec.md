## Problem
- Фронт ни разу не говорил с сервером. Нужен **клиент API**: он различает пароль прокси, «входа
  нет», отказ сервиса, страницу вместо ответа, перенаправление, обрыв связи, молчание сервера и
  отмену — и говорит человеку словами, что делать.
- На экране этого не видно: нужна **проверка связи на заглушке** — «сервер отвечает» или почему
  нет, с кнопкой «Спросить ещё раз».
- В разработке `/api` никуда не ведёт: нужен **сервер разработки** на своих портах, который не
  переезжает молча на чужой порт и не открыт в сеть.
- В dev-зависимостях 11 умеренных находок `npm audit`, В1б держит их снимком: 7 — цепочка
  `typescript-eslint` → `minimatch` (GHSA-g3hv-75wg-m249), исправленный выпуск допустим по правилу
  14 суток с 2026-11-30T21:52Z; 4 — цепочка Stryker → `typed-rest-client` 2.3.1 → `qs` 6.15.1:
  Stryker 10.1.1 — последний выпуск, держит `typed-rest-client ~2.3.0`, а тот — `qs` ровно
  6.15.1, и исправленный `qs` (6.16.2 и новее, с 2026-10-27) встаёт только через `overrides`.

## In scope
**Часть 4в — клиент.**
- **Клиент API — `src/api/client.ts`:**
  - чтение `GET`; путь — только наш, от `/api/`: другое отказывает до запроса;
  - не ставит и не трогает `Authorization` — в нём браузер несёт пароль сайта; пропуска не хранит
    и не шлёт (Ч1.10);
  - ответ берёт только с сервера: `cache: 'no-store'`;
  - перенаправлений не исполняет;
  - ждёт ответа не дольше предела: 15 с по умолчанию, вызов может задать свой; предел web — 30 с,
    клиент обрывает раньше;
  - отмену по сигналу вызывающего отличает от обрыва и от предела;
  - разбирает отказ по коду, по признаку в `X-Access-Refusal` и по общей форме
    `{detail, kind, retry}` [договор]; ответ без формы — словами по коду;
  - «ответил не сервис» — когда не сходится хоть один из трёх признаков: тип `application/json`,
    разбор, вид тела.
- **Здоровье — `src/api/health.ts`:** `GET /api/health`, ждёт тело образца `health-ok` [договор].
- **Слой `src/api/` в правилах слоёв В1б:** клиент не знает страниц и темы.

**Часть 4д — связь и сервер разработки.**
- **Кэш запросов — `@tanstack/react-query`:** клиент кэша один на жизнь приложения, в общем
  провайдере; сам не повторяет — ни на сбой, ни на возврат во вкладку, ни на появление сети;
  запрос уходит, даже если браузер считает, что сети нет; изменяющие запросы — те же правила.
- **Итог проверки связи — данными:** ответ сервиса или причина, почему его нет. Прежний итог
  остаётся на экране, пока едет новый.
- **Заглушка — блок «Связь с сервером»:** состояние словами в области `role="status"`; тексты
  сбоев — тексты клиента как есть, текст сервера — только текстом; кнопка «Спросить ещё раз» в
  загрузке, пока ответа нет, двойное нажатие — один запрос. Кнопка — обычная, темы Ч1.4б:
  поведение кнопок — 4г.
- **Сервер разработки — `vite.config.ts`:** фронт на 5177, API на 8107, номера из `FRONT_PORT` и
  `API_PORT`; `/api` проксируется без переписывания пути; недоступный API — 502 телом образца
  `proxy-bad-gateway`, как web в бою; `strictPort` у разработки и у `vite preview`; слушает только
  свою машину.
- **Правила интерфейса — `frontend/UI_RULES.md`:** раздел «Отказы на экране» и строка «текст,
  который меняется без перехода, объявляется».
- **README** — как поднять фронт с API в разработке: две строки.

**Долг строки 8 списка полосы.** `typescript-eslint` — до выпуска с исправленным `minimatch`, не
моложе 14 суток вместе с ним (8.73.0 от 2026-11-16T17:07Z и `minimatch` 11.0.9 от

## Acceptance (observable)
- [ ] Каждый вид отказа и сбоя — словами: без имени класса, кода исключения и «Failed to fetch».
      401 — всегда пароль сервера; «входа нет» — по признаку, а не по тексту.
- [ ] Клиент ходит только на наш `/api/`, не исполняет перенаправлений, не трогает
      `Authorization` и не шлёт пропуска; ответа из кэша браузера не берёт, ждёт не дольше
      предела и отличает отмену от обрыва.
- [ ] Фронт идёт по всем образцам файла договора; незнакомый образец — красный.
- [ ] Проверка связи — на экране словами в области `role="status"`: на сбой — один запрос, его не
      повторяют ни возврат во вкладку, ни появление сети; двойное нажатие — один запрос; без
      сети запрос не встаёт на паузу; прежний ответ на экране, пока едет новый.
- [ ] Сервер разработки — на 5177, `/api` уходит к API на 8107; недоступный API — ответ web;
      занятый порт — отказ старта с номером; слушает только свою машину.
- [ ] `npm audit` по lock фронта — записей цепочки `typescript-eslint` и `minimatch` нет; снимок
      JS-аудита — 4 (цепочка Stryker с причиной) или 0 с `overrides` по слову владельца (F51).

## Безопасность
1. **Что появляется.**
   - Первые запросы фронта к нашему `/api/` — `GET /api/health` — и прокси `/api` у сервера
     разработки на 5177. Экран шлёт их только через клиент.
   - Данных заказчика, секретов и пропуска нет. Пароль сайта несёт в `Authorization` сам браузер:
     клиент его не видит и не трогает.
   - Два новых пакета: `@tanstack/react-query` — в сборку, `@testing-library/user-event` — в тесты;
     версии точные, не моложе 14 суток. Кандидаты по реестру на 2026-11-27:
     `@tanstack/react-query` 5.107.1 от 2026-11-06T23:04Z с единственной зависимостью
     `@tanstack/query-core` 5.107.1 от 2026-11-06T23:03Z, пиры — React 18 или 19 (у нас 19.3.0);
     `@testing-library/user-event` 14.6.10 от 2026-11-12T04:41Z, зависимостей нет, пир
     `@testing-library/dom` от 7.21.4 (у нас 10.4.2). Скриптов установки нет. Новее: 5.107.2 —
     допустима с 2026-12-01T10:34Z, 14.6.11 — с 2026-11-30T00:48Z; на день кода — свежайшая
     допустимая, с той же сверкой.
2. **От кого защищаемся.**
   - Запрос мимо нашего API: путь, собранный из данных, или перенаправление на чужой узел увели бы
     туда наши заголовки — в Ч1.10 среди них будет пропуск.
   - Ложное «сервер отвечает»: ответ из кэша браузера; страница вместо ответа сервиса.
   - Подробности на экране: «Failed to fetch», имена классов, страница прокси с именем сервера.
   - Смешение двух замков: 401 стирает у браузера пароль сайта — поэтому 401 всегда пароль прокси,
     «входа нет» — 403 с признаком, а клиент `Authorization` не касается.
   - Чужой текст как разметка: текст отказа сервера выводится только как текст.
   - Действие без человека: изменяющий запрос, ушедший сам с появлением сети.
   - Посторонний в той же сети: сервер разработки, открытый наружу, отдаёт код и проксирует к API.
   - Подменённый, свежий или уязвимый пакет.

   - F21 — только наш путь `/api/`; `Authorization` и пропуск клиент не трогает; ответ не из кэша;
   - F48 — перенаправления не исполняются;
