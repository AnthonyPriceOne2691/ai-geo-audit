# Spec: база и миграции (Ч1.2)

## Problem
Кода работы с базой нет. Следующим поставкам нужны четыре вещи:
- один движок на процесс и сессия с явной фиксацией;
- соглашение об именах ограничений, заданное до первой таблицы;
- миграции, которые проходят с нуля, назад и снова вверх;
- тестовая база на настоящем Postgres, где гонку воспроизводят два независимых соединения.

Плюс три замечания проверяющего к Ч1.1 о паролях в адресах.

## Users / stakeholders
- Исполнитель следующих поставок: заводит таблицы моделью и ревизией по одному образцу, пишет
  тесты гонок на двух соединениях.
- Тот, кто выкатывает: `migrate` применяет ревизии с нуля и повторно без вреда; два запуска
  разом не ломают базу; сбой ревизии оставляет базу на прежней.
- Тот, кто разбирает сбой: видит процесс по имени в `pg_stat_activity`; паролей в журнале нет.

## In scope
- `storage`: ленивый движок на процесс, сессия «фиксация на выходе, откат при ошибке», шаг
  стадии на точке сохранения; размеры пула и имя приложения — из конфига.
- Модели: `MetaData` с соглашением об именах, общая база моделей, перечисление хранится
  значением.
- Миграции: `alembic.ini`, `env.py` (наш журнал, сверка типов и умолчаний, замок на время
  миграций), шаблон ревизии, ревизия `0001` без таблиц.
- Тестовая база: своя у рабочей копии, снос схемы только в базе с префиксом `audit_test_`,
  миграции с нуля той же командой, что в бою, движок без пула. Без Postgres прогон
  останавливается один раз и называет команду, которой его поднять.
- Postgres для разработки и тестов: `docker-compose.dev.yml` с одним сервисом на
  `127.0.0.1:5462`. Порты 5432 и 5442 на этой машине заняты или бывают заняты соседями.
- Три правки Ч1.1: пароль в `REDIS_URL` скрыт в журнале; пароль базы скрыт и в процентной
  записи; в боевом режиме пароль базы короче 12 знаков — отказ старта.

## Out of scope
- Таблицы продукта: люди и журнал действий — Ч1.7, ключи сервисов — Ч1.12, аудиты — Часть 3.
- Эндпоинт здоровья с ревизией миграции — Ч1.3.
- Сервис `migrate` в компоузе выката, образы — Ч1.5; выкат — Ч1.6. Тревоги — Ч1.14.

## Acceptance (observable)
- [ ] Записанное видно другому соединению только после фиксации; сбой шага откатывает шаг, а не
      стадию.
- [ ] Ограничения в базе называются по соглашению; дубль ключа опознаётся по имени ограничения.
- [ ] Миграции проходят с нуля, повторно, назад и снова вверх; сбой ревизии и два запуска разом
      базу не портят.
- [ ] Тесты не трогают никакой базы, кроме своей тестовой; без Postgres прогон честно
      останавливается.
- [ ] Пароли адресов базы и Redis в журнал не попадают.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| A1 | `session_scope()`: внутри вставлена строка, выход без ошибки | строка видна из второго независимого соединения |
| A1 | то же, но внутри исключение | строки нет ни в одном соединении; исключение дошло до вызывающего |
| A1 | строка вставлена и отправлена в базу (`flush`), фиксации ещё нет | второе соединение её не видит; после фиксации — видит (запись без фиксации — не сохранение) |
| A1 | процесс `api` взял движок дважды | один и тот же объект; в `pg_stat_activity` соединение подписано `ai-geo-audit:api` |
| A2 | стадия из трёх шагов в одной сессии; шаг 2 падает внутри `step()` | после фиксации есть строки шагов 1 и 3, строки шага 2 нет; ошибка шага 2 дошла до вызывающего, стадия не откатилась |
| A3 | модель `probe`: уникальное поле `key`, индекс, внешний ключ на `owner`, проверка `positive` | в базе `pk_probe`, `uq_probe_key`, `ix_probe_…`, `fk_probe_owner_id_owner`, `ck_probe_positive` |
| A3 | вторая строка с тем же `key` из другого соединения | ошибка уникальности с именем ограничения `uq_probe_key`: дубль отличим от прочих ошибок по имени |
| A4 | перечисление `Status.DONE = "done"` в колонке модели | в базе тип хранит значения (`done`), а не имена (`DONE`) — сверка по `enum_range` |
| A5 | два независимых соединения вставляют один ключ разом: встреча перед вставкой, обе фиксации настоящие | ровно одна строка; одно соединение успело, второе получило ошибку `uq_probe_key`; тест краснеет, если ограничение убрать |
| A6 | пустая база → `alembic upgrade head` | `alembic_version` = `0001`; голова ревизий одна |
| A6 | `alembic upgrade head` второй раз | изменений нет, код выхода 0 |
| A6 | `alembic downgrade base`, затем `upgrade head` | после отката в схеме нет ни наших таблиц, ни типов-перечислений (`pg_type`); подъём снова проходит |
| A6 | после `upgrade head` модели сверены с базой | расхождений нет; модель с лишней колонкой даёт расхождение — проверка умеет краснеть |
| A6 | ревизия падает посередине: таблица уже создана, потом ошибка | `upgrade` завершился с кодом ≠ 0 и именем ревизии в журнале; таблицы нет; `alembic_version` — прежняя ревизия |
| A6 | два `upgrade head` разом на пустой базе | оба с кодом 0; в `alembic_version` одна строка `0001` |
| A7 | Postgres по `TEST_DATABASE_URL` не отвечает | pytest останавливается в начале одним сообщением с командой `docker compose -f docker-compose.dev.yml up -d db`, а не десятками пропусков |
| A7 | две рабочие копии | базы `audit_test_<10 знаков sha256 пути корня>` у них разные |
| A7 | обвязка получила базу `audit` (без префикса `audit_test_`) | снос схемы отказывает, база цела |
| A7 | `DATABASE_URL` указывает на базу разработки | тесты её не читают и не меняют: адрес тестов — только `TEST_DATABASE_URL` |
| A8 | `REDIS_URL=redis://:r3dis-pass-123456@redis:6379/0`, оба формата журнала | пароля Redis в выводе нет |
| A8 | `DATABASE_URL` с паролем `p%40ss-word-123456` | в выводе нет ни `p%40ss-word-123456`, ни `p@ss-word-123456` |
| A8 | `APP_ENV=prod`, пароль базы `short-pw11` (10 знаков) | `api`, `worker` и `migrate` не стартуют: у `DATABASE_URL` причина «пароль базы короче 12 знаков» |

## Прогоны: семь вопросов

Шагов прогона в поставке нет. Миграции — ближайший к ним путь, поэтому вопросы разобраны на них.

| Вопрос | Ответ |
|---|---|
| 1. Повтор шага | `upgrade head` второй раз ничего не меняет — A6 |
| 2. Сбой и число попыток | ревизия с ошибкой не повторяется сама: код выхода ≠ 0 и имя ревизии в журнале, база на прежней ревизии — A6; повтор — решение выката (Ч1.6) |
| 3. Потолок | не относится: платных вызовов и расхода в поставке нет |
| 4. Обрыв посреди шага | ревизия падает посередине — база на прежней ревизии, ничего наполовину — A6 |
| 5. Кто ещё меняет те же данные | два `upgrade head` разом — A6; два прогона тестов из разных рабочих копий — разные базы, A7 |
| 6. Двойное нажатие или запрос | не относится: действий человека нет; двойной запуск `migrate` — вопрос 5 |
| 7. Тревога | не относится до Ч1.14: отказ миграции громкий — код выхода и строка журнала; тревогу о нём даст выкат (Ч1.6) через канал Ч1.14 |

## Non-functional
- Тесты не читают `.env`, `DATABASE_URL` и переменные разработчика, не ходят в сеть дальше
  тестового Postgres.
- Полный прогон тестов — один на рабочую копию за раз.
- Строки до 100 знаков, форма — как у форматтера ruff (он придёт с волной В1).
