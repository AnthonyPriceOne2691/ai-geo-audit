## Problem
- **Команды `up` нет.** Нечем поставить на сервер ровно проверенные образы: по полному SHA, по
  дайджестам из итога публикации и при дереве на этом SHA — с отказом до первого изменения.
- **Плавающая метка и чужой реестр.** Соседние сессии сливают параллельно: метка без дайджеста
  увезла бы чужое (общий план, «Канал выката»); путь образов, заданный руками, — лишняя опечатка
  и дверь к подмене реестра.
- **Негодный образ узнаётся поздно.** Без правил `--prod` в скачанном образе и без разового
  старта migrate и api с новым образом и файлом сервера отказ пришёл бы после копии и записи
  образов в файл сервера.
- **Строка «сверить» `check` неточна** на тег, якорь и список портов в несколько строк: текст
  подписан в A185, причины названы только в памятке (decisions 6а-3, 2026-11-27T12:17Z).

## In scope
- **`up <SHA> --backend-digest <D> --web-digest <D>`, вход.** SHA — 40 знаков hex, оба дайджеста
  обязательны; `HEAD == SHA` и чистое дерево — иначе отказ с командой `git checkout --detach
  <SHA>` или с именами изменённых файлов. Дерево скрипт не переключает. Всё это — до первой
  команды докера (A187, строки 1–2).
- **Путь образов — из адреса `origin` копии.** Только `https://github.com/<владелец>/<имя>`,
  владелец строчными, как в джобе публикации; иначе отказ — что не так, без самого адреса. Путь
  не подставляется ни из другого реестра, ни по умолчанию (A187, строка 3).
- **Порядок A187 до копии.** `deploy.py check` (A185, A189) → снимок соседа → backend и web по
  метке SHA со сверкой дайджестов → db и redis по дайджесту, только если их нет → правила
  `--prod` внутри скачанного образа → разовый старт migrate и api с новым образом и файлом
  сервера. Отказ любого шага — до копии и до записи образов в файл сервера, стек не тронут; в
  выводе — команда вернуть дерево на прежний SHA (A187, строки 4–5).
- **Где кончается `up` 6в-1.** После разового старта — строка «вход и образы сверены; подъёма в
  этой версии нет — 6в-2»; стек, файл сервера и копии не тронуты.
- **Строка «сверить» `check`** — текст по слову владельца (раздел «Решает владелец», п. 2).
- **Живой прогон** в джобе `stack` на запросе на слияние — отказы `up` на машине раннера с
  настоящими `git` и `docker`: ничего не тронуто. На main шага нет — там A187 держат тесты.

| 1. Повтор шага | `up` того же SHA повторяет сверку: реестр спрашивается снова, слои второй раз не качаются; стек и файл сервера не тронуты |
| 2. Сбой и число попыток | своих повторов нет. Реестр или Docker Hub не ответили — отказ до изменений (A187); повтор — человеком, после паузы. У каждой команды — предел времени |

| 4. Обрыв посреди шага | ход — сначала в `.deploy/`, дочерние процессы — в своей сессии, обрыв связи шаг не роняет (ядро 6а-1). Скачанный наполовину образ докер не показывает; повтор той же команды доводит |

## Безопасность
1. **Что появляется.** Команда `up` скачивает образы публичного реестра на общую машину; стек и
   файл сервера в 6в-1 не меняются.
2. **От кого защищаемся.**
   - Ошибка оператора: не тот SHA, короткий SHA, плавающая метка, дерево не на SHA, правка руками.
   - Подмена образа в реестре между публикацией и скачиванием — дайджест из итога джобы
     обязателен (A187).
   - Подмена реестра — путь образов только из адреса `origin` вида
     `https://github.com/<владелец>/<имя>`; учётные данные в адресе — отказ, без печати адреса.
   - Утечка: в выводе и журнале нет адреса `origin`, значений файла сервера и секретов (A183).
   - Вред соседу: `up` начинает с `deploy.py check` и снимка соседа, чужого не трогает (A185,
     A186).
   - Не защищаемся: от root машины; от подмены образа до публикации — её держат правила В1.
3. **Защиты этой поставки.** Каждая краснеет без своей защиты: A187, строки 1–5 — вход, дерево,
   адрес `origin`, ответ реестра, правила `--prod` и разовый старт до любого изменения.
4. **Что проверит ведущая своими пробами.** Вывод отказов живого прогона — строка за строкой с
   примерами; что после отказа файл сервера и стек — как до.
5. **Открытое.** Копия, подъём и сверка — 6в-2 и 6в-3; канарейка — 6в-4.
6. **Опора на опись защит соседа.** З82: образы собирает CI, сервер не собирает; у соседа сервер
   тянет метку `main`, у нас — только дайджест.

## Non-functional
- Скрипт — тот же `deploy/deploy.py`: одна команда `up`, только стандартная библиотека,
  `python3 -I`; тесты — подставным исполнителем без Docker и без сети.
- У каждой внешней команды — предел времени; скачивание образа — свой предел.
- Строки до 100 знаков, кроме строк таблиц и блоков команд.
- **Чего защита не ловит.** Реестр может ответить на метку иначе между публикацией и `up` — тогда
  `up` отказывает, а не выкатывает: подмену ловит дайджест, но раньше о ней не говорит.
