## Problem
Таблиц продукта ещё нет. Их первая поставка (Часть 3) должна получить готовыми:
- имена ограничений, известные заранее: по ним вызывающий отличает «ключ занят» от «нарушена
  проверка», не разбирая текст ошибки;
- типы колонок по умолчанию, на которых не переполняется счётчик и не падает пачка из-за
  длинного адреса, и правила для внешних ключей и перечислений, которые проверка не пропустит;
- alembic с цепочкой ревизий, откатом и сверкой моделей с базой машиной;
- тестовую базу, построенную той же командой, что в бою.

## Users / stakeholders
- Исполнитель Части 3 и дальше: объявляет модели через базу моделей и помощник перечисления,
  ревизию заводит по шаблону; о расхождении скажут проверки.
- Тот, кто выкатывает (Ч1.5–Ч1.6): `alembic upgrade head` — одна команда; сбой ревизии
  оставляет базу на прежней.
- Тот, кто разбирает сбой: имена ограничений стабильны, журнал миграций идёт через журнал
  сервиса.

## In scope
- Зависимость по слову владельца 2026-11-18T12:16:25Z (вопрос о пакетах Ч1.2): alembic.
- `storage/models.py`:

  - карта типов: `int` → `bigint`, `str` → `text`, `datetime` → `timestamp with time zone`.
    Узкий тип — только поимённо, со списком причин. Предел длины проверяется на входе, а не
    шириной колонки;
  - помощник колонки-перечисления: только `StrEnum`, в базе — значения, строка фиксированной
    длины и проверка `ck_…`, типов ENUM нет;
  - сверка значений проверок в базе с перечислениями;
  - проверка правил моделей: узкие типы и плавающая точка — только поимённо с причиной,
    явный `ondelete`, имена ограничений и индексов не длиннее 63 знаков.
- `backend/alembic.ini`, `backend/migrations/env.py`: асинхронный движок сервиса, журнал сервиса
  без `fileConfig`.
- Шаблон ревизии, ревизия `0001` — начало цепочки, таблиц в ней нет.

  - пробные таблицы Ч1.2а — моделями пробы;

- `README.md`: как завести ревизию. Номер — следующий по порядку; кто сливает вторым, тот

## Acceptance (observable)
- [ ] Имя ограничения известно заранее и стабильно; ошибку различают по имени из ответа базы.
- [ ] Целые, строки и время по умолчанию — `bigint`, `text`, `timestamptz`. Узкий тип или
      плавающая точка без причины, внешний ключ без явного `ondelete` и имя длиннее 63 знаков
      проверка моделей не пропускает.
- [ ] Перечисление хранит значения; значение, добавленное без ревизии, ловит сверка, а не первая
      вставка в бою.
- [ ] `upgrade head` с нуля и повторно: цепочка одна и без повторов номеров, модели совпадают с
      базой вместе с индексами. Откат работает; сбой ревизии оставляет базу на прежней.
- [ ] Тестовая база строится той же командой, что в бою; миграции не глушат журнал приложения.

## Прогоны: семь вопросов

Шаг прогона здесь — миграция базы.

| Вопрос | Ответ |
|---|---|
| 1. Повтор шага | `upgrade head` второй раз ничего не меняет — A17 |
| 2. Сбой и число попыток | ревизия с ошибкой сама не повторяется: код выхода ≠ 0 и имя ревизии в журнале, база на прежней — A18; повтор — решение выката (Ч1.6) |
| 3. Потолок | не относится: платных вызовов нет |
| 4. Обрыв посреди шага | ревизия падает посередине — база на прежней ревизии — A18 |
| 5. Кто ещё меняет те же данные | два одновременных `migrate` развести некому до замка миграций — Ч1.2в (A19); до него миграции идут только в тестах, каждая по своей базе (A12, A18), а сервиса `migrate` нет до Ч1.5 |
| 6. Двойное нажатие или запрос | не относится: действий человека нет; двойной запуск `migrate` — вопрос 5 |
| 7. Тревога | не относится до Ч1.14: отказ миграции громкий — код выхода и строка журнала; тревогу даст выкат (Ч1.6) |

## Non-functional
- Тесты не читают `.env`, `DATABASE_URL` и переменные разработчика; подпроцесс alembic
  получает адрес своей тестовой базы явно.
- У каждого подпроцесса в тестах свой предел времени: зависший прогон называется командой, а
  не висит.
- В отчёте проверки — число собранных, прошедших и пропущенных тестов; пропущенных 0.
- Ревизии в тестах идут подпроцессом той же командой, что в бою. Цена: покрытие файлов ревизий
  не видно — решение волны В1 (в её черновике).
- Строки до 100 знаков, форма — как у форматтера ruff (он придёт с волной В1).
