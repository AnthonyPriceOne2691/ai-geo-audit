  Старше 14 суток и старше отсечки `exclude-newer` (2026-11-05T12:00Z) — поимённого исключения
  не нужно. Слово владельца — 2026-11-24T13:20:59Z (STATUS, строки `new_dependency`). Цена — в
  замке косвенные другие, чем в слове, — стоп и снова слово владельца.
- 2026-11-24 · выбрал в `pyproject.toml` пин `cryptography==50.0.2` вместо диапазона, как у
  `fastapi` и `uvicorn`, потому что слово владельца — на версию: обновление замка не сдвинет её

- 2026-11-24 · выбрал ключи Fernet, номера мастер-ключа и отпечатка, выведенные из строки файла
  HMAC-SHA256 — у каждого назначения своя метка, — вместо 32 байт строки ключом Fernet напрямую,
  потому что из одной строки выводятся три вещи: один материал не служит двум алгоритмам, а
  номер мастер-ключа в открытой колонке ничего не говорит о ключе шифра (вывод). Цена — ключ
  Fernet руками из файла не взять, только кодом `settings/crypto.py`; формат файла A220 тот же.
- 2026-11-24 · выбрал для шифротекста не из ASCII тот же отказ «не расшифровывается», что для
  испорченного, вместо исключения пакета наружу, потому что по пробе ниже текст не из ASCII даёт
  `ValueError`, а не `InvalidToken`. Колонка `text` такое примет — подмена в базе (Безопасность,
  п. 2). Цена — нет.
- 2026-11-24 · выбрал токен без срока жизни вместо `ttl` в `decrypt`, потому что ключ живёт,
  пока его не сменили, а срок проверяется только с `ttl` (проба ниже). Цена — нет: время записи —
  колонка `set_at`.
- 2026-11-24 · выбрал формат файла мастер-ключа — строки по 64 знака hex, первая — текущая, —
  вместо ключа Fernet в base64, потому что так ответил проверяющий 2026-11-20T10:44Z: формат один
  для разбора A220 и для `env-init` 6а-2, ему формат передаёт проверяющий. Цена — разбор строк и
  вывод ключей — свой код в `settings/crypto.py`.

Пробы на стенде (L8), 2026-11-24, до 13:28Z по `date -u`: `cryptography` 50.0.2, `cffi` 2.1.1,
`pycparser` 3.12 во временном окружении `uv run --no-project --with …`; в проект ничего не
ставилось. Два шифра одного значения разные; метки нет ни в тексте токена, ни в байтах после
base64. `MultiFernet` расшифровывает прежней строкой и шифрует первой; одна вторая строка новую
запись не читает — `InvalidToken`. Токен со временем 0 без `ttl` расшифровывается, с `ttl=60` —
`InvalidToken`: срок проверяется только с `ttl`. Чужой мастер-ключ и изменённый знак токена —
`InvalidToken` без текста, без `__cause__` и `__context__`; строка не из base64 — `InvalidToken`
с `__context__` `binascii.Error`; текст не из ASCII — `ValueError` «string argument should
contain only ASCII characters».

Освежено на main `aefde68` и `8adca75`: ревизия — `0002_settings`; `schema.py` и правки
`tests/dbtools.py` заводит эта поставка; `.importlinter` В1а есть; `env-init` 6а-2 нет.

Срез 1 — мастер-ключ и шифр.

- 2026-11-24 · выбрал разбор файла мастер-ключа и `MasterKeyError` в `config/master_key.py`
  вместо `settings/crypto.py`, потому что его зовёт и проверка старта в `config`, а контракт слоёв
  `api → settings → storage → logs → config → refusal` (срез 2) не пускает `config` к `settings`;
  `logs.register_secret` слою `config` тоже не дан (L111). Разбор один на A220 и A221 (L53), строки
  в вычистку отдаёт `settings.crypto`. Предложение второй проверяющей и решение ведущей
  2026-11-24. Цена — в `config` модуль, который читает файл, а не окружение.
- 2026-11-24 · выбрал кэш чтения файла в `config.master_key.read` вместо кэша в шифре, потому что
  так файл читается один раз за процесс и проверкой старта, и шифром. Цена — новый файл действует
  только после перезапуска, как и задумано; тесты сбрасывают кэш фикстурой `forget_master_key`.
- 2026-11-24 · выбрал от строки файла срезать только `\r` в конце вместо обрезки пробелов, потому
  что формат A220 называет два послабления — регистр и CRLF, а пробел, табуляция, BOM и нулевой
  знак — порча при копировании: отказ «строка N — знак не из hex» дешевле догадки (решение второй
  проверяющей, п. 3). Знаки судятся раньше длины; «файл пуст» — по ключам, а не по байтам: файл
  из одних переводов строк — тоже пуст. Цена — файл с пробелом в конце не стартует, пока его не
  поправят.
- 2026-11-24 · выбрал для файла без прав и каталога отказ словами «файл не читается: <путь>»
  вместо ошибки ОС, потому что вход `python -m ai_geo_audit.api` ловит только `ConfigError`
  (L123), а текст и цепочка ошибки ОС в отказ уходить не должны (A237). Цена — нет; в проверке
  старта каталог по-прежнему «файла нет», через `is_file()`.
- 2026-11-24 · выбрал строки реестра ключей — имена и слова — в срезе 1 вместо среза 3, потому
  что отказы шифра называют ключ словом: «шифротекст другого ключа: Ahrefs» (A222). Проверка
  значения ключа — в срезе 3. Цена — нет.
- 2026-11-24 · выбрал слова ключей по ТЗ:485–490 — OpenAI, Claude (`anthropic`), Gemini,
  Perplexity, Ahrefs, PageSpeed Insights — вместо названий компаний, потому что так ключи
  называет ТЗ: «ключи Claude, Gemini, Perplexity», «PageSpeed Insights, бесплатный ключ Google».
  Сверено второй проверяющей. Цена — у `anthropic` слово не равно имени.
- 2026-11-24 · выбрал текст отказа «не расшифровывается: OpenAI» вместо голого «не
  расшифровывается» из A222, потому что приёмка требует отказ с именем ключа, а порядок «причина:
  слово» — тот же, что у «шифротекст другого ключа: Ahrefs». Цена — нет.
- 2026-11-24 · выбрал правку оракула — запись мастер-ключа функцией `write_master_key` в формате
  A220 — сейчас, коммитом к срезу 1, вместо среза 5, потому что проверка старта из среза 1
  отвергает прежний ключ `secrets.token_urlsafe(32)` («строка 1 — знак не из hex»): джоба
  `stack` на `b6d642a` красна (CI ведущей 2026-11-24T14:05Z) и до среза 5 прятала бы другие
  поломки стека. Находка 5 второй проверяющей, решение ведущей 14:09Z. Функция — в
  `stack_oracle_compose.py`, рядом с `KEYS_MASTER_KEY_HOST_FILE`: в `stack_oracle.py` она вывела
  бы файл за 500 строк. Цена — нет; живой оракул и порча записи временной веткой — на приёмке
  (L126).
- 2026-11-24 · выбрал оставить в причине отказа подъёма хвосты журналов migrate и web вместо того,
  чтобы добавить журнал api (замечание ведущей «на усмотрение»), потому что так подписан A76
  Ч1.5а и так его держит тест: третий журнал — правка подписанной строки, только словом
  владельца. Цена — причину «api unhealthy» в CI видно по журналу джобы, а не в строке шага.
- 2026-11-24 · выбрал проверку номера мастер-ключа до расшифровки вместо одной `MultiFernet`,
  потому что так отказ называет беду — «зашифрован мастер-ключом с номером N, его нет в файле»
  (A223), — а не общее «не расшифровывается». Расшифровка — `MultiFernet` по всем строкам. Цена —
  нет.

Срез 2 — таблицы, ревизия, оснастка.

- 2026-11-24 · выбрал ревизию `0002_settings` командой `alembic revision --autogenerate` по
  моделям вместо ручной, потому что так ревизия и модели совпадают по построению, а `alembic
  check` это сверяет (A236). Цена — правка текста только оформлением: заголовок и переносы.
- 2026-11-24 · выбрал в проверках `master_id` и `fingerprint` строчные hex (`^[0-9a-f]{8}$`,
  `^[0-9a-f]{12}$`) вместо любого регистра, потому что код пишет их `hexdigest()` строчными, а
  заглавные в колонке — запись мимо кода. Цена — сырая вставка заглавными — отказ.
- 2026-11-24 · выбрал автонумерацию версий `GENERATED BY DEFAULT AS IDENTITY` (`Identity()`)
  вместо `BIGSERIAL`, потому что у identity счётчик принадлежит колонке: права и `TRUNCATE …
  RESTART IDENTITY` идут вместе с таблицей (вывод). Цена — нет; `alembic check` — код 0.
- 2026-11-24 · выбрал перенумеровать ревизии-пробы A18–A20 (`0002` и `0003` → `0003` и `0004`) и
  завести голову `dbtools.HEAD` вместо проб поверх `0001`, потому что настоящая `0002_settings`
  совпала бы с номером пробы, а откат проб на `0001` (`back_to_start`) снёс бы таблицы настроек в
  тестовой базе до конца прогона. Цена — новая ревизия сервиса правит `HEAD` и номера проб (так и
  сказано в `dbtools`).
- 2026-11-24 · выбрал в `schema.py` импорт модуля моделей настроек ради его таблиц вместо списка
  таблиц словами, потому что таблицы ложатся в общий `models.Base.metadata` при импорте модуля —
  так и в спеке Ч1.7в; `schema.metadata` — тот же объект. Цена — `noqa: F401` с причиной; в
  правиле A229 (срез 5) это поимённое исключение.
- 2026-11-24 · выбрал в `dbtools` чистку и проверку пустоты по таблицам `schema.metadata` вместо
  списка имён, потому что новая таблица из `schema.py` попадает в чистку сама — как в плане Ч2.1.
  Цена — перед каждым тестом с фиксациями счёт строк каждой таблицы сервиса.
- 2026-11-24 · выбрал пробы сверки A17 поверх таблиц сервиса (`with_service_tables`) вместо пустых
  метаданных, потому что в `public` теперь есть таблицы настроек и «точная» проба видела бы их
  лишними (`remove_table`). Цена — нет.
- 2026-11-24 · выбрал в `smoke_run.py` побочный импорт `ai_geo_audit.schema` вместо
  `schema.metadata`, потому что тест копии A370 подменяет `smoke_run.models` и должен остаться
  прежним. Цена — нет; S3 судит таблицы настроек, это держит отдельный тест.
- 2026-11-24 · выбрал не писать pytest на вызов `write_master_key` в `run_oracle` вместо теста с
  подставными шагами (вариант (а) проверяющей), потому что вызов держит джоба `stack` в CI — без
  него api в бою не стартует — и живая порча вызова временной веткой на приёмке (L126). Решение
  ведущей, вариант (б). Цена — порча O6 в pytest живёт.

Срез 3 — ключи.

- 2026-11-24 · выбрал порядок причин отказа ключа — пусто, края, пробел внутри, видимые знаки,
  длина — вместо порядка строки A225, потому что пробел и переводы строки сами не видимые знаки:
  при проверке видимых раньше пробел внутри получил бы чужую причину. Цена — значение с двумя
  бедами получает первую по этому порядку.
- 2026-11-24 · выбрал `\r` переводом строки — отказы «внутри» и «по краям» — и `\x0b`, `\x0c`
  управляющими знаками — отказ «только видимые знаки ASCII» — вместо всех шести пробельных
  знаков ASCII в одном наборе, потому что A225 называет пробел, табуляцию и перевод строки, а `\r`
  — перевод строки, как в CRLF (A220); вертикальная табуляция и перевод страницы — управляющие,
  как нулевой и `ESC` в слове владельца 13:41:39Z. Находка 8 второй проверяющей. Цена — нет.
- 2026-11-24 · выбрал текст отказа ключа «слово — причина» («OpenAI — пусто») вместо другой
  формы, потому что так же говорят отказы настроек A233 и A238 («Аудитов одновременно — …»); у
  имени не из реестра — само имя: «nope — такого ключа нет». Цена — нет.
- 2026-11-24 · выбрал итог `put_key` «задан» и для новой строки, и для замены вместо трёх итогов,
  потому что A226 различает только «без изменений», а экрану Ч1.13 хватит «задан». Цена — нет.
- 2026-11-24 · выбрал `resolve` и `states` выборкой колонок вместо сущности `ServiceKey`, потому
  что карта сущностей сессии отдала бы прежнюю строку без запроса (п. 5 проверяющей). Карта
  ссылается слабо, поэтому A227 держит строку в читающей сессии сам: без этого порча «через
  `session.get`» жила (своя порча, срез 3). Цена — нет.
- 2026-11-24 · выбрал для записи `key-unreadable` `log.exception` вместо `log.error`, потому что так
  велит правило ruff TRY400 внутри `except`; трассировка значения не несёт: отказ шифра поднят вне
  `except`, цепочки нет (A237). Цена — запись длиннее на трассировку.
- 2026-11-24 · выбрал «расшифровывается ли» в `states` настоящей расшифровкой со сверкой имени
  вместо номера мастер-ключа в файле, потому что переставленные строки по номеру сошли бы за
  годные, а `resolve` им откажет (п. 9 проверяющей). Цена — расшифровка шести ключей на вызов.
- 2026-11-24 · выбрал строку `SettingVersion` в `scripts/lint/dead-code-allowed.json` вместо ссылки
  по имени в `schema.py`, потому что подписанная A229 велит `schema.py` импортировать модуль
  моделей без имён, а CI на `afc84b7` красен по мёртвому коду (прогон 45412742982, сообщение
  ведущей): модели зовут alembic и сверки через `schema.metadata`. `ServiceKey` по имени зовёт
  срез 3, `SettingVersion` — срез 4; там гейт назовёт строку устаревшей, и срез 4 её снимает. Цена
  — до среза 4 класс жив только строкой с причиной. Свой пропуск: хуки pre-push после среза 2 я
  не гоняла.
