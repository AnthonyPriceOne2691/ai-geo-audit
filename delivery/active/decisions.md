  число для `INCRBY` отброшенных известно только до `EXEC`: без `WATCH` гонка двух постановок

  счётчик 1, отброшена самая старая. Повтор после `WatchError` — не повтор сбоя: записи не было;
  повторы — в пределах срока 2 с.
- 2026-11-25 · выбрал внутри синхронного `queue_alert` асинхронный клиент `redis.asyncio` под
  `asyncio.timeout(2)` в своём `asyncio.run` вместо синхронного `redis.Redis` со сроком чтения

**Протокол.** У `redis` 8.1.0 протокол по умолчанию — RESP3: рукопожатие — `HELLO 3 AUTH`. Без
пароля Redis с паролем отвечает `AuthenticationError` уже на `HELLO`; сервер теста, что на любую
команду отвечает `OOM` или `NOAUTH`, роняет рукопожатие тем же классом за 0,00 с — сценарии A240
на нём идут.

**Служба CI.** Страница GitHub о службах джобы перечитана 2026-11-25 своим веб-инструментом без
токена, даты на странице нет: `command` — «Overrides the Docker image's default command (`CMD`)»,
значение идёт аргументами после имени образа в `docker create`; у `options` служб не поддержан
только `--network`; `env` задаёт переменные окружения контейнера службы. Пароль — в `command`,
`REDISCLI_AUTH` — в `env` службы. На образе стека `redis-cli -e ping` с `REDISCLI_AUTH` — `PONG`,
код 0; без пароля — `NOAUTH`, код 1, а без `-e` — код 0 (L60).

**Находка — чинится здесь.** Под `noeviction` полный Redis на `PING` отвечает `PONG`: здоровье —
200, а постановка — `OutOfMemoryError` и строка ERROR. Слово владельца 2026-11-25T12:39:26Z —
«правьте такое сразу»: здоровье пробует Redis записью своего ключа со сроком, а не `PING`. Проба
12:45:57Z на образе стека (Redis 7.4.12, `noeviction`, `maxmemory` ниже занятого): `PING` —
`PONG`; `SET ai-geo-audit:health:probe 1 PX 60000` — `OutOfMemoryError` и при существующем ключе, и
при новом, ключ не создан; после снятия предела — `OK`. `INFO memory` не берём: Redis решает `OOM`
по своей оценке памяти, а запись проверяет то же, что делает постановка. Правка спеки и плана —
текстом исполнителя, внесла ведущая (`807a110`); мера +~83, итого ~1 177.
