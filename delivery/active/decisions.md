# Decisions

- 2026-11-19 · выбрал сборку `vite build` и проверку типов отдельным шагом `tsc --noEmit` вместо
  `tsc -b && vite build`, как у соседа, потому что `tsc -b` пишет `tsconfig.tsbuildinfo` в
  дерево; цена — сборка сама типов не проверяет: это держит шаг 3 из 6 цепочки
  `npm run check`, и тест F3 краснеет, если шаг выпал.
- 2026-11-19 · выбрал предел воркеров тестов `maxWorkers: 2` в `vite.config.ts` вместо предела в
  брифе агенту, как у соседа, потому что бриф не держит `npm test` в соседней сессии; цена —
  тесты на машине идут не больше чем в 2 воркера, CI поднимает предел флагом.
- 2026-11-19 · выбрал точные версии в `package.json` вместо `^` и `~`, потому что с ними сборка
  зависит от дня установки; цена — каждое обновление пакета — правка `package.json` и lock
  руками, 23 прямые зависимости.
- 2026-11-19 · выбрал список одобренных пакетов файлом `frontend/approved-packages.json` вместо
  строк `new_dependency` в STATUS, потому что STATUS на handoff уезжает в архив, и тест F17
  после переноса читал бы пустоту; цена — новый пакет пишется одной правкой в два места,
  список — около 25 строк.
- 2026-11-19 · выбрал проверку адресов узлов в JS сборки по поимённому списку с причиной вместо
  проверки только HTML и CSS (решение проверяющего 2026-11-19), потому что запрос к чужому узлу
  из скрипта до CSP (Ч1.5) иначе не ловит ничто; цена — пакет, принёсший новый адрес, краснит
  оракул, и узел вносит в список человек с причиной; в списке 3 узла.
- 2026-11-19 · выбрал оракул сборки `scripts/check-dist.mjs` без зависимостей вместо пакета
  разбора HTML и CSS, потому что пакет — новое слово владельца и новая поверхность; цена —
  ссылки ищутся регулярными выражениями, поэтому формы ссылок перечислены в F5 поимённо и у
  каждой проверки — порча в тесте оракула, около 60 строк тестов.
- 2026-11-19 · выбрал `ignore-scripts=true` в `frontend/.npmrc` до первой установки вместо
  скриптов установки по умолчанию, потому что скрипт пакета исполняется на машине до любой
  проверки; цена — пакет, которому скрипт нужен, называется поимённо с причиной: в lock
  соседнего сервиса скрипт установки объявляют 2 пакета, `esbuild` и `fsevents`.
- 2026-11-19 · выбрал шаблоны eslint и prettier канона сразу вместо конфигов соседа, потому что
  механика контура — только из канона (`delivery/CONSTITUTION.md`, принцип 8); цена — 2 новых
  пакета шаблона, `eslint-plugin-react` и `eslint-plugin-import`, по слову владельца
  2026-11-19T08:59Z.
- 2026-11-19 · выбрал снимки двух ширин Chrome без окна на машине вместо браузера в наборе
  тестов (решение проверяющего 2026-11-18), потому что браузер в тестах — новый пакет и минуты
  CI на каждом прогоне; цена — ширины 1440 и 390 тест не видит, их видит проверяющий по
  снимкам, а в verify-report — блок «Исполнение рисковых путей».
- 2026-11-19 · оставил `typescript-eslint` 8.70.0 из одобренного набора вместо исправленной
  8.73.0 (решение проверяющего 2026-11-19), потому что 8.73.0 и её `minimatch` 11.0.9 вышли
  2026-11-16 — свежий выпуск инструмента, который исполняется на машине и в CI, — больший риск,
  чем находка; цена — `npm audit` даёт 7 находок средней тяжести с одной причиной
  (GHSA-g3hv-75wg-m249: отказ в обслуживании через шаблон поиска файлов в `minimatch` внутри
  `typescript-eslint`). Инструмент линтера, в сборку не идёт, шаблоны у него только из нашего
  конфига. Исправление берём, когда ему исполнится две недели, — после 2026-11-30, в В1б или
  отдельной правкой lock.
- 2026-11-19 · выбрал постоянную настройку `min-release-age=14` в `frontend/.npmrc` и пересборку
  lock с ней вместо разового `npm install --before` (решение проверяющего 2026-11-19), потому
  что флаг забудется на первой следующей установке, а настройка — нет; `npm ci` её не трогает:
  там версии из lock. Свежие версии стояли в lock с 09:27Z до пересборки в 09:52Z: 53
  транзитивные версии моложе 14 суток, среди них `rollup` 4.68.7 от 2026-11-18. Их скрипты
  установки не исполнялись — `ignore-scripts=true` уже действовал, а скрипт есть только у
  `esbuild` и `fsevents`, оба в `approved-packages.json`; `esbuild` 0.28.2 вышел 2026-08-08 и в
  эти 53 не входит. Их код исполнялся в линте, тестах и сборке; признаков вреда нет. После
  пересборки: по всем 456 парам lock моложе порога — 0, состав пакетов тот же, 52 пакета стоят
  на версию раньше, прямые зависимости без изменений, `npm audit` — те же 7 находок средней
  тяжести с одной причиной.
  Цена — новая версия любого пакета, в том числе исправление уязвимости, приходит в lock не
  раньше чем через 14 суток после выхода; срочное исправление — только словом проверяющего,
  разовым исключением с причиной.
