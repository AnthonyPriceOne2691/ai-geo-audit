# Decisions

- 2026-11-20 · выбрал ожидания строк A37, A48, A51–A53, A55, A57 по пробам 1–12 плана на пакетах
  ветки (fastapi 0.141.1, starlette 1.7.0, uvicorn 0.54.0, httpx 0.28.1, Python 3.12.13;
  2026-11-20T08:47Z–08:51Z) вместо чтения кода библиотек, потому что поведение меняется от версии
  к версии (L8); цена — пробы гоняются заново при смене пары. Итоги 1–12 совпали с планом и
  строками примеров; строки A37 опровергла отдельная проба — следующий пункт.
  Проба 1 — область `lifespan` идёт насквозь слоя: у `create_app()` с маршрутами-пробами есть
  `lifespan.startup.complete` и `lifespan.shutdown.complete`; lifespan «`yield`, затем
  `dispose_engine()`» на `shutdown` закрывает соединение пула сразу — снимок пуст (A37).
  Проба 2 — наследник `HTTPException` Starlette с кодом 413, поднятый из `receive` при чтении тела
  пробы с телом, доходит до обработчика как есть: ответ 413, а не 400 (A53).
  Проба 3 — `app.routes` держит включённый роутер одним `_IncludedRouter`; `iter_route_contexts`
  раскрывает его и вложенный, путь — с приставкой; `Mount` отдаёт как есть, `methods` — `None`;
  схема, консоли и `/docs/oauth2-redirect` — `Route` в том же списке; у `APIRoute` с телом —
  `body_field`; маршрут вебсокета — `APIWebSocketRoute`, `methods` — `None`: обход по методам
  прошёл бы мимо него молча (A52).
  Проба 4 — живой `python -m ai_geo_audit.api`: заголовки `POST /api/nope` с `Content-Length:
  5000000` без тела — 403 за 0,0 с; `POST /api/health` с `Content-Length: 1048577` — 405 за 0,0 с
  (до кода предела); после 403 на `Content-Length: 100000` тело дослано, следом `GET /api/health`
  на том же соединении — 200: остаток тела транспорт дочитал и выбросил, соединение живо (A55).
  Проба 5 — `HTTPBearer()`, `OAuth2PasswordBearer(tokenUrl="/api/x")`, `APIKeyHeader(name=
  "X-Access-Token")` без заголовка — 401, `WWW-Authenticate` — `Bearer`, `Bearer`, `APIKey` (A52).
  Проба 6 — после `uvicorn.Config(**server_settings())` у логгеров `uvicorn` и `uvicorn.error`
  обработчиков нет, `propagate` — истина; у `uvicorn.access` — ложь (A57).
  Проба 7 — `SIGTERM` живому серверу: код выхода −15 за 0,15 с; 13 строк вывода — все JSON,
  «Application shutdown complete.» — запись `uvicorn.error` (A55).
  Проба 8 — два запроса одной записью на одном соединении uvicorn в процессе теста: на входе
  приложения у первого номер пустой, у второго — номер первого: задача второго запроса начинает
  с контекстом первого (A48; Non-functional спеки).
  Проба 9 — `Route` Starlette у схемы и консолей — `GET` и `HEAD`, `APIRoute` здоровья — только
  `GET`: в `dev` 7 пар «метод — путь», 14 запросов обхода (A52).
  Проба 10 — при `docs_url="/api/docs"` и умолчании маршрут `/docs/oauth2-redirect` отвечает 200,
  в HTML консоли есть `oauth2RedirectUrl`; при `swagger_ui_oauth2_redirect_url=None` — 404 и слова
  нет (A51).
  Проба 11 — без маршрутов со схемой входа ключа `components` в схеме нет; с закрытой пробой —
  одна схема `APIKeyHeader`: `apiKey`, заголовок `X-Access-Token` (A51).
  Проба 12 — httpx с телом-генератором оставляет заданный руками `Content-Length: 1048577` и не
  ставит `Transfer-Encoding`, приложение видит тот же размер; без своего размера —
  `transfer-encoding: chunked` (A53).
- 2026-11-20 · выбрал для A37 пробный запрос — закрытую пробу тестов с тестовым пропуском, которая
  читает базу сессией движка процесса, — вместо `GET /api/health` подписанных строк, потому что
  проба A37 (2026-11-20T08:47Z, база копии, снимок `pg_stat_activity` сразу и через 2 с) показала:
  здоровье ходит своим движком без пула (Ч1.3а, L45) и после него соединений 0, а без
  `dispose_engine()` после `shutdown` их тоже 0 — обе строки зелёные без защиты; цена — новые
  тексты строк проверяющий несёт владельцу, код A37 ждёт его слова (решение проверяющего
  2026-11-20). Закрытая проба чтения — одно соединение `ai-geo-audit:api`, `idle`, и через 2 с
  тоже; с ней без `dispose_engine()` после `shutdown` соединение пула остаётся `idle` и через 2 с,
  с `dispose_engine()` снимок сразу пуст.
