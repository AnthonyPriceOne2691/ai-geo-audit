## Stack / boundaries
- **Новый пакет — `cryptography` 50.0.2** (косвенные `cffi` 2.1.1 и `pycparser` 3.12): Fernet и
  `MultiFernet`; HMAC — из стандартной библиотеки. Других пакетов нет.
- **Граница:** `settings` зависит от `config`, `storage`, `logs`. Модели и расшифровку вне
  `settings/` не импортирует никто; импорт модуля моделей без имён — поимённое исключение для
  `schema.py` (A229, решение проверяющего 2026-11-20T11:49Z);
  потребители зовут `settings.keys.resolve` и `settings.values.current`.
- **Гейт:** рисковый путь — `backend/src/ai_geo_audit/settings/`; `artifact_oracle:` —
  `scripts/stack_oracle.py` первым путём: образ собирается с новым пакетом, api в бою стартует с
  мастер-ключом нового формата (A65 Ч1.5а).

## Rejected alternatives
- **AES-GCM с именем как связанными данными** (b1:444) — отвергнут, потому что Fernet даёт формат
  с версией и смену мастер-ключа через `MultiFernet` без своего кода. Цена — имя сверяется после
  расшифровки, а не самим шифром.
- **Мастер-ключ строкой в файле окружения** (b1:448) — отвергнут, потому что значение видно в
  `docker inspect` и уходит во все контейнеры; у нас — файл-секрет только у api (правило
  `master-key` Ч1.5а).
- **Кэш расшифрованного значения на 30–60 с с номером смены** (b1:462) — отвергнут, потому что
  выборка по ключу таблицы и расшифровка дешевле любого вызова провайдера, а кэш даёт окно
  старого ключа и счётчик смен. Цена — один запрос к базе на вызов провайдера.
- **Окружение — запасной источник ключей провайдеров** (b1:453) — отвергнуто: ключей провайдеров
  в файле сервера нет и не будет (`ch1-06-spec.md:240`).
- **Одна строка на настройку с правкой на месте** — отвергнута, потому что «новая версия, а не
  правка» (b1:430) даёт историю и номер для сверки «перечитайте». Цена — чтение последней версии
  по индексу пары.
- **Номер мастер-ключа числом, как `key_version` разведки,** — отвергнут, потому что числу нужна
  таблица «номер → строка файла», а файл её не держит. Номер от HMAC строки виден из самой строки.
- **Проверка прав файла мастер-ключа в процессе** — отвергнута, потому что на раннере файл читаем
  всем, иначе uid 10001 его не прочтёт (оракул ставит 644). Права на сервере сверяет `check` 6а.
- **Все ключи ТЗ в реестре сразу** — отвергнуто, потому что у пары DataForSEO и списка прокси
  своя форма значения: её проверку пишет их клиент.
- **Состояние ключей — в остатке Ч1.12** — отвергнуто, потому что это чтение той же таблицы и
  место, где держится «значения в выводе нет» (A230). Цена — около 25 строк кода и тест сейчас.
- **Список стран и языков двумя списками — отдельно страны и языки** — отвергнут, потому что язык
  осмыслен в паре со страной, а поставщики выдачи берут пару «место и язык» (вывод). Цена — у
  страны с двумя языками две строки списка.

## Risks
- **Формат мастер-ключа и 6а-2.** Оракул пишет ключ сам (`scripts/stack_oracle.py`) и `env-init`
  не зовёт, поэтому расхождение он не поймает. Держит тест-договор A220, вторая строка: его
  кладёт поставка, что сливается второй.
- **Номер ревизии.** Ч1.7в и поставки частей 2–3 заводят свои: кто сливается вторым, тот
  перенумеровывает (ответ проверяющего 2026-11-20T10:44Z); повтор ловит A17.
- **Пакет моложе отсечки.** Если последний выпуск `cryptography` моложе `exclude-newer` —
  поимённое исключение, как у `sqlalchemy` в `pyproject.toml`; решает проверяющий.
- **Колёса пакета.** Сборка образа на `python` 3.12-slim без компилятора: нужны готовые колёса
  под платформу образа. Проверяет оракул (A60, A65 Ч1.5а).
- **`schema.py` и оснастка тестов у двух поставок.** Если Ч1.7в или Ч2.1 успеют первыми — здесь
  строка в их список и их правка `dbtools.py`.
- **Одолженное окружение `merge_guard` (L114).** Гейт слияния одалживает `backend/.venv`
  основной папки: `cryptography` в нём нет, пока основная папка не сделает `uv sync --frozen`
  по замку поставки, — шаги гейта, исполняющие пакет, упадут на импорте (вывод по чтению).
  Синхронизация основной папки — у ведущей (её ответ 2026-11-24): перед гейтом —
  `uv sync --frozen --no-install-project` по замку ветки, `.pth` не трогается; после слияния —
  `uv sync --frozen` по main. Это вывод; проба — у ведущей перед слиянием.
- **Сверка таблиц S3 smoke станет настоящей (L121).** С таблицами `settings/` S3 впервые судит
  непустой список; тест копии A370 smoke подменяет `smoke_run.models` и не меняется.

## Rollout / migration
- Ничего не выкатывается этой поставкой. Таблицы встанут на бою со следующим выкатом шагом
  migrate — это изменение живой базы: слово владельца на тот выкат (конституция).
- Таблицы на бою пустые: число одновременных аудитов — умолчание 3, список стран и языков пуст до
  первой записи; состав списка — в показе Ч3.1.
- `.env.example` не меняется: `KEYS_MASTER_KEY_FILE` уже есть.

## Test / eval strategy
- **pytest без Docker, база — тестовая копии:** A220–A238 и A23; вторая строка A220 — только
  если Ч1.12а сливается позже 6а-2.
- **Оракул стека:** A60 и A65 Ч1.5а зелёные — образ с новым пакетом, api в бою с мастер-ключом
  нового формата.
- **Ручные порчи** — какая краснеет на каком примере:
  - разбор файла пропускает строку из 63 знаков, знак не из hex или повтор; отвергает
    заглавные или CRLF — A220;
  - проверка старта смотрит только «файл есть» — A221;
  - шифруется одно значение без имени — A222, строка под чужим именем;
  - шифр новой записи прежней строкой файла; запись ERROR без поля `master_id` — A223;
  - значение кладётся в подсказку целиком или в колонку открыто — A224;
  - снят запрет не-ASCII или пробела; пробел по краям молча обрезается; предел 512 поднят —
    A225;
  - `put_key` пишет при том же отпечатке — A226;
  - кэш в `resolve` на 30 с — A227; значение не уходит в вычистку — A228;
  - вызов `resolve` при импорте модуля; исключение `schema.py` пускает тот же импорт из другого
    файла — A229;
  - в `repr` состояния — шифротекст; строка реестра без строки таблицы теста — A230;
  - запись ключа двумя командами — выборка, затем вставка: вторая транзакция падает на ключе —
    A231;

  - список принимает повтор пары или страну из трёх букв; регистр не приводится — A238.
