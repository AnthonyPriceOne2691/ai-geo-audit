- README: таблица S3, S1, S2 с пределами 120, 60 и 600 с; строка «чего S1 не доказывает» — сеть
  стека и боевой старт.
- `.gitignore`: `.smoke/` — замок копии, файл группы сервера, вывод сценариев.
- `run.sh`: нет `backend/.venv` — строка «окружение: …», код 1; `PYTHONPATH` — `backend/src`
  корня; `exec` интерпретатора окружения с помощником. Без глушилок.
- Помощник `backend/tests/smoke_run.py` рядом с `dbtools`:
  - окружение: путь пакета первой строкой и сверка с корнем, предпроверка Postgres
    (`dbtools.unreachable`, `START`);
  - замок без ожидания и остатки прошлого прогона;
  - сценарии с пределами: строка на сценарий, вывод — в файл в `.smoke/`, при отказе — строка
    причины и хвост;
  - S3 и S1 с `PYTHONPATH` корня (`alembic_env(extra=…)`, `live_env`); база smoke — `named`,
    `server_url`;
  - S2 — `uv run --no-sync pytest`, затем снос базы набора своего корня;
  - уборка ровно одна на SIGINT и SIGTERM.
  Свой замок, а не `oracle_guard.copy_lock`: у того текст отказа оракула, а скрипты «Оракула» —
  долг по путям.
- Окружение S1 и свободный порт — общие с A55: `free_port` и `live_env` из `test_api_live.py` — в
  общий модуль тестов, адрес и `PYTHONPATH` — параметрами; поведение A55 то же.
- Тесты — вызовом помощника, со своим `.smoke/` в `tmp_path` и своим именем базы:
  - подставные сценарии: первый сбой, предел, ноль, окно 15 строк при отказе последнего;
  - замок: тест держит его сам, как `test_mutation_db.py`;

    отдельным процессом; чужой лидер;

  - `uv` без `--no-sync` в `run.sh` и помощнике — красный тест;
  - S3 с подставной командой, вышедшей с кодом 0, — «ревизия базы не head»;
  - S1 при занятом порте; настоящие S3 и S1 — одним тестом;
  - таблица README и помощник: id и пределы.
- Порчи помощника CI не мерит (mutmut — только `src`): порчи руками на сверке, как у
