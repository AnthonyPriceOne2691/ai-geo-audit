# Plan: сборка фронта (Ч1.4а)

## Уроки до кода
Прочитано до кода:
- черновик Д2 (рабочий черновик вне репозитория) — раздел «Уроки соседей по теме» (с номерами
  строк реестров);
- наш `archive/INDEX.md`.

Ниже — суть своими словами и куда урок лёг.

**Инструменты и сборка**
- **Node.** У соседа на машине Node 24, а в CI и в образе — 22: проверки шли не на том, на чём
  работает сервис. Поэтому Node 24 везде, в трёх местах, с тестом (F1).
- **Воркеры тестов.** Тесты на общей машине без предела воркеров мешали соседним сессиям, а у
  соседа предел жил только в брифе агенту. Здесь предел — в конфиге и с тестом (F2).
- **Типы.** Тесты фронта типов не проверяют, поэтому проверка типов — отдельный шаг цепочки
  (F3).
- **Следы инструментов** (`*.tsbuildinfo`, снимки) у соседей попадали в git. Здесь они
  игнорируются классом, а оснастка пишет только во временную папку (F4).
- **Имя сервиса** у соседа стояло в двух копиях без сверки. Здесь оно в одном месте, с тестом
  (F8).
- **Тестовый рендер.** У соседа тема и схема в тестах расходились с приложением. Здесь один
  `AppProviders` (F9).
- **Заглушка.** На экране факт, а не обещание (F16).
- **Ширины проверки** — 1440 и 390; снимок 390 — через рамку (F16).

**Наш индекс архива**
- **L2.** Прогон в клоне — с `--diff-base origin/main`.
- **L5.** Архивация — на handoff в этой же ветке.
- **L11.** Номера примеров сквозные: у фронта своя буква, F.
- **L13.** `git commit -- <пути>` новые файлы не берёт: новые — через `git add` по имени.
- **L17.** Дайджест привязывает утверждение по номеру в описании теста: у каждого теста в
  описании — свой F.
- **L18.** Порчи проверяющего гоняются до сверки.
- **L20.** Команды во временном клоне — подоболочкой или `git -C`.

## Approach

Три среза. Каждый — отдельные коммиты; тест сначала красный, потом зелёный.

**1. Инструменты (F1–F4, F17).**
- `package.json` — версии точные: набор соседа по слову владельца 2026-11-18, плюс два плагина
  шаблона eslint по слову владельца 2026-11-19T08:59Z; их точные версии — при установке, в lock.
- `.nvmrc`; `.npmrc` с `engine-strict=true` и `ignore-scripts=true`. Пакет, которому нужен
  скрипт установки, — поимённо с причиной.
- **Список, одобренный владельцем,** — `frontend/approved-packages.json`: каждая прямая
  зависимость и зачем она. Новый пакет — строка в списке и строка `new_dependency` в STATUS
  одной правкой. Тест F17 сверяет со списком `dependencies` и `devDependencies` из
  `package.json`.
- `tsconfig.json` — строгие флаги шаблона канона.
- `vite.config.ts` — у тестов `maxWorkers: 2`.
- Шаблоны eslint и prettier канона с объявленной адаптацией.
- `.gitignore`.
- `toolchain.test.ts` — F1–F4 и F17: адрес каждого пакета в lock — реестр npm, `integrity` у
  каждой записи пакета, точные версии, прямые зависимости — по списку.
- README в корне — раздел о фронте в три строки: Node 24, `npm ci`, `npm run check`.

**2. Оракул сборки (F5, F7).**
- `scripts/check-dist.mjs` — без зависимостей.
- Что проверяет:
  - язык и заголовок;
  - каждый файл по ссылке есть и с хешем в имени; нет `.map`;
  - нет адресов разработки;
  - нет чужих узлов в HTML и CSS: со схемой и без неё, в `@import`, `preconnect` и
    `dns-prefetch`, `srcset`, `url()`;
  - адреса узлов в JS — только из поимённого списка с причиной: пространства имён
    `www.w3.org`, справка `react.dev` и `mantine.dev`. Список — в самом оракуле; новый узел —
    красный, и оракул называет узел;
  - нет встроенных скриптов.
- Проверку наборов знаков шрифта добавит Ч1.4б.
- Порчи подкладываются во временную копию `dist/` во временной папке ОС; у каждой проверки
  оракула — своя порча в тесте оракула.

**3. Приложение (F8, F9, F16).**
- `main.tsx`, `App.tsx` (`AppProviders` со стандартной темой), `brand.ts`, `words.ts`,
  `StubPage.tsx` — имя и строка-факт.
- Тестовая обвязка `test/setup.ts`, `test/render.tsx`.
- **Снимки для приёмки** — Chrome без окна: `vite preview`, 1440 × 900 и 390 × 844. Снимок 390
  — через страницу-рамку с `iframe` шириной 390. Снимки — во временную папку, вне git.

## Stack / boundaries
- React, Mantine, Vite, Vitest и jsdom — набор и версии соседа по слову владельца 2026-11-18.
- Плюс `eslint-plugin-react` и `eslint-plugin-import` для шаблона канона — слово владельца
  2026-11-19T08:59Z через проверяющего. Шаблон канона называет у них только линию (7 и 2):
  точная версия — при установке, в lock.
- Фронт не знает бэкенда до Ч1.4в: запросов к серверу нет.

## Rejected alternatives
- Одна поставка «сборка и тема» — отвергнута, потому что с добавками она выходит около 1350
  строк с поправкой при пределе 1200, а сжимать нельзя (решение проверяющего 2026-11-18).
- Сборка с `tsc -b` — отвергнута, потому что `tsc -b` пишет `tsconfig.tsbuildinfo` в дерево.
  Типы проверяются отдельным шагом `tsc --noEmit`.
- Предел воркеров в брифе агенту, как у соседа, — отвергнут, потому что бриф не держит
  `npm test` в соседней сессии. Предел — в конфиге, с тестом.
- Версии пакетов с `^` и `~` — отвергнуты, потому что сборка тогда зависит от дня установки.
  Точные версии и lock держат её повторяемой.
- Список одобренных пакетов строками `new_dependency` в STATUS — отвергнут, потому что STATUS на
  handoff уезжает в архив, и тест F17 после переноса читал бы пустоту.

## Risks
- **Ширина 390 в Chrome без окна** — проверить на машине до снимков, запасной путь — рамка.
- **Файл lock у фронта большой.** Гейт его не считает, но сканер РФ и РБ его читает: строки
  `integrity` пропускаются и называются в отчёте.
- **Плагины шаблона eslint** — одобрены: слово владельца 2026-11-19T08:59Z через проверяющего.
  Шаблон канона ставится с ними.
- **Узел вне списка уже в первой сборке** — например, ссылка в тексте ошибки пакета. Оракул
  красный и называет узел; в список узел попадает с причиной, словом человека, а не
  исполнителя.

## Rollout / migration
- Фронт ещё нигде не выкатывается: образ и nginx — Ч1.5.

## Test / eval strategy
- Vitest и jsdom, не больше двух воркеров; цепочка `npm run check`.
- Оракул сборки — `check-dist.mjs`, проверяющий подкладывает порчи в копию сборки.
- Ручные порчи:
  - предел воркеров снят;
  - шаг цепочки выпал;
  - другой major Node;
  - встроенный скрипт;
  - ссылка на чужой узел — со схемой, без схемы, в `@import`, `preconnect`, `dns-prefetch`,
    `srcset`, `url()`;
  - новый узел в JS;
  - своя тема в тестовом рендере;
  - имя в двух местах;
  - `ignore-scripts` снят;
  - версия с `^`;
  - запись lock без `integrity`;
  - прямая зависимость не из списка.
- Снимки 1440 × 900 и 390 × 844 — для приёмки проверяющего, вне git.
- Сканер слов и поясов РФ и РБ — по новым файлам и lock (A23).
