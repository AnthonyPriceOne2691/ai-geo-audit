Ниже — суть своими словами и куда урок лёг.

**Образ**
- **«Образ собрался» — не «образ делает продукт»** (второй сосед, L69 и L84; журналы, Р50).
  У соседей в образ не попадали шаблоны: способ установки терял файлы не `.py`, а проверка
  образа звала только `--help`. Поэтому оракул сверяет файлы пакета с копией и гоняет
  alembic из образа на пустой базе (A62, A65).
- **Консоль внутри образа — свой путь** (журналы, Р49): заглушка пакета перекрывала
  настоящий код. Команды образа — `python -m <модуль>` и `alembic`; оба пути проходит оракул
  (A65, A69). Консоли учёток придут с Ч1.8–Ч1.10.
- **Базовый образ — по дайджесту** (журналы, Р52): подвижная метка меняла патч Python между
  сборками, в образе оставались остатки сборки. Дайджест у `FROM` держит разбор `Dockerfile`
  (A60), у образов compose — правило `image-digest` (A71); стадии сборки не оставляют следов в
  итоговом образе (A60).
- **Последний патч старше 14 суток** (правило ведущей 2026-11-19): свежий выпуск ещё не
  обкатан. Тег линии и дайджест; дата выхода сверяется при каждом добавлении и обновлении;
  версия и дайджест закрепляются в день кода, срез 0 (Stack).
- **Лимиты Docker Hub** (реестр CI, Ч1.5): у соседа Docker Hub дважды подряд отказывал по
  лимиту анонимных загрузок. Вместо зеркала, решение ведущей: базы — с Docker Hub по
  дайджесту; дайджест закрепляет содержимое, второй поставщик не нужен. Упрёмся в лимит на
  раннере — это сбой реестра, а не код (реестр CI, В1): упавшую джобу повторяет человек после
  конца прогона и с паузой (вопрос 2 о прогонах); повторится — ведущая идёт к владельцу.
- **Одна версия Python везде** (журналы, Р31; реестр CI, Ч1.4): на машине 3.14, в CI 3.12.
  Оракул сверяет версию в образе с `requires-python` и `uv.lock` (A60).
- **Установка по lock под тестом** (опись, З81): у соседа тест замка зависимостей сверяет
  `uv sync --locked` и одну версию `uv` в `Dockerfile`. У нас — разбор `Dockerfile` (A60).
- **Секрет — ни в образе, ни в образце** (журналы, Р55). Белый список контекста, канарейки и
  выдуманные значения, переданные в сборку, которых потом нет в истории образа (A61, A64).
- **Монтирование накрывает то, что поставил образ** (второй сосед, L70). Исходники в стек не
  монтируются; правило `workdir-volume` запрещает том в рабочем каталоге образа — там конфиг
  ищет `.env` (A71).

**compose и migrate**
- **Миграции — одноразовым сервисом до остальных** (реестр CI, Ч1.2б): migrate без
  перезапуска, api ждёт его успешного выхода (A65, A67, правила `restart` и `order`).
- **Миграцию гоняют тем, чем её гонят в бою** (журналы, Р22): тесты катили миграции из копии,
  а сервер — из образа. Оракул гоняет их из образа на пустом томе (A65).
- **Откат со схемой опускает образ новой версии** (реестр CI, Ч1.2б). Проверка `downgrade` из
  образа и порядок отката — Ч1.6, решение ведущей (вторая строка A66): обратимость уже держат
  тесты Ч1.2б на настоящей базе.
- **Весь `.env` уходит во все контейнеры** (реестр CI, Ч1.5): у соседа ключ хранилища копий
  оказался бы в сервере, смотрящем в интернет. У нас `env_file` нет, у процесса — ровно свой
  список, прочие имена — только поля конфига (A72).
- **Боевой compose держит только имена секретов, `${VAR:?причина}`** (второй сосед, L72):
  тихий старт с пустым секретом хуже отказа (A72).
- **Здоровье — у каждого процесса своё** (реестр CI, Ч1.3): «жив» — не «делает работу». Проба
  api ходит в health, а health — в базу (A69). У соседа «у каждого долгоживущего есть
  проверка здоровья» держит тест сторожа; у нас — правило `healthcheck` (A71).
- **Числа проверки здоровья — в спеке** (чтение спек): без них порча «`retries` 30» не
  краснеет. Окна A69 посчитаны из чисел In scope.
- **Готовность Postgres — по TCP** (реестр CI, Ч1.2а): временный сервер начальной настройки
  слушает только сокет. Проверка db — `pg_isready` с адресом, правило `db-health-tcp`.
- **После перезагрузки всё поднимается само** (реестр CI, Ч1.5): `unless-stopped` у
  долгоживущих (правило `restart`). Проверка перезапуска — Ч1.5б: её нельзя делать
  `docker kill` (второй сосед, L71).
- **В образе — штатные команды, а не разовые скрипты** (реестр CI, Ч1.5): alembic — да
  (A62); команды учёток — с поставками входа.
- **Правку `.env` видит только пересоздание; разбор конфига до `up -d`** (реестр CI, Ч1.5) —
  Ч1.6.

**Оракул, машина, CI**

- **Имя владельца в реестре образов — строчными** (журналы, Р43) — Ч1.6, при публикации.

## Approach

Срез 0, четыре среза кода и контрольная точка после среза 4. Каждый срез кода — отдельные
коммиты; тест или шаг оракула сначала красный, потом зелёный. Порядок: сначала то, что
проверяется без Docker.

**0. Версии и дайджесты — в день кода, до первой сборки.**
- Для каждого образа — последний патч линии, который в этот день старше 14 суток; дата выхода
  — по первоисточнику.
- Проба в decisions — сверка дайджеста по второму источнику в день закрепления: дайджест
  с Docker Hub сверяется с ещё одним чтением того же образа; это чтение, а не источник
  сборки. У `uv` — дайджест по тегу 0.11.26 в реестре авторов сверяется с файлом сверки
  версий: должен быть тот же.
- Итог — строкой на образ в decisions: тег, дата выхода, дайджест, где сверен, дата сверки.
  Строк кода нет.

**1. Правила compose (A71–A73).**
- `backend/src/ai_geo_audit/ops/stack_rules.py`: вход — JSON `docker compose config
  --no-interpolate --format json`; выход — нарушения «код, сервис, переменная» без значений и
  строка «сервисов N, правил M». Пустой ввод и ноль сервисов — отказ.
- Перечень правил основного набора, в этом порядке; тест сверяет его с модулем:
  1. `stack-name`; 2. `ports`; 3. `healthcheck`; 4. `restart`; 5. `order`; 6. `init`;
  7. `db-health-tcp`; 8. `image-digest`; 9. `trusted-proxy`; 10. `workdir-volume`;
  11. `required-vars`; 12. `secret-form`; 13. `foreign-secret`; 14. `unknown-var`;
  15. `env-file`; 16. `master-key`.
- `config/startup_checks.py`: публичная `required(process)` вместо чтения закрытого поля.
  Списки процессов — из неё; имена прочих настроек — поля конфига; секреты — поля
  `SecretStr` и файл мастер-ключа.
- Сервис и процесс сопоставляются по имени: api — `api`, migrate — `migrate`. У db и redis
  процесса нет, переменных из списков у них быть не должно.
- `backend/tests/test_stack_rules.py`: верный вымышленный конфиг и порча на каждое правило;
  верный — 0 нарушений.

**2. Проба здоровья (A70).**
- `backend/src/ai_geo_audit/api/probe.py`: `GET /api/health` на петле контейнера, порт — из
  настройки Ч1.3, предел 3 с; код 0 только на 200, иначе 1 и одна строка причины.
- Импортирует только конфиг и стандартную библиотеку.
- `backend/tests/test_probe.py`: четыре сервера теста на петле, порт — свободный от системы.

**3. Каркас оракула, образ и контекст (A60–A64).**
- `scripts/stack_oracle.py`, каркас: чистая копия `git archive HEAD`, канарейки с меткой
  прогона, имя стека — `ai-geo-audit-oracle-` и 10 знаков sha256 пути копии, один исполнитель
  команд Docker, уборка своего имени в `finally`, отчёт по шагам. Первый шаг — Docker
  отвечает; иначе одна строка с командой подъёма.
- `deploy/backend/Dockerfile`: стадия установки с `uv` через `RUN --mount`; итоговая стадия на
  `python` 3.12-slim; `/opt/venv`; пользователь `app`, uid 10001, в `USER` — числом: тогда
  `Config.User` образа — `10001` (A63); рабочий каталог — с `alembic.ini` и `migrations/`;
  команда по умолчанию — api.
- `deploy/backend/Dockerfile.dockerignore`: `*`, затем пять открытых путей, затем повторное
  закрытие на любой глубине.
- `backend/tests/test_dockerfiles.py`: разбор `FROM` и установок; 5б добавит в него свой
  `Dockerfile`.
- Шаги оракула: проба контекста, сверка файлов пакета, выдуманные значения в `--build-arg`,
  история и `Config.Env` образа.
- `backend/tests/test_stack_oracle.py`, модуль грузится по пути файла: чистые части каркаса —
  поиск метки и сверка списков файлов (A61, A62).

**4. compose, migrate и правила на настоящем файле (A65–A67, A69, A73 — первая строка).**
- `docker-compose.yml`: db, redis, migrate, api; том базы; файл-секрет мастер-ключа; проверки
  здоровья с числами спеки; порядок и перезапуск; адреса базы — из `MIGRATE_DATABASE_URL` и
  `API_DATABASE_URL` сервера, у процесса это `DATABASE_URL`.
- `.env.example`: блок «стек compose» с заглушками — пароль базы, адреса базы для migrate и
  api, адрес web для доверия api, путь к файлу мастер-ключа на машине.
- Оракул: подъём с `--wait`, версии alembic из образа, повтор, неверный пароль у migrate,
  остановка и старт db; шаг A73 — правила на настоящем файле внутри собранного образа.
- README: как поднять стек и как гонять оракул.
- `delivery/active/eval-smoke.md`: строка живого прогона оракула — команда, ожидание, время
  и номера A60–A67, A69, A73.

**Контрольная точка — страховка, после коммита среза 4** (решение ведущей).
- Срез 4 — последний срез кода 5а; число — по счёту гейта поставки после коммита.
- 2300 и меньше — поставка идёт на сдачу.
- Больше 2300 — стоп: число ведущей до следующего шага, то есть до сдачи. Авторазреза нет:
  A74–A76 уже вынесены в «Оракул стека в CI».

Уборка оракула при обрыве, два прогона разом, таблица шагов и джоба `stack` — бывшие срезы 5 и
6 — в малой поставке «Оракул стека в CI» сразу после 5а, до 5б: спека и план — рядом,

## Оценка объёма

Строки — вместе с тестами, без `uv.lock`, файлов CI и `delivery/`: гейт их не считает. Шаг
оракула с контейнером — 8–25 строк, в среднем около 15: короткий — осмотр образа, длинный —
подъём стека и разбор состояний.

|---|---|---|
| 1. Правила | `stack_rules.py` ~110 (16 правил, имена настроек, отказ на пустом); тесты ~90 (конфиг, 16 порч, перечень кодов); `required()` с тестом ~8 | ~208 |
| 2. Проба | `probe.py` ~25; тест A70 ~55 (четыре сервера на петле) | ~80 |
| 3. Каркас оракула и образ | каркас оракула ~60 (копия, канарейки, имя, исполнитель, уборка в `finally`, отчёт); тест его чистых частей ~20; `Dockerfile` ~45, белый список ~20; разбор `Dockerfile` ~30; шаги оракула A60–A64 ~75 | ~250 |
| 4. compose, migrate, A73 | `docker-compose.yml` ~90, `.env.example` ~10; шаги оракула A65–A67, A69 ~67 и A73 ~8; README ~15 | ~190 |
| **Итого** | | **~728** |

По мере × 2 — около **1456** при пределе 2500. Файлов около 13 при пределе 50. «Оракул стека
в CI» — оценка в его плане (`ch1-05-stack-ci-plan.md`).

**Цена проверок с контейнером.** Шаг с контейнером дороже правила на вымышленном конфиге в
2–4 раза по строкам (около 15 против 4–6) и в сотни раз по времени: десятки секунд против
миллисекунд. Весь прогон 5а — по оценке 5–7 минут на машине, на раннере дольше.

**Отсечка — решение ведущей.** A68 (четыре migrate в стеке) и вторая строка A66 (`downgrade` и
`upgrade` из образа) — в Ч1.6: замок и обратимость уже держат тесты Ч1.2в и Ч1.2б на
настоящей базе, а порядок отката со схемой — тема выката. В оценке их нет.

Заранее больше не режем — решение ведущей: срез 5 Ч1.2в вышел в 1,6 раза больше оценки.
A74–A76 вынесены сразу: при прежнем пределе 1200 к точке и так выходило около 945, шов
сработал бы почти наверняка. Точка после среза 4 осталась страховкой.

## Stack / boundaries
- **Новых пакетов Python нет.** Проба — `urllib`, правила — `json`, оракул — стандартная
  библиотека.
- **Образы — слово владельца получено:** `by=human:owner at=2026-11-19T10:40Z` — на python
  3.12, postgres 16, redis 7.4 и uv; источник — Docker Hub по дайджесту, у `uv` — реестр
  его авторов. Правило: тег линии и
  дайджест; последний патч линии, который на день кода старше 14 суток; дата выхода — при
  каждом добавлении и обновлении. Даты сверены по первоисточникам 2026-11-19; на день кода их
  перепроверяет срез 0:
  - `python` линии 3.12-slim — 3.12.15, выход 2026-10-22; 3.12.16 от 2026-11-08 годится с
    2026-11-22. База стадии установки и итоговой стадии;

    `uv.lock` писала и читала одна версия; обновление `uv` — осознанной правкой сразу в трёх

  - `redis` линии 7.4-alpine — 7.4.11, выход 2026-10-26; 7.4.12 от 2026-11-12 годится с
    2026-11-26. У соседа метка 7; первый потребитель — Ч1.8.

## Rejected alternatives
- **Два образа, для api и migrate,** — отвергнуто, потому что зависимости разъехались бы.
  Один образ, разные команды; позже — и воркер.
- **Один `Dockerfile` в корне с целями `backend` и `web`** (черновик) — отвергнуто, потому что
  контекст общий: образ сервиса видел бы исходники фронта, а белый список правили бы обе
  поставки. У каждого образа свой файл и свой список в `deploy/`.
- **Чёрный список, как у соседей,** — отвергнут, потому что новый каталог с секретом попадает
  в контекст сам. Белый список открывает только названное.
- **`env_file: .env`** — отвергнут, потому что весь файл уходит во все контейнеры, включая
  базу и очередь.
- **«Ровно переменные из списка» буквально** — отвергнуто, потому что тогда запрещены
  `APP_ENV`, `LOG_FORMAT`, `API_PORT` и пулы базы. Ровно — только для имён из списков проверки
  старта; прочие — поля конфига, незнакомое имя — красное (A72).
- **Один адрес базы на migrate и api** — отвергнут, потому что в Ч1.5б у них разные роли, а
  A67 нужен неверный пароль только у migrate.
- **`curl` в образе для проверки здоровья** — отвергнут, потому что это лишний пакет и бинарь в
  образе. Проба — на стандартной библиотеке, с тестом.
- **Правила по YAML-файлам** — отвергнуты, потому что нужен пакет YAML, а итог наложения
  основного и боевого файлов не виден. `docker compose config` даёт итог без нового пакета.
- **Оракул тестами pytest** — отвергнут, потому что тесты бэкенда идут без Docker и быстро.
  Оракул — отдельный скрипт для CI и машины; без Docker тестируются его чистые части.
- **Запасная отсечка: тесты хода оракула заменить живыми пробами ведущей** — отвергнута
  решением ведущей. Выбрал вынос A74–A76 в свою поставку вместо замены тестов живыми
  пробами, потому что тест не меняем на ручную пробу: пробы ведущей идут сверх тестов. Цена
  — ещё одна малая поставка «Оракул стека в CI», при прежнем пределе 1200 около 135 строк с
  поправкой вместо минус 40 у отсечки, и ещё один круг проверки и подписи.
- **Шов на контрольной точке на ходу** — отвергнут решением ведущей, потому что при прежнем
  пределе 1200 к точке выходило около 945 при пороге 850: шов сработал бы почти наверняка.
  A74–A76 вынесены сразу, точка осталась страховкой.
- **Зеркало реестра для базовых образов** — отвергнуто решением ведущей. Выбрал Docker Hub по
  дайджесту вместо зеркала, потому что дайджест закрепляет содержимое и второй поставщик не
  нужен. Цена — сборка в CI зависит от лимитов Docker Hub для анонимных загрузок: у соседа
  такой отказ случился дважды подряд; повтор — человеком после конца прогона.
- **Публикация образа уже здесь** — отвергнута, потому что это выход в бой и подпись
  владельца. Публикация — Ч1.6.
- **Воркер в compose сейчас** — отвергнут, потому что его точки входа нет: решение ведущей —
  Часть 3.

## Risks
- **Список контекста у каждого `Dockerfile`** работает только под BuildKit. Без него в
  контекст уходит весь репозиторий — A61 краснеет на первой же канарейке.
- **`uv_build` и файлы не `.py`.** От этого зависит, чем A62 окажется в первый день. Если
  теряет — включение файлов настройкой сборки в `pyproject.toml`.
- **Права файла мастер-ключа.** Файл-секрет compose монтируется с правами машины, а читает
  его uid 10001. На раннере и на macOS проверить первым шагом; на сервере — Ч1.6.
- **`up -d --wait` и одноразовый migrate.** В части версий compose вышедший с кодом 0 сервис
  считается сбоем `--wait`. Первый шаг — проба на машине и на раннере; если так — оракул ждёт
  migrate отдельной командой, а A65 сверяет коды выхода сам.
- **Вывод `--no-interpolate`.** Порт вида «петля, переменная, порт» без подстановки может не
  разложиться на `host_ip` и `published`. Правило `ports` разбирает и сырую строку; проба — на
  первом выводе настоящего файла.
- **Соседние поставки.** При открытии ветки — сверка с main: проба, `API_PORT`,
  `API_TRUSTED_PROXIES`, `server_settings()` и проверка старта у migrate берутся из Ч1.2в и
  Ч1.3; расхождение — ведущей.
- **Время круга CI** растёт на несколько минут; зависший шаг называется своим пределом.
- **Лимиты Docker Hub на раннере.** Анонимные загрузки ограничены; отказ по лимиту — сбой
  реестра, а не код: повтор после конца прогона и с паузой. Повторится — ведущая идёт к
  владельцу.
- **Docker общий с соседями.** Свои имена и тома, портов наружу нет; тяжёлое — при нагрузке
  машины ниже 12.

## Rollout / migration
- Ничего не выкатывается, боевой базы нет. Стек разработки `ai-geo-audit-dev` не меняется.
- `.env.example` получает блок стека с заглушками; тесты образца остаются зелёными.
- STATUS: `artifact_oracle: scripts/stack_oracle.py`, рисковый путь — `deploy/backend/`.
- A68 и вторая строка A66 записываются в спеку Ч1.6 с теми же номерами.
- Порядок поставок до выката (решение ведущей): 5а → «Оракул стека в CI» → 5б → «Учётки
  хранилищ» → Ч1.6. Если сработает шов 5б — «Боевое наложение» встаёт перед Ч1.6.
- Сразу после 5а — «Оракул стека в CI»: файлы `scripts/stack_oracle.py` (уборка, замок,
  таблица шагов), `backend/tests/test_stack_oracle.py` (их тесты), файл джобы CI и строка
  README; примеры A74, A75, A76 — с теми же номерами.

## Test / eval strategy
- **pytest без Docker:** A60 (вторая строка), A70, A71, A72, A73 (вторая строка), чистые
  части каркаса оракула (A61, A62).
- **Оракул на машине:** A60 (первая строка), A61–A67, A69, A73 (первая строка); строка живого
  прогона в `eval-smoke.md` называет эти номера — по ней гейт видит ссылки.

- **A74–A76 и их порчи** исполняет «Оракул стека в CI», в том числе джобу в CI.
- **Ручные порчи** — какая порча краснеет на каком примере:
  - снят `--no-dev`: в образе `pytest` — A60;

  - убрано повторное закрытие `.env*` — A61, метка из `backend/src`;
