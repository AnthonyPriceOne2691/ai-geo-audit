## Approach

Срезы кода — отдельные коммиты, тест сначала красный. Подставной исполнитель — с записями с
раннера и из разведки (6а).

### 6в «Подъём, сверка и публикация» — срезы 1–5

**1. `up` (A187, A188, A190, A194).**
- Защита входа: полный SHA; `--backend-digest` и `--web-digest` обязательны; `HEAD == SHA` и
  чистое дерево — иначе отказ с командой `git checkout`.
- Путь образов — из адреса `origin` копии на сервере: владелец строчными, как в джобе публикации.
  В файл сервера `up` пишет `<путь>@<дайджест>` — пометка «пишет выкат»; владелец пути не задаёт.
  Адрес не вида `https://github.com/<владелец>/<имя>` — отказ до первой команды докера, без
  самого адреса в выводе и без подстановки другого реестра (A187).
- Порядок A187: `check` 6а → снимок соседа → скачивание и сверка дайджестов, db и redis — только
  если их нет → правила `--prod` в образе → разовый старт migrate и api → копия → запись образов в
  файл сервера → db и redis → скрипт ролей «Учёток» → `run --rm migrate` → `up -d --no-build
  --wait` → `verify` → канарейка → история.
- Копия: `exec -T db` суперпользователем через сокет; db остановлен — поднять прежний; временный
  файл 600, переименование; пять копий.
- Отказ до первого изменения — печать команды возврата дерева.

**Внутренняя точка — после коммита среза 1,** число — по счёту гейта (L27). Порог — 2300 минус
срезы 2–5 × 2, около 768: **1532**. Больше — стоп: число ведущей.

**2. `verify` и канарейка (A190, A191, A193, A195, A196).**
- Здоровье по итоговому конфигу; Id образов; `alembic current` и `heads` из образа; `APP_ENV` и
  `LOG_FORMAT` по окружению контейнеров; отпечатки окружения против итогового конфига; порты;
  `--logs` — журналы сервисов и `.deploy/`; `--journal` — `journalctl` по имени контейнера api,
  два Id; снимок соседа.
- Канарейка: настройки `curl` с адресом и телом — через stdin (`-K -`), ответ — поле `ok`.

**3. Режим репетиции и живой прогон в `stack`.**
- Режим репетиции: только при `CI=true`, SHA — вершина копии, образы — прогона. Им пользуются
  живые прогоны 6в и 6в3 и репетиция по реестру.
- На запросе на слияние после шагов оракула: `env-init` с выдуманными значениями во временном
  корне, `check`, `up`, `verify`; второй `up` того же SHA (A194); разовый migrate с неверным
  паролем роли миграций — Id api до и после (A190, вторая строка); смена пароля роли сервиса:
  обе строки пары, `check`, `up` (A194, вторая строка); `verify --logs` (A195); пересоздание api
  и `verify --journal`, если на раннере есть journald (A196).
- Это первая часть «Исполнения рисковых путей» 6в до слияния; блок в verify-report — с номером

**4. Публикация образов и репетиция по реестру (A180).** Джоба на push в main: сборка → шаги
оракула → push ровно этих образов, Id сверяется → скачать по дайджесту → репетиция в режиме среза 3:
`env-init` с выдуманными значениями, `up` по метке и дайджестам, `verify`, копия, снос базы,
восстановление по рецепту памятки, сверка строки; обрыв посреди `up` — повтор доводит. Тесты
скрипта — и на минимальной версии Python.

**Внутренняя точка — после коммита среза 4.** Порог — 2300 минус срез 5 × 2, около 180:

- Шаг оракула A213: живой прогон берёт команды из памятки, а не копией, и сверяет вывод с

**«Исполнение рисковых путей» 6в, вторая часть** — до слияния: живой прогон в `stack` — копия,

### 6в3 «Откат и уборка» — срезы 6–8

Сразу после первого выката, до второго с новым SHA. Первому выкату откатываться не на что: стек
снимается `docker compose down` без томов (общий план, «Откат по шагам»).

**6. Откат без схемы и уборка (A197).** `rollback <SHA>` — дайджесты из истории, `up` по ним;
одна запись в истории — отказ и подсказка `down` без томов. Уборка: образы наших путей старше трёх
последних выкатов — `docker image rm` по дайджесту. Живой прогон в `stack`: `rollback` при одной
записи истории — отказ; уборка после `up` — образы чужих путей на месте.

**Внутренняя точка 6в3 — после коммита среза 6.** Порог — 2300 минус срезы 7–8 × 2, около 190:
**2110**. Больше — стоп: число ведущей.

**7. Откат со схемой и миграции в стеке (A198, A211, A212).** `--downgrade-to`: без флага — план;
флаг сверяется с историей; `downgrade` образом текущего выката при дереве на нём. Оракул: A211 —
`downgrade -1` и `upgrade head` из образа, `alembic check`; A212 — четыре migrate разом на пустом
томе.

**8. Памятка, раздел отката.** `rollback`; `--downgrade-to` — только словом владельца с

## Stack / boundaries
- **Новых пакетов, образов и действий нет:** ни `registry`, ни действий артефактов; публикует та
  же джоба, что собрала и прогнала оракул.
- **Реестр** — реестр образов GitHub; путь владельца — из переменной CI строчными, на сервере — из
  адреса `origin` копии; пакеты — публичные, одно действие владельца после первой публикации.
- **Граница:** скрипт зовёт alembic, правила и разбор конфига внутри образа; копию снимает
  `pg_dump` в контейнере db; канарейка — `curl` хоста; разовые наблюдения — движок сервиса в
  контейнере api.

## Rejected alternatives
- **Откат — отдельной поставкой 6в3 после первого выката, а не на пути к нему.** Решение
  проверяющего 2026-11-19 вместо отката во второй поставке: первому выкату откатываться не на что,
  стек снимается `docker compose down` без томов. Цена — до второго выката с новым SHA нужна ещё
  одна поставка и ещё один круг проверки и подписи.
- **Публикация — в той же поставке, что подъём, а не отдельно.** Слово владельца 14:26Z вместо
  прежнего разреза при пределе 1200: поставка — тема целиком, вместе около 1238, ниже 2300. Цена —
  поставка крупнее, и перерасход ловят только внутренние точки; зато первому выкату нужна одна
  поставка, а не две.
- **Путь образов — из адреса `origin` копии, а не значение владельца.** Выбрал путь от
  репозитория вместо переменной, которую вводит владелец, потому что путь однозначно задан
  репозиторием и джобой публикации, а значение руками — лишняя опечатка. Цена — копия на сервере
  обязана быть клоном с GitHub; иначе `up` отказывает словами.
- **Разовые наблюдения — командами памятки, которые исполняет живой прогон, а не ручным `psql`
  ведущей.** Замечание проверяющего 2026-11-19 вместо запросов руками: команда движком сервиса
  видит то же, что сервис, а вывод сверен заранее. Цена — около 55 строк в 6в.
- **migrate отдельным шагом до пересоздания api, а не внутри одного `up -d --wait`.** Выбрал
  `run --rm migrate` вместо одного `up`, потому что compose пересоздаёт api в фазе создания, до
  того как migrate кончит, — сверено чтением исходника. Цена — migrate идёт дважды за выкат,
  второй проход пустой, плюс секунды.
- **Публикует джоба, что прогнала оракул, а не отдельная сборка.** Выбрал публикацию проверенных
  образов вместо пересборки в своей джобе, потому что пересобранный образ — уже не тот, что
  проверен. Цена — джоба на main длиннее: оракул, push, скачивание и репетиция подряд.
- **Без действий артефактов и без образа `registry`, а не локальный реестр на раннере.** Выбрал
  настоящий реестр после публикации вместо локального, потому что так исполняется ровно тот путь,
  что на сервере, и новых зависимостей нет. Цена — репетиция по реестру идёт только на main.
- **Дайджесты — обязательными флагами `up`, а не из ответа реестра на метку.** Выбрал сверку с
  итогом джобы вместо доверия метке, потому что метку можно подменить между публикацией и
  скачиванием. Цена — ведущая переносит два дайджеста из итога джобы в команду.
- **Дерево переключает ведущая видимой командой, а не скрипт.** Выбрал `git checkout` отдельной
  командой вместо переключения и перезапуска скрипта (`os.execv`), потому что скрипт иначе
  исполняет прежнюю свою версию на новом дереве. Цена — если `up` отказал, дерево уже на новом
  SHA при прежних образах; возврат — командой, которую печатает отказ.
- **Копия `pg_dump`, а не снимок тома.** Выбрал `pg_dump` вместо снимка живого тома, потому что
  снимок без остановки Postgres не согласован. Цена — минуты на большой базе позже.
- **Корень копий — вне каталогов соседа, а не рядом с его копиями.** Выбрал свой корень по
  разведке вместо `/srv/backups/ai-geo-audit/` по умолчанию, потому что выгрузка или ротация
  соседа может брать весь `/srv/backups`. Цена — ещё один корень в списке своих путей.
- **Откат со схемой по флагу с названием ревизии, а не сам.** Выбрал флаг вместо автоматического
  `downgrade`, потому что он теряет данные новых колонок, а это изменение живой базы. Цена — две
  команды и слово владельца.
- **Восстановление копии — рецептом памятки, а не скриптом.** Выбрал рецепт вместо команды,
  потому что восстановление с проверкой — Ч1.15, а до неё база пустая. Цена — до Ч1.15 рецепт
  руками, но он исполняется в живом прогоне 6в и в репетиции.
- **Уборка своих образов — три последних выката, а не «позже».** Выбрал уборку в 6в3 вместо
  отсрочки «на потом», потому что каждый выкат кладёт на общий диск сотни мегабайт. Цена — откат
  дальше трёх выкатов — со скачиванием заново.
- **Канарейка через `curl -K -`, а не адресом в аргументах.** Выбрал настройки через stdin вместо
  адреса в командной строке, потому что токен стоит в адресе Telegram. Цена — нужен `curl` на
  машине (разведка, блок 5).

## Risks
- **Первому выкату нужна 6в; 6в3 — до второго выката с новым SHA.** Без 6в3 откат — только
  `docker compose down` без томов, а новую ревизию на бою опустить нечем.
- **Поведение compose на сервере.** Исходник прочитан у v5; на сервере версия — по разведке. Шаг
  `run --rm migrate` держит порядок при любой версии.
- **`up -d --wait` и вышедший migrate** — в части версий вышедший с кодом 0 сервис считается
  сбоем `--wait`; тогда скрипт ждёт остальные сервисы без migrate — так же, как решит оракул Ч1.5а.
- **journald на раннере** — A196 только на сервере, если его нет.
- **Пакеты приватны** до действия владельца — `up` отказывает словами (A187).
- **Обрыв связи посреди `up`** — ход в `.deploy/`, `tmux`, повтор доводит; проба — в репетиции по
  реестру.
- **Команды памятки отстают от кода** — их исполняет живой прогон 6в (A213), расхождение —
  красный шаг, а не устаревшая памятка.
